# طبقة قوالب الطباعة المؤصّلة

تدير هذه الطبقة **مكتبة القوالب ومراجعاتها وتعييناتها**. وهي لا ترسم القالب ولا تصدّر PDF؛ ستستهلكها واجهة المحرر ومحرك الإخراج في المرحلتين التاليتين. وجودها المنفصل يمنع تحويل إعداد مرئي إلى تغيير صامت في مستند تاريخي.

| الكيان | نطاقه | مسؤوليته |
|---|---|---|
| `PrintTemplate` | المؤسسة | هوية القالب واسمه وحالته والمراجعة المنشورة الحالية. |
| `PrintTemplateRevision` | المؤسسة | تعريف JSON مرقّم. المسودة قابلة للتعديل؛ المراجعة المنشورة لا يتغير تعريفها ولا تحذف. |
| `PrintTemplateAssignment` | المؤسسة مع تجاوز فرع | اختيار مراجعة منشورة لنوع مستند واستعمال، مع أولوية الفرع ثم افتراضي المؤسسة. |

> **سياسة معتمدة:** تثبت مراجعة القالب عند إصدار أو ترحيل المستندات الضريبية والمحاسبية. تظل المسودات متصلة بالتعيين الأحدث إلى أن تصدر، ثم يجب أن يشير المستند إلى `PrintTemplateRevision` المنشورة المحددة في وقت الإصدار.

## قواعد الخدمة

`PrintTemplateService` هو المسار الوحيد لإنشاء مسودة، نشر مراجعة، نسخ قالب، أو تعيين مراجعة. لا يقبل التعيين مسودة، ولا يغير نشر مراجعة تعريفاً منشوراً سابقاً. عند تعديل قالب منشور تُنشأ مسودة بإصدار تالٍ؛ يبقى القالب المنشور صالحاً للطباعة إلى أن تنشر المراجعة الجديدة.

الترحيل `000058` ينسخ `sales_config.designs` غير الفارغ إلى قالب مصدره `migrated` ومراجعة أولى وتعيين افتراضي للفواتير الضريبية. لا يحذف الإعداد القديم؛ لذلك تظل المخرجات الحالية مستقرة حتى تتبنى طبقة الإخراج الجديدة هذا التعيين صراحةً.

## المرحلة التالية

على مرحلة محرر القوالب استهلاك `PrintTemplateContract` وسجل المتغيرات الأمامي معاً. وعلى مرحلة الإصدار إضافة binding مرجعي للمستند المنشأ أو المرحّل يحفظ `print_template_revision_id`، ثم يقرأ محرك الطباعة هذا الربط قبل أي تعيين حي.
