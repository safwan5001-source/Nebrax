# API_AUTH_401_FIX_REPORT — R1: anonymous `/api/*` → 401 JSON

## Summary
Anonymous requests to protected `/api/*` routes now return **HTTP 401 `{"message":"Unauthenticated."}`** regardless of the `Accept` header. Previously, omitting `Accept: application/json` produced **HTTP 500** (`Route [login] not defined`).

## Root cause
Laravel 11's `ApplicationBuilder::withMiddleware()` installs `redirectGuestsTo(fn () => route('login'))`. `Authenticate::unauthenticated()` evaluates that callback **eagerly** whenever `!$request->expectsJson()` — inside the middleware, before any exception renderer runs. This app defines no `login` route (no web routes), so `route('login')` throws `RouteNotFoundException` → 500. (The smoke report's suggested handler-only fix would not have worked; the exception is raised before the handler.) `bootstrap/app.php` is generated by `setup.sh`/CI and is not tracked, so the fix lives in a tracked provider.

## Code changes
`app/Providers/TenancyServiceProvider.php` — new private `renderApiAuthenticationFailuresAsJson()`, called from `boot()`:
1. `Authenticate::redirectUsing` and `AuthenticationException::redirectUsing`: return `null` for `api/*`; otherwise `route('login')` (previous behaviour, unchanged).
2. Re-applied via `afterResolving(HttpKernel::class)` so it survives `withMiddleware` re-installing the default, in either kernel resolution order (Codex review P1, adopted in `7330c2b`).
3. `Handler::shouldRenderJsonWhen`: JSON when `expectsJson()` **or** (`AuthenticationException` on `api/*`). All other exceptions keep default behaviour (validation redirects/422 unchanged).

Not touched: guards, Sanctum token validation, RBAC, sessions, migrations, accounting, API contracts (other than 500 → 401).

## Security & tenant isolation
- 401 body is the existing generic message; no tenant/customer data, no route names, no stack traces.
- The override runs only after authentication has already failed; it cannot grant access. Authorization (403) verified unchanged.
- No tenant context is read or set in the new code.

## Remaining risks
- Override keys on the `api/*` path prefix; any future protected API routes registered outside `/api` (e.g. `/store/v1`, `/platform`-style prefixes) would still hit the old behaviour if they use `auth` middleware without `Accept: application/json`. Current storefront/public groups use `ForceJsonResponse`.
- Non-API guarded routes still throw if no `login` route exists (pre-existing, intentionally unchanged).
- Local scaffold copy used for dev tests is stale vs CI (pre-existing).
