# عقد السمات (Themes) — v3.0-draft

> `[APPROVED]` Default = Tinted Neutral · `[APPROVED]` الثيم الاختياري = **AWJ Ink** (قشرة داكنة / مساحة عمل فاتحة) ·
> `[APPROVED]` الثيم الثالث **AWJ Core** (قشرة بلون الهوية الأزرق نفسه: Light `#1E40AF` · Dark `#1E3A8A` [D-42، كان `#4F8CFF` في D-41]، اختيار المالك الصريح) — §6A ·
> `[REJECTED]` Exploration C (شريط علوي حبري + جانبي مصبوغ) خارج الاتجاه المعتمد.

## 1. المبدأ

**السمة = نبرة القشرة، لا أكثر.** السمة تُغيّر مظهر الشريط الجانبي والعلوي (وما يتبعهما: حقل البحث، حالة العنصر النشط، علامة المؤسسة).
مساحة العمل (Desk/Paper)، المكوّنات، التخطيط، دلالات الحالات، منطق التفاعل، سطح النتيجة — **كلها نواة واحدة**.

AWJ Ink وAWJ Core **ليسا Fork**. كلٌّ منهما مجموعة قيم لـ13 توكناً فقط فوق نفس النظام ([`TOKEN_REFERENCE.md`](./TOKEN_REFERENCE.md) §4).
أي فرق بنيوي (ترتيب، حجم، مكوّن إضافي) بين السمات **عيب** يُصلَح.

|---|---|---|---|
| الاسم الداخلي | `default` | `ink` | `core` |

| القشرة (Dark) | حبر كحلي (= Ink) | حبر كحلي (= Default) | **أزرق الهوية المتوسط `#1E3A8A`** (`brand-700`) — مستقلة |
| نص القشرة | داكن | فاتح | **أبيض في الوضعين**؛ Apex: Light أبيض · Dark `#A9C4FF` |
| العنصر النشط | لوح أبيض مرفوع + Apex `#1E40AF` | لوح `#1A2A4A` + إطار داخلي + Apex `#7FA8FF` | Light: لوح `#3558C8` + إطار داخلي + Apex أبيض · Dark: لوح `#425FAB` + إطار داخلي `#8FA9E8` + Apex `#A9C4FF` |
| الشعور | هادئ، طويل الجلسة، يقرّب القشرة من الورق | أقوى هوية وتباين، بيانات أسطع | هوية الأزرق صريحة على القشرة؛ يطابق لون الأفعال |
| الافتراضي؟ | **نعم** | اختيار | اختيار |
| المخاطرة | فاصل القشرة↔Desk ضعيف (1.09:1) يُراقَب | ثقل بصري/إجهاد جلسة طويلة غير مُختبَر `[EXPERIMENTAL]` | مساحة زرقاء مشبعة كبيرة؛ قشرة Dark متوسطة (1.92:1 مع Desk `#07090C`، كانت 6.20:1 مع `#4F8CFF`) — راحة الجلسات الطويلة غير مُختبَرة `[EXPERIMENTAL]` |

سطح النتيجة (`surface-outcome`) **حبري في السمتين** ويعمل كمفتاح نغمي: في Default هو النقطة الداكنة الوحيدة في الصفحة، وفي Ink يتناغم مع القشرة. ([`SIGNATURE_LANGUAGE.md`](./SIGNATURE_LANGUAGE.md) §2)

## 3. ما يجوز للسمة تغييره

**13 توكناً فقط** (القائمة مغلقة): `shell-bg`, `shell-fg`, `shell-fg-muted`, `shell-line`, `shell-hover`, `shell-active-bg`,
`shell-active-fg`, `shell-active-shadow`, `shell-apex`, `shell-field-bg`, `shell-field-line`, `shell-focus-ring`, `shell-brandmark-bg`.

وتُغيَّر **قيمها**، لا أدوارها ولا أسماؤها.

## 4. ما لا يجوز للسمة تغييره (Forbidden)

| الممنوع | السبب |
|---|---|
| ألوان الدلالة المالية (`status-*`) | الأحمر خطر والأخضر نجاح في كل مكان. تغييرها يكسر ثقة المحاسب |
| Desk / Paper / Band / Sunken / الحدود / النصوص | مساحة العمل نواة مشتركة؛ بيانات المستخدم تُقرأ دائماً على السطح نفسه |
| `surface-outcome` | معناه «النتيجة النهائية» ثابت عبر السمات |
| `action-primary*` (الزر الأساسي، الروابط) | الفعل المقصود يجب أن يُعرف فوراً؛ لا لون زر مختلف لكل مستخدم |
| عقد التركيز (السماكة، الإزاحة، الحد الأدنى للتباين) | عقد وصولية |
| التباعد، الزوايا، الكثافة، الطباعة، الحركة | Postures وحدها تتحكم (لا السمات) |
| حجم/ترتيب/وجود أي مكوّن، أو نص | السمة لا تُغيّر التخطيط |
| معاني الأيقونات والحالات | |
| ما يخصّ الـPosture (لمس، وسائط، كثافة) | |

## 5. ما يتشاركانه حتماً

نفس المكوّنات والتخطيط · نفس **الدلالات المحاسبية** (مدين/دائن، مرحّل/مسوّدة، إلخ) · نفس معاني الحالات · نفس عقد التركيز · نفس منطق التفاعل
(hover/selected/editing) · نفس لغة الأرقام · نفس نصوص الواجهة · نفس اختبارات الوصولية (مصفوفة 2 سمة × الأوضاع).

## 6. السمة ≠ الوضع (Ink ≠ Dark Mode)

**تصحيح للمفهوم القائم:** الوضع الداكن **موجود اليوم** (`.dark` في `globals.css`، `next-themes` بـ`attribute="class"` و`defaultTheme="system"`، زر `theme-toggle`).
فالسؤال ليس «هل نبنيه» بل **كيف تتفاعل السمتان معه**.

| | **Theme** (Default / Ink / Core) | **Mode** (Light / Dark) |
|---|---|---|
| ما يتغيّر | نبرة القشرة (13 توكناً) | **كل** الأسطح والنصوص والحدود والحالات |
| مساحة العمل | فاتحة دائماً | تتبع الوضع |
| ملكية الاختيار | تفضيل المستخدم (+ افتراضي المنشأة `[OPEN]`) | تفضيل المستخدم/النظام |
| الآلية المقترحة | سمة على الجذر `data-awj-theme="default\|ink\|core"` | `class="dark"` (القائم، next-themes) |
| يُخزَّن | ملف المستخدم + `localStorage` كاحتياط | `next-themes` القائم |

**محورا تحكّم مستقلان — لا دمج في محوّل واحد.** (دمجهما في `next-themes` كقيم `ink`/`dark` سيجعل Ink والداكن يتنافسان.)

### مصفوفة Theme × Mode

| | Light | Dark |
|---|---|---|
| **Default** | مُواصَف هنا | Dark v3 (الشريحة 10): كل الأسطح الدلالية داكنة؛ القشرة نغمة حبرية أدكن من Desk |
| **Ink** | مُواصَف هنا | **= Default-Dark** `[DECIDED D-12]` |
| **Core** | مُواصَف هنا (§6A) | **مستقل** `#1E3A8A` `[DECIDED D-41/D-42]` — الاستثناء الوحيد من D-12 |

**لماذا Ink-Dark = Default-Dark** (وCore هو الاستثناء المقصود، §6A): ما يميّز Ink هو **التباين بين قشرة داكنة ومساحة عمل فاتحة**. في الوضع الداكن هذا التباين غير موجود، فتصير السمتان بلا فرق حقيقي. إتاحتهما معاً تضاعف الاختبار (4 تركيبات × RTL/LTR × Posture) بلا قيمة. عند اختيار Dark يُعطَّل محدّد السمة (أو يُتجاهل) ويُوضَّح ذلك للمستخدم.

### Dark v3 — `[DECIDED]` مُنفَّذ (S10، H3)

1. الأسطح بالتدرّج النغمي (الارتفاع بالفاتحية لا بالظل): `desk (#07090C) < sunken < paper (#1C1F28) < band ≈ raised < docked < float`.
2. أزواج الدلالة: قيم `#16A34A`/`#F87171`/`#D97706` **أُبقيت كما هي** (استمرارية مع `.dark` v2.0) وأُعيد التحقّق منها فعلياً على `paper` الداكن الجديد (`#1C1F28`): 4.99 · 5.95 · 5.17 — تجتاز.
3. `surface-outcome` بلا تغيير (حبري ثابت عبر الوضعين، D-13)، ويُفصَل عن Desk الداكن بـ`box-shadow: inset 0 0 0 1px var(--awj-outcome-edge)` (`ink-600`) — قاعدة CSS مخصّصة لا تغيير في قيمة السطح.
4. `action-primary` = `brand-500` (`#4F8CFF`): `brand-600` سقط دون 3:1 على `paper` الداكن. ولأن الأبيض على `brand-500` لا يجتاز 4.5:1، نصّ الزر (`action-primary-fg`) أصبح داكناً (`ink-900`) في هذا الوضع فقط — لا تغيير في منطق الزر.
5. الظلال أُبقيت (خافتة جداً، `rgba(0,0,0,…)`) كدعمٍ لا كمصدر وحيد للفصل؛ الفصل الأساسي من فرق الفاتحية بين الأسطح.
6. **مصفوفة التباين الكاملة (28 زوجاً، كلها ناجحة) في [`TOKEN_REFERENCE.md`](./TOKEN_REFERENCE.md) §11.**
7. **لا مصفوفة Ink داكنة ثانية:** `shell-*` تحت `.dark` = القيم المحسوبة لـ`theme.ink` حرفياً (مرجع واحد في المولِّد)، فتُنفِّذ D-12 بنيوياً لا بالتوثيق فقط. **Core وحده** يتجاوزها بكتلة `[data-awj-theme="core"].dark` أعلى خصوصية (13 توكناً قشرة فقط)، فلا تتأثر Default/Ink.

## 6A. AWJ Core `[APPROVED]` `[DECIDED D-41 · D-42]`

**العقد (اختيار المالك الصريح):** قشرة الشريطين الجانبي والعلوي = **Light `#1E40AF`**، **Dark `#1E3A8A`** (`primitive.brand.700`، التصميم M المعتمد بعد المقارنة البصرية في PR #1535، D-42). كان Dark `#4F8CFF` في D-41 فاستُبدل: وهجه 6.20:1 مع Desk الداكن ولمعانه ≈5.4 أضعاف. بنية Default وتخطيطه وتفاعله **كما هي** حرفياً؛ يتبدّل 13 توكن قشرة فقط (§3).

**القيم المنفَّذة** (المصدر `awj.tokens.json` → `theme.core.light|dark`، مرجع الأرقام والتباين: [`TOKEN_REFERENCE.md`](./TOKEN_REFERENCE.md) §4 و§12):

| التوكن | Core Light | Core Dark |
|---|---|---|
| `shell-bg` | `#1E40AF` (brand-600) | `#1E3A8A` (brand-700) |
| `shell-fg` / `shell-fg-muted` | `#FFFFFF` / `#CBD9FB` | `#FFFFFF` / `#DCE5FB` |
| `shell-hover` / `shell-line` | `#2A4DBF` / `#5573D2` | `#2E4A98` / `#3D5AA6` |
| `shell-active-bg` / `-fg` | `#3558C8` / `#FFFFFF` | `#425FAB` / `#FFFFFF` |
| `shell-active-shadow` | `inset 0 0 0 1px #6F8BE0` | `inset 0 0 0 1px #8FA9E8` |
| `shell-apex` / `shell-focus-ring` | `#FFFFFF` / `#FFFFFF` | `#A9C4FF` / `#FFFFFF` |
| `shell-field-bg` / `-line` | `#18368F` / `#9DB4EE` | `#142B6B` / `#8FA9E0` |
| `shell-brandmark-bg` | `#FFFFFF` | `#A9C4FF` |

**قرارات تصميم:**
1. **لوح العنصر النشط ليس أبيض** (خلافاً لـDefault): Apex يُستهلك نصّاً على القشرة (عنصر فرعي نشط، hover) وشريطاً على اللوح معاً، ولا يوجد لون واحد يجتاز 4.5:1 على `#1E40AF` وعلى الأبيض. فاللوح درجة أفتح من القشرة (نمط Ink) وApex أبيض في Light و`#A9C4FF` في Dark.
2. **حلقة التركيز** الموحَّدة (`--awj-state-focus-ring` = brand-600) تختفي (1:1) على قشرة Core؛ لذا قاعدة CSS يدوية واحدة، **محصورة بـCore داخل `[data-awj-shell]`**، تأخذ `--awj-shell-focus-ring`، وتستثني القوائم/الحوارات داخل القشرة (تعود إلى Paper). Default وInk بلا تغيير.
3. **Dark: قشرة متوسطة بنص أبيض (D-42).** `#4F8CFF` (D-41) كان يُلزم نصاً داكناً (الأبيض عليه 3.22:1) ويلمع 6.20:1 فوق Desk الداكن؛ `#1E3A8A` يعيد النص الأبيض (10.36:1) ويبقى فوق Desk بـ1.92:1 فقط، ويحتفظ بهوية زرقاء مميزة عن Ink-Dark `#0E1A31` (1.67:1) وبقرب من قشرة Light (1.19:1).
4. **Apex في Dark = `#A9C4FF`:** يُستهلك نصاً (فرع نشط، hover، شعار) وشريطاً؛ على `#1E3A8A` أقل منه (`#8FB4FF`) يهبط نص hover دون 4.5:1. تباينه: 5.93 على القشرة · 4.72 على hover · 3.48 شريطاً على لوح النشط.
5. **وضوح Active/Hover/Focus في Dark:** Shell→Hover **1.26** · Hover→Active **1.36** · Shell→Active **1.70** (حدود مسجَّلة بنيوياً في `contrastChecks`: 1.2 · 1.3 · 1.6) بدل 1.19 · 1.33 · 1.58 في M الموثَّق أولاً — بخافت `#DCE5FB` أفتح ليبقى ≥ 4.5 على اللوح الأفتح (4.82). حلقة التركيز **بيضاء** في الوضعين (10.36 على القشرة · 8.24 hover · 6.08 لوح النشط · 13.23 الحقل) وتوازي حلقة Light.
6. **النطاق:** كالسمات الأخرى (§9A، §10): Ledger فقط؛ Floor/Studio/Storefront لا تتبنّى Core. مساحة العمل والمكوّنات والدلالات المالية وسطح النتيجة والأزرار **كلها نواة واحدة**.
7. **الحفظ:** `awj:theme=core` في localStorage + `preferences.appTheme='core'` على الخادم (قائمة التحقق في `UpdateAccountPreferencesRequest` تقبل `default|ink|core`؛ بلا migration، العمود JSON قائم).

## 7. الحماية: التباين والوصولية

1. **كل سمة تجتاز مصفوفة التباين** قبل القبول (§12 في [`TOKEN_REFERENCE.md`](./TOKEN_REFERENCE.md)): نص القشرة ≥ 4.5، Apex/تركيز/حقول ≥ 3.0.
2. **تحقق آلي:** اختبار وحدة يقرأ مصدر التوكنز ويحسب نسب كل زوج مسجَّل؛ فشله يمنع الدمج ([`GOVERNANCE.md`](./GOVERNANCE.md) §4).
3. **`prefers-contrast: more`** يرفع كل السمات: `shell-line` ← أقوى، `shell-fg-muted` ← `shell-fg`، ويُلغى `shell-cast`.
4. **`forced-colors`:** Apex والحدود التي تعتمد `background` تُكمَّل بـ`border`/`outline` بألوان النظام.
5. **شعار المؤسسة على Ink وCore:** الشعار الداكن يختفي على الحبر وعلى أزرق Core؛ لذلك يُرسَم دائماً داخل **لوحة شعار** (`brandmark plate`: `surface-paper`، `radius.control`، حشوة 2px) في كلتا السمتين، فلا يتبدّل ظهوره بالسمة. ([`TENANT_BRANDING.md`](./TENANT_BRANDING.md))

## 8. التطبيق المقترح (للشريحة 7، دون تنفيذ الآن)

```
<html class="dark?" data-awj-theme="default|ink|core" data-awj-ui="3">
```

- `data-awj-ui="3"` **بوابة التفعيل** لكل v3 (الشريحة 2 فصاعداً): حذف الخاصية = رجوع كامل لما كان. ([`MIGRATION.md`](./MIGRATION.md))
- القيم تُعرَّف كمتغيرات CSS تحت `[data-awj-theme="ink"]` و`[data-awj-theme="core"]` فوق قيم Default؛ لا CSS مكوّنات مخصّص لـInk.
- قراءة التفضيل **قبل الرسم** (سكربت مضمَّن صغير أو cookie) لتفادي وميض السمة.
- اختيار السمة لا يغيّر مسارات ولا صلاحيات ولا بيانات.

## 9. سمات إضافية (مستقبلاً)

سقف v3 **ثلاث سمات** (Default/Ink/Core). أي سمة جديدة (شريك، White-label، تباين مرتفع) تمرّ بالعملية في [`GOVERNANCE.md`](./GOVERNANCE.md) §6:
قيم للتوكنز الـ13، مصفوفة تباين ناجحة، لقطات بصرية لـ3 شاشات مرجعية، واعتماد مالك. لا سمة تُضيف توكناً خارج الـ13.

## 9A. نطاق القشرة (H5) `[DECIDED D-37]`

القشرة (`data-awj-shell`) تقع على `--awj-shell-bg` لا على Paper؛ لذلك تُعاد المتغيّرات القديمة (`--text/--muted/--border/--surface/--primary/--primary-soft`)
**داخلها فقط** من توكنز `shell-*`، وتعود القوائم/الحوارات/القوائم المنسدلة داخل القشرة (`role=menu|dialog|listbox|tooltip`) إلى Paper. قبل H5 كانت
نصوص الشريط تقرأ ألوان Light فتصير شبه غير مقروءة على Ink (1.0–2.8:1)؛ المسح الحيّ لـInk صار 0 إخفاقات.

## 10. ما تفعله السمات مع الـPostures

| Posture | تأثير السمة |
|---|---|
| **Ledger** | كامل: الشريط الجانبي + العلوي بحسب السمة |
| **Floor (POS)** | القشرة مصغّرة (بلا قائمة جانبية). لوحة السلة/الدفع **سطح نتيجة حبري** في كل السمات. **`[DECIDED H4]` Floor يبقى على القشرة الافتراضية (شريط علوي Paper) ولا يتبنّى Ink ولا Core**: تجربة بصرية (قشرة Ink على الشريط العلوي) أنتجت شريطاً حبرياً فوق لوحة حبرية — «قوسان» ثقيلان يحيطان بكتالوج فاتح، وفشلت عناصر الشريط الحالية (شارة الجلسة بخلفية سطح) في القراءة؛ والفائدة المرجوّة (تخفيف الوهج) لا يحققها شريط واحد بعرض 56px. يُعاد فتحه فقط باختبار كاشير فعلي |
| **Studio** | **لا تتأثر**: أدوات الاستوديو بـ`awj-editor-*` graphite محايدة ثابتة كي لا يتلوّن إدراك ألوان التاجر |
| **Storefront** | **لا تتأثر** (نظام آخر — [`STOREFRONT_BOUNDARY.md`](./STOREFRONT_BOUNDARY.md)) |
