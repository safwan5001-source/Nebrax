> **الحالة:** خارطة معتمدة أساساً للبرنامج. **قرارات المالك:** V2 هو التصميم المرجعي النهائي · AD-01 معتمد · AD-02…AD-13 قيد المراجعة قبل شرائحها · App Factory مسار مستقل ضمن هدف الاكتمال. لا Merge ولا Deploy ولا Production دون موافقة صريحة.

> **السجل المرجعي:** `AWJ-APP-BUILDER-MASTER-GAP-REGISTER.md` (**108 فجوات**: الـ97 الأصلية + DRF-11 + UX-08…UX-11 + APF-01…APF-06) · **القبول:** `AWJ-APP-BUILDER-ACCEPTANCE-MATRIX.md`.

## 1) مبادئ البرنامج

1. **لا فجوة تُسقَط ولا تُؤجَّل خارج البرنامج:** كل الفجوات مربوطة بشريحة أو بشرط عابر (SEC-03, CPT-05, QA-07). الترتيب زمني فقط.
2. **سلامة الحفظ والتوافق والأمان أولاً.**
3. **V2 هو الأساس التصميمي:** يُنفَّذ **فوق** `BuilderApp/Draft/PublishedVersion` والمحرر الحالي؛ الوضع المتقدم محفوظ؛ لا محرك موازٍ؛ مشكلات V2 المثبتة تُصلَح أثناء التنفيذ (UX-08…UX-11)؛ أي تغيير جوهري في التصميم يحتاج موافقتك.
4. **لا يُعدّ شيء مكتملاً إلا عبر المسار الكامل:** المحرر ← الحفظ ← التحقق ← النشر ← الخدمة ← Runtime (جهاز/معاينة) ← (وللإصدار الحقيقي) App Factory.
5. **كل شريحة = من 1 إلى 4 PR صغيرة** بنطاق محدد، وعلم ميزة حين تغيّر سلوكاً قائماً.
6. **كل PR:** اختبارات وحدة/تكامل + أمن وعزل مستأجرين وصلاحيات + مراجعة توافق رجعي + تقرير تنفيذ `docs/reports/app-builder/Sxx-IMPLEMENTATION-REPORT.md`.
7. **أي هجرة أو تغيير عقد API:** يُوثَّق أثرها وتوافقها في الـPR ويُعتمد قبل الدمج.
8. **لا تبدأ أي شريحة قبل مراجعتك نتائج السابقة** (قرارك الأخير). لا شريحة تعتمد على قرار AD غير معتمد.
9. **أرشيف النسخ المنشورة** يُشغَّل كاختبار توافق في كل شريحة (CPT-05).
10. **لا مساس بالمنطق المحاسبي.**
11. **لا إعلان اكتمال** ما دامت فجوة معتمدة بلا دليل إغلاق.

## 5) الشريحة S01 — سلامة الحفظ (AD-01 المعتمد)

**الترتيب المعتمد للتنفيذ:** **S01a أولاً وحدها**، ثم مراجعتك، ثم S01b، ثم S01-INV، ولا **S01c** قبل اكتمال الحصر وموافقتك.

| PR | المحتوى | الطبقة | القيود المعتمدة |
|---|---|---|---|
| **S01a** | `base_revision` **اختياري** في جسم PUT؛ `UPDATE … WHERE revision = :base` داخل معاملة بقفل صف؛ **409 `draft_conflict`** بـ`{current_revision, updated_by, updated_at}`؛ مقياس «حفظ بلا base_revision»؛ fixture عقد | BE | لا 428؛ بلا هجرة؛ اختبارات PostgreSQL للتزامن/الصلاحيات/العزل/التوافق الرجعي |
| **S01b** | الويب: تخزين revision؛ حوار التعارض؛ **لا كتابة فوق** إلا بعد إعادة جلب أحدث revision وتأكيد المستخدم؛ **مسودة محلية احتياطية** تحفظ التعديلات عند التعارض وفشل الشبكة؛ حارس مسار؛ Ctrl+S؛ استعادة تمرّر revision؛ حجب `manage` | FE | لا ضياع للتعديلات المحلية |
| **S01-INV** | **تقرير حصر**: كل مسارات الكتابة (حفظ المحرر، استعادة الإصدار، عملاء API، اختبارات، أوامر/سكربتات) وتوافقها | توثيق | شرط لـS01c |
| **S01c** | فرض `base_revision` (428 `revision_required`) | BE | **لا يُنفَّذ قبل اكتمال S01-INV وموافقتك** |

**الاعتماديات:** AD-01 (معتمد). لا هجرة. لا تغيير في Flutter.

**الاختبارات (إلزامية):**
| النوع | الحالات |
|---|---|
| **I (PostgreSQL)** | حفظ بـrevision صحيح؛ revision قديم ⇒ 409؛ بلا revision ⇒ مقبول (انتقالي) مع المقياس؛ **سباقان متزامنان (`pcntl`)**: واحد ينجح والثاني 409 ولا تضيع كتابة؛ restore لا يكتب فوق مسودة أحدث |
| **S** | مستأجر آخر ⇒ 404 موحّد؛ `view` فقط ⇒ 403؛ لا تسريب `updated_by` عبر المستأجرين |
| **C** | توافق رجعي: عميل قديم بلا `base_revision` يعمل كما كان؛ fixture عقد إضافية |
| **W/E (S01b)** | حوار التعارض بمساراته، المسودة المحلية عند فشل الشبكة، حارس المسار، سيناريو بمتصفحين |

## 6) إدارة البرنامج

- **لوحة الحالة:** عمود «الحالة·الدليل» في السجل؛ الإغلاق الكامل = كل الصفوف «مغلقة · دليل».
- **بوابة الموافقة:** لا دمج ولا نشر قبل موافقتك؛ كل PR يُرفَق به معايير القبول ونتائج الاختبارات وأثر الهجرة/API وخطة التراجع.
- **الاعتماديات الخارجية المعلنة:** مفاتيح FCM/APNs (S19)، بنية الفيديو (S14)، وحسابات المتاجر (AF03) — مرصودة وليست مسقَطة.
- **App Factory:** مسار مستقل **ضمن هدف الاكتمال**؛ لا يبدأ ضمن S01؛ ويُعتبر المشروع غير مكتمل ما دامت APF-01…APF-06 مفتوحة.
