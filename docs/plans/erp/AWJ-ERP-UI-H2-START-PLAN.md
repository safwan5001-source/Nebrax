**الاقتراح الأساسي: «H2 = إغلاق ذيول H1 + حماية من الانحدار + تحقق عبر المتصفحات».** UI فقط، بلا API، بلا محاسبة.

- أي تغيير محاسبي، ضريبي/ZATCA، تسعير، أرصدة، مخزون، رؤية tenant/branch، auth/RBAC، قاعدة البيانات، API عام، البنية التحتية.
- ميزات جديدة أو وحدات «قريباً».
- النشر/الإصدار/الهجرة على الإنتاج.
- `web/src/app/platform/**` و`web/src/components/platform/**` (مسار AWJ-PLATFORM-UX-H1).

## 4. بوابات القبول لكل شريحة (موروثة من H1-1 §3)
1. PR مستقل لكل شريحة، رأس نهائي واحد.
2. Vitest كامل على الرأس النهائي + `npm run build` + Web CI أخضر.
3. قبل/بعد مقاس على المسارات المتأثرة بالأدوات نفسها.
4. مراجعتا Reviewer وAWJ Guardian على الرأس النهائي، و**إعادة قراءة كل خيوط المراجعة مباشرة قبل الدمج** (درس H1-8b)، ثم `PRE_MERGE_REVIEW` و`POST_MERGE_REVIEW` بالـMerge SHA الحقيقي.
5. بعد الدمج: فحص CI على `main` قبل بدء شريحة تابعة.
6. المدموج ≠ المنشور؛ لا نشر دون موافقة مستقلة.
