# AWJ-PAY-H4-02 — حجز المخزون والتحرير الآمن (D-14 خيار A) — تقرير التنفيذ

**الحالة:** مُنفَّذ. لا هجرة، لا قيود، لا حركة مخزون. البوابة الإلكترونية تبقى مغلقة افتراضياً.

## ما بُني
| البند | التفصيل |
|---|---|
| الحجز عند الإتمام | `CommerceCheckoutService::holdStockForPayment` للنية الإلكترونية فقط؛ نقص ⇒ `insufficient_stock` (السطر المعني) وتراجع كامل |
| `acquire` | يقبل `variantId` و`expiresAt`؛ يقفل صف مخزون المتغيّر؛ إصلاح: كان يتجاهل المتغيّر |
| `reserve` | يمرّر المتغيّر والموعد؛ المخزن يُحسم عند أول سطر متتبَّع (طلب خدمات بلا سياسة تنفيذ لا يفشل)؛ `OrderLineUnavailableException` تسمّي السطر |
| الإعداد | `sales.commerce_payment_hold_minutes` (60؛ 15..1440؛ تحقق في `UpdateSalesSettingsRequest`) |
| المكنسة | `CommerceUnpaidOrderSweeper` + `commerce:expire-unpaid-orders` كل 5 دقائق (`withoutOverlapping`, `onOneServer`) |
| دفع ناجح | `completeCaptured` يجعل الحجز دائماً (`expires_at=null`) |
| إلغاء الإدارة | يحرّر الحجز (best-effort، والمكنسة شبكة أمان) |

## الاختبارات
- `OnlineOrderStockHoldTest` (12): حجز 60 د بلا حركة/قيد، الإعداد، مشترٍ ثانٍ، COD بلا حجز، مكنسة (حي/منتهٍ/مزوّد غير متاح/ملتقَط/متأخر/idempotent)، إلغاء الإدارة، الجدولة، المتغيّرات.
- PostgreSQL: سباق المكنسة مع الالتقاط (4 جولات) ⇒ لا «مدفوع بحجز محرَّر» أبداً.
- انحدار: التجارة/المتجر/الحجز/المخزون/الإعدادات/الجدولة/المدفوعات.

## المخاطر والمتبقي
- مزوّد غير متاح باستمرار ⇒ يبقى الحجز (آمن) حتى عودته؛ لا تنبيه تشغيلي بعد (يُقترح في H4-03/الإغلاق).
- حجز دائم لطلب مدفوع حتى H4-03 (الاستهلاك عند الإصدار).
- سباق `revalidateAndPrice` (ترتيب السلة) ↔ `reserve` (ترتيب product_id) على أقفال صفوف المخزون: احتمال جمود نظري بين إتمامين متزامنين بسلتين متعاكستي الترتيب؛ يُعاد المحاولة تلقائياً (`DB::transaction(..., 3)`)، وهو موجود أصلاً في `revalidateAndPrice`.
