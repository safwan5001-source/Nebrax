# AWJ-PAY-METHOD-VISUAL — تخصيص أيقونة/صورة/لون طريقة الدفع

## القرار المعماري (الأصغر المتوافق رجعياً)
- **5 أعمدة إضافية nullable على `payment_methods`** بلا backfill: `visual_mode` (`default|icon|image`، NULL = افتراضي)، `icon_key` (قائمة بيضاء من 14 مفتاح Lucide)، `icon_color` (`#RRGGBB` فقط)، `logo_path`/`logo_disk`.
- **الشعار** يعيد استعمال `AttachmentStorage` (نمط صورة الموظف): نطاق جديد `payment-method-logo`، مفتاح R2 مشتق من `TenantContext`، مسار `payment-methods/{id}/logo` (GET `payments.view`، POST/DELETE `payments.manage`) مصادَق ومعزول بالمستأجر عبر `findOrFail`. لا مكتبة وسائط جديدة.
- التنافي: أيقونة/افتراضي يُسقطان الشعار (الخادم يحذف الكائن بعد الالتزام)، والصورة تشترط شعاراً مرفوعاً. غياب الحقول البصرية في `PUT` يُبقي القائم (لا يمسحه التفعيل/التعطيل).
- **SVG مرفوض صراحةً** (لا تعقيم في خط التخزين): PNG/JPEG/WebP، ≤ 1 ميغابايت، ≤ 2000×2000، فحص محتوى عبر قاعدة `image`. لا روابط خارجية، لا استيراد ديناميكي للأيقونات، اللون يُمرَّر كخاصية `color` بعد التحقق.

## الواجهة
- `modules/payments/methods/`: `visual.ts` (العقد + الخريطة المغلقة)، `PaymentMethodVisual.tsx` (عارض مشترك مع كاش وسقوط آمن)، `PaymentMethodVisualPicker.tsx` (المنتقي: 3 أوضاع، شبكة أيقونات، لون + hex + إعادة ضبط للأيقونات فقط، رفع/استبدال/إزالة بمعاينة).
- مدمج في `/payment-methods` (النموذج + القائمة) وأزرار الدفع في POS.

## خارج النطاق / مؤجَّل صراحةً
- **Storefront Checkout**: واجهته العامة بلا مصادقة وعقد `checkout/payment-methods` مجمَّد الشكل؛ الشعار هنا خلف مصادقة ERP. العرض للمتسوق يحتاج مساراً عاماً/وسائط منشورة (مسار `storefront_media`) وقراراً بعقد API — لم يُنفَّذ.
- منتقيات `<select>` الأصلية (سندات الدفع، الفواتير) لا تعرض أيقونات؛ لم تُغيَّر.
- لا مساس بالقيود/التسوية/الربط المحاسبي/الافتراضية/الأهلية/الصلاحيات.
