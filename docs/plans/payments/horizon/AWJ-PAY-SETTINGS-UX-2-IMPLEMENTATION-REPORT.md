## 2) التغييرات
### Backend
- **هجرة إضافية** `2026_12_11_010000_…`: على `online_payment_method_settings`: `default_gateway_id` (FK → `payment_gateways`، `nullOnDelete`)، `use_in_invoices` (افتراضي true)، `use_in_store` (افتراضي true)؛ وعلى `…_events`: `changes` (لقطة JSON). **الصفوف القائمة تُضبط `use_in_store=false`** فلا يظهر شيء في متجر مستأجر قائم بلا قرار منه. `down()` يرفض متى وُجدت صفوف.
- `OnlinePaymentMethodSettingsService::updateSettings()` (و`setEnabled` يفوّض إليه): يحفظ `enabled`/`default_gateway_id`/`use_in_invoices`/`use_in_store` (الغائب لا يتغيّر). البوابة الافتراضية: اتصال **من المستأجر نفسه، غير ملغى، يعلن محوّله الوسيلة** وإلا `method.default_gateway_invalid` (422). التغيير الفعلي وحده يُدقَّق مرة واحدة (`changes` من/إلى).
- **الجاهزية مع الافتراضية:** إن اختار التاجر بوابة ولم تجهز ⇒ الوسيلة غير جاهزة (`no_usable_gateway`/`provider_setup_required`) و`effective_gateway=null` — **لا تحويل تلقائي إلى بوابة أخرى** (التزام CLAUDE.md: تفادي تكرار الخصم). بلا اختيار ⇒ أول اتصال جاهز كما كان.
- **المتجر:** `storeRows()` = `enabled && use_in_store`؛ `StorefrontOnlineMethodResolver` يستعمل **البوابة الفعلية وحدها** (الافتراضية المختارة أو الأولى) ثم نفس فحوصات PR #1740 (طريقة دفع نشطة متاحة للقناة + `usableGatewayFor` يعيد الاتصال نفسه). **رابط الدفع:** `customerVisibleKeys` يحترم `use_in_invoices` (والاتصال المحدَّد للرابط).
- الاستجابة: `default_gateway_id`، `usage {invoices,store,pos:false}`، `usage_supported`، `default_gateway_selectable`. المتحكّم: كل الحقول اختيارية و`method.nothing_to_update` (422) إن لم يصل أي إعداد معروف. الصلاحية كما هي (`payment_gateways.manage`؛ القراءة `payments.view`).

### Web
- **وسائل:** صف = شعار + اسم + شارة حالة + مفتاح «إظهار للعميل» + «إدارة» (عمودي على الجوال، أفقي ≥ sm) + سطر تنبيه واحد لـ«مفعّلة · غير جاهزة». `MethodManageSheet`: ① الحالة والجاهزية (الخطوة التالية + فتح تبويب البوابات) ② البوابة الافتراضية (تلقائي/اتصال، مع البيئة والجاهزية، والبوابة الفعلية الآن) ③ أماكن الاستخدام (فواتير/متجر مفاتيح حقيقية، POS «غير متاح») ④ الاتصالات. حفظ واحد بالحقول المتغيّرة فقط؛ رفض الخادم يُترجم ويبقى اللوح مفتوحاً ويُعاد قراءة الحال؛ للقارئ فقط: عناصر معطّلة وبلا زر حفظ.
- **بوابات:** `GatewaysPanel` بطاقات (شعار، اسم، مزوّد، شارات: الحالة · البيئة · الاعتماد متحقَّق/غير متحقَّق) + «إدارة» واحد؛ أزرار الإجراءات والصفوف التقنية خرجت من البطاقة إلى اللوح القائم. **لا فقدان لإعداد:** سياسة ضريبة الرسوم كانت على البطاقة فنُقلت إلى قسم «الاستردادات والتسويات» وتُعرض الآن حتى لاتصال بلا محوّل.
- رسائل ar/en للمفاتيح الجديدة؛ `pay-h8-02` e2e يُحدَّث ومصفوفة الإعدادات (320/375/390/768/1024/1440) + سيناريو `payment-methods-manage` الجديد (حفظ حقيقي وإعادة فتح تعرض المحفوظ).

## 6) المخاطر والقرارات
1. **`use_in_store=false` للصفوف القائمة** قرار محافظ: مستأجر فعّل مدى لرابط الدفع قبل Beta لا يظهر في متجره حتى يفعّل «المتجر» من «إدارة».
2. **البوابة الافتراضية الثابتة تعطّل الوسيلة** إن توقفت، بدل التحويل — الاختيار الآمن؛ التاجر يعود لـ«تلقائي» أو يصلح البوابة. التحويل التلقائي متعدد البوابات يبقى H2-04.
3. **الافتراضية لا تغيّر اختيار البوابة في إنشاء رابط الدفع** (يبقى لكل رابط عند إنشائه)؛ تأثيرها على المتجر والعرض فقط.
4. حذف اتصال مختار افتراضياً يعيد الوسيلة إلى «تلقائي» تلقائياً (`nullOnDelete`) دون سجل `changes` (الحذف نفسه مدقَّق في البوابات).
5. شارة مشاكل Next (dev) أخفاها اختبار e2e فقط؛ أخطاء `INVALID_KEY` للترجمة قائمة قبل هذا العمل ومنشؤها خارج نطاقه.
