# AWJ-PAY-H3-02b — بنود الاسترداد في التسوية (A6) والفرق غير المفسَّر (D-21)

DATE: 2026-10-24 · ADR-0008 (accepted) · يعتمد على H3-01 و02a (مدموجتين)

## القيود المحاسبية الناتجة (عبر `LedgerService::post` حصراً)
قيد واحد لكل تسوية مرحَّلة؛ التحصيل 115,000.00 والاسترداد A5 المرحَّل سابقاً (مدين 1130 / دائن 1170 = 46,000.00)، عمولة 1,600.00:

| الحالة | الحساب | مدين | دائن |
|---|---|---|---|
| **A6-1** صافي 674.00 ريال (67,400 هللة) | البنك (1120) | 67,400 | — |
| | 5510 عمولات البوابة | 1,600 | — |
| | 1170 (بند استرداد PRF) | 46,000 | — |
| | 1170 (تحصيل) | — | 115,000 |
| | **المجموع** | **115,000** | **115,000** |
| **A6-2** استرداد بعد تسوية سابقة (1170 دائن 46,000 من A5): تحصيل جديد 115,000 | نفس الأسطر | 115,000 | 115,000 |
| A6-3 خصم الاسترداد على دفعتين (20,000 ثم 26,000) | بند استرداد بجزئه في كل تسوية | | |
| A6-4 صافٍ سالب · A6-5 استرداد غير مرحَّل/بوابة أخرى · A6-11 فرق غير مفسَّر | **لا قيد** | | |

(الأرقام بالهللات في الجدول.) أثر 1170 عبر دورة A1 → A5 → A6-1 = **صفر**؛ لا مساس بـ4110 ولا بضريبة المخرجات ولا بـ1130 في قيد التسوية. المعادلة: `التحصيلات − الاستردادات = الصافي + الرسوم (+ ضريبتها) + الاستقطاعات − الاعتمادات`.

## ما أُضيف
- هجرة إضافية: جدول `payment_gateway_settlement_lines` (`line_type=refund` في 02b) + عمودا `refunds_total` و`unreconciled_minor` + حالة `unreconciled`؛ مُشغّلات PostgreSQL وSQLite: بند الاسترداد يشترط استرداداً مرحَّلاً لنفس المستأجر والبوابة والعملة ولا يتجاوز المستهلَك مبلغه، البنود ثابتة بعد الترحيل، `posted` نهائية، و`unreconciled` لا تحمل قيداً ولا فرقاً صفرياً. `down()` يرفض متى وُجدت بنود أو مسودات.
- `PaymentGatewaySettlementService::record()` (ترحيل أو حفظ `unreconciled`؛ إعادة الإرسال بالمرجع نفسه تحدّث المسودة نفسها وتُرحِّلها حين يصير الفرق صفراً) مع بقاء `post()` الصارم؛ بوابة تفعيل المؤسسة (الإيقاف الطارئ للمنصة لا يمنع تسوية مال وصل فعلاً)؛ رفض `negative_net_unsupported` و`refund_not_posted`؛ معاينة تتبع القواعد نفسها (`saveable_as_unreconciled`، `refunds_total`).
- API: `POST /payment-gateway-settlements` (صلاحية جديدة `payment_settlements.manage` — owner/admin فقط) و`GET /payment-gateways/{id}/unsettled-refunds`؛ الأخطاء النطاقية 422/409 برمز ثابت لا 500؛ تفاصيل التسوية تعرض البنود.
- ترتيب الأقفال: البوابة ← صفوف السندات ← صفوف الاستردادات ← مِرساة المستأجر (لا دورة مع ترحيل A5: محاولة ← استرداد ← مِرساة).

## مراجعة مستقلة (مُعالَجة)
فصل الصلاحيات: `unsettled-refunds` بـ`payment_refunds.view`، وهوية الاسترداد (المعرّف/الرقم) في تفاصيل التسوية لحاملها وحده، وبنود الاسترداد في المعاينة/التسجيل تشترطها · حراس حذف المرحَّل (تسوية/بنود تحصيل/بنود استرداد) في القاعدة والنموذج · العملة = عملة المؤسسة · تاريخ التسوية ≥ تاريخ ترحيل الاسترداد · UUID موحَّد الحالة (لا تكرار بحالة أحرف مختلفة) والتكرار الآمن يعدّ كل سطر · التكرار الآمن لمرحَّلة قائمة يُعاد ولو عُطّلت المؤسسة بعدها · ترويسة المسودة المصحَّحة تُحفظ قبل بنودها.

## حدود معلنة
مُشغّل الانتقال إلى `posted` يعيد فحص الاستهلاك لا أهلية البند (البوابة/العملة/الترحيل) — تفرضها الخدمة وعند إدراج البند في القاعدة · قيد التسوية بلا فرع (النشط) بينما قيد A5 بفرع التصحيح التجاري ⇒ تقرير أعمار 1170 بالفرع (H3-03) · تسوية `gross = 0` (إفراج احتياطي/تعديل دائن) و`gateway_reserve`/`provider_adjustment` = 02c · إعداد ضريبة الرسوم D-04 محجوب بـEXT-05 (يبقى الرفض) · الصافي السالب غير مدعوم (يبقى الاسترداد مفتوحاً) · متبقٍّ في 1170 لكل فرع ممكن (تقرير أعمار H3-03) · لا واجهة (02d) · لا Deploy ولا ترحيل إنتاجي.
