# AWJ-PAY-H2-03b — قسم «الدفع الإلكتروني» في تفاصيل الفاتورة (تقرير التنفيذ)

الأفق: AWJ-PAYMENTS-HZ-01 · يعتمد على API الطلبات (H2-02b) وإصدار الرابط (H2-02e). **لا أثر محاسبي**: الترحيل عند التقاط المزوّد (H2-02c) ويظهر هنا حالةً فقط.

## البحث البصري (إلزامي) — ما شوهد وما لم يتوفر
- **External Evidence:** واجهات الإدارة لدى Stripe (لوحة الفواتير/Payment Links) وOdoo (معالج رابط الدفع) خلف تسجيل الدخول؛ المتاح علناً لقطات جهة الدافع فقط (شوهدت: Stripe Hosted Invoice، Stripe Payment Links، Tap Checkout، Odoo Online Payment في H2-03a/هنا) — **لم يُعثر على لقطة إدارة علنية** وهذا مسجَّل كفجوة دليل. النمط المأخوذ من توثيق Stripe (نص): الرابط يُنشأ من الفاتورة، يُنسخ، له صلاحية، ويُلغى.
- **AWJ Decision:** التزام بأنماط الشاشات القائمة في المنتج (بطاقة داخل صفحة الفاتورة، شارات دلالية، حوار نمطي `Dialog`) لا باختراع نمط جديد؛ DESIGN_SYSTEM (جداول/قوائم كثيفة، لون هوية واحد، أخضر/أحمر دلاليان مع نص، RTL أولاً).
- **Rejected:** إظهار القسم دائماً (يضجّ لمن لا يستعمل الدفع الإلكتروني)؛ عرض الرمز بعد الإصدار الأول (الخادم لا يخزّنه)؛ ربط `custom` برابط دفع (لا محوّل).

## ما بُني
| البند | التفصيل |
|---|---|
| `InvoiceOnlinePayments` (بطاقة في `/invoices/[id]`، تخطيط AWJ v3 والقديم) | قائمة طلبات الفاتورة: حالة (مفتوح/مكتمل/ملغى/منتهٍ)، النوع (كامل/جزئي)، **آخر دفعة** بلغة الإدارة (بانتظار الدافع · مدفوع ومرحَّل · مدفوع قيد الترحيل · محجوب بفترة مقفلة · يحتاج مراجعة · لم يكتمل) مع علامتي «فائض غير مخصص» و«التقاط متأخر»، تاريخا الإنشاء والانتهاء |
| إنشاء طلب | اتصال (مفعّل + قابل للاستعمال + **متحقَّق** + مزوّد له محوّل `moyasar` فقط)، سماح بالجزئي (افتراضياً لا — D-16)، مدة (بلا/يوم/3/7/30) → `POST /invoices/{id}/payment-requests`؛ بعده يُصدَر الرابط تلقائياً |
| إصدار الرابط | `POST /payment-requests/{id}/link`: يظهر **مرة واحدة** في حوار بحقل للقراءة فقط وزرّ نسخ وتحذير؛ الطلب يحمل `link_issued` فقط (إضافة backend صغيرة: حقل منطقي في `InvoicePaymentRequestResource`، بلا إظهار هاش ولا رمز) |
| إلغاء | بتأكيد؛ الخادم يرفض إن اكتمل الدفع (`payment_captured`) |
| الصلاحيات | القراءة `payments.view`، الكتابة `payments.manage` (الخادم هو الحاسم)؛ بلا قراءة أو في المعاينة (demo) أو لفاتورة غير مرحَّلة ⇒ القسم غائب؛ مؤسسة بلا اتصال صالح وبلا طلبات ⇒ غائب (لا ضجيج) |
| الأخطاء | رموز الخادم الثابتة تُترجَم (طلب مفتوح قائم، فاتورة غير قابلة للدفع، تفعيل/إيقاف المنصة، صلاحية…) |
