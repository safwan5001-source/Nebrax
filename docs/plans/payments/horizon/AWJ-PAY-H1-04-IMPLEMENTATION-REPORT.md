## Outcome

صندوق أحداث المزوّد + مستقبِل webhook عام + مطابِق مجدول لاستعادة المحاولات المتعثّرة. **الحدث لا يحمل حقيقة:** يُتحقَّق من توقيعه ويُخزَّن مرة واحدة ثم يطلق استعلام المزوّد (`sync`) فقط؛ ما في جسمه لا يُطبَّق أبداً. **صفر أثر مالي:** لا سند ولا قيد ولا تخصيص (حارس ساكن يمنع استدعاء الخدمات المحاسبية).

## Design

| القرار | السبب |
|---|---|
| المسار العام `POST /api/payment-webhooks/{provider}/{webhookKey}` بلا `SetTenant` ولا مصادقة؛ الهوية = `webhook_key` (فريد عالمياً) + توقيع المزوّد يتحقق منه المحوّل | المزوّد لا يحمل رمز مستأجر؛ المفتاح غير قابل للتخمين (32–128 حرفاً) وحدّ `throttle:600,1` |
| الترتيب: حد 64KB (413) ← حلّ الاتصال خارج نطاق المستأجر (غير موجود/غير نشط/مسودة/ملغى/مستأجر معطّل ⇒ 404 موحّد) ← التحقق من التوقيع (401 خاطئ/غائب، 400 جسم غير مفهوم) ← الإدراج | التوقيع الخاطئ لا يُخزَّن ولا يكشف وجود الاتصال؛ ردود 404 موحدة تمنع الاستقصاء |
| الاتصال `suspended` يستقبل الأحداث؛ إيقاف المنصة الطارئ لا يمنع الاستقبال | ما التقطه المزوّد فعلاً يجب أن يبقى مرصوداً (D-15)؛ الضابط يوقف **البدء** فقط |
| dedupe: `UNIQUE(payment_gateway_id, provider_event_id)` + `body_hash` (SHA-256) — نفس الجسم ⇒ replay 200 بلا استعلام ثانٍ؛ جسم مختلف ⇒ 409 ولا تغيير | حدث بمعرّف واحد وجسمين = تلاعب أو خلل مزوّد |
| الجسم مشفَّر (`encrypted` cast) ومخفي (`hidden`) ≤ 64KB؛ هوية الصف وجسمه غير قابلين لإعادة الكتابة (يُسمح بمسح الجسم فقط للاحتفاظ)؛ الحذف مرفوض | سجل أدلة غير قابل للتحوير |
| الحدث يطلق `PaymentOrchestrator::sync()` (استعلام المزوّد) — لا قراءة حالة من الجسم | حدث متأخر/خارج الترتيب/مزوَّر الجسم لا يُرجع الحالة ولا يلتقط شيئاً؛ الرتابة من `applySnapshot` |
| انقطاع المزوّد أثناء المعالجة ⇒ 503 ويبقى الحدث `received` ويعيد المزوّد المحاولة (المعالجة تُستأنف عند التسليم التالي)؛ حدث لمحاولة غير معروفة ⇒ `unmatched` يُحفظ للمراجعة | لا فقد حدث ولا تطبيق مجهول |
| المطابِق `payments:reconcile-attempts` كل 5 دقائق (`withoutOverlapping`, `onOneServer`): مرشَّحه المحاولة الجارية المتأخرة أو غير الملتقطة ذات صفحة قائمة؛ **إيجار ذرّي لكل محاولة** (`UPDATE … WHERE lease IS NULL OR lease <= now`) ينتهي تلقائياً (120ث) | مطابِقان متزامنان لا يعالجان محاولة واحدة؛ انهيار العامل لا يترك إيجاراً عالقاً |
| الفشل ⇒ تراجع أسّي 2^n دقيقة حتى سقف 60، و`last_reconcile_error` برمز ثابت فقط | لا حلقة ضغط على مزوّد معطّل ولا تسرب تفاصيل مزوّد |
| `PaymentOrchestrator::reconcile()`: يستأنف `created`، ويزامن، وينهي `pending_customer` تجاوزت `expires_at` بلقطة `expired` | تنظيف المتروك دون تدخل بشري؛ لا يمسّ ملتقَطاً |
| المطابِق بلا سياق مستأجر عند البدء ويثبّت سياق كل محاولة ثم يمسحه؛ لا يشترط ضابط التفعيل | عزل لكل محاولة؛ الإيقاف الطارئ لا يعمي النظام عمّا التقطه المزوّد |
| `POST /api/payment-attempts/{id}/sync` (صلاحية `payments.manage`) استعادة يدوية | مسار المشغّل حين يتوقف المجدول (ADR-0004 §5) |
| `GatewayAdapter::verifyWebhook` يضاف للعقد؛ `FakePaymentGatewayAdapter` يوقّع HMAC-SHA256 | المحوّلات الحقيقية تنفّذه في H2-01؛ الصندوق لا يعرف أي مزوّد |

- `PaymentWebhookInboxTest`: **18 ناجحاً** (SQLite وPostgreSQL): توقيع صحيح ⇒ صف مشفَّر + استعلام موثوق (الجسم يدّعي `failed` والمزوّد `captured` ⇒ `captured`)؛ توقيع خاطئ/غائب/لجسم آخر ⇒ 401 بلا تخزين؛ جسم غير مفهوم ⇒ 400؛ مفتاح/مزوّد/اتصال/مستأجر غير صالح ⇒ 404 موحّد؛ اتصال معلّق يستقبل؛ جسم ضخم ⇒ 413؛ مكرر ⇒ replay بصف واحد وبلا استعلام ثانٍ؛ المعرّف نفسه بجسم آخر ⇒ 409؛ متأخر/خارج الترتيب لا يُرجع الحالة؛ حدث لمحاولة مجهولة ⇒ `unmatched`؛ انقطاع المزوّد ⇒ 503 ثم نجاح عند إعادة التسليم؛ السر السابق ضمن نافذة السماح فقط؛ عبور مستأجر مستحيل؛ إيقاف المنصة لا يمنع الاستقبال؛ المسار عام ومحدود المعدل؛ النموذج يرفض إعادة الكتابة والحذف؛ المطابقة اليدوية (401/403/404 للغريب/200/مكرر/503)؛ حارس «لا دفتر».
- `PaymentAttemptReconcilerTest`: **9 ناجحة**: التقاط المتعثّر بلا أثر مالي؛ الطازج والملتقَط لا يُمسّان؛ تراجع أسّي ورمز خطأ ثابت وتعافٍ؛ سقف ساعة؛ إيجار حيّ يمنع التكرار وإيجار منتهٍ يُستعاد؛ انتهاء المتروك والتقاط متأخر يُعلَّم `late_capture`؛ عدة مستأجرين بلا تسرب سياق وبلا اعتماد على الضابط؛ **تمرين الاستعادة (ADR-0004 §5)**: نبض المجدول قديم ⇒ محاولة عالقة ⇒ `sync` يدوي يلتقطها ⇒ عودة النبض ثم `payments:reconcile-attempts` يلتقط الباقي ويكرّر آمناً؛ الأمر مجدول `withoutOverlapping` والمطابِق لا يمسّ الدفتر.
- `PaymentInboxPostgresTest`: **3 ناجحة** على PostgreSQL 16 حقيقي (`pcntl_fork`): 6 تسليمات متطابقة ⇒ صف واحد والكل 200 والالتقاط مرة واحدة؛ 6 أحداث مختلفة لمحاولة واحدة ⇒ 6 صفوف معالجة والحالة `captured` رتيبة بلا مراجعة ولا جمود؛ 4 مطابِقات متزامنة على 4 محاولات ⇒ كل منها تنتقل مرة واحدة فعلياً بلا إيجار عالق.

## Accounting impact

## Tenant / branch isolation impact

`PaymentProviderEvent` يرث مستأجره من اتصاله (يُتحقق في `creating`)؛ حدث اتصال مستأجر لا يلمس محاولات غيره (مختبَر). المطابِق يثبّت سياق كل محاولة. لا أثر على الفروع (CompanyWide).

## Security / authorization impact

نقطة عامة جديدة: محميّة بمفتاح الاتصال + توقيع المزوّد + حد حجم + تحديد معدل. الاستعادة اليدوية تتطلب `payments.manage` وعزل المستأجر. لا استدعاء مزوّد حقيقي (Fake فقط في `local`/`testing`).
