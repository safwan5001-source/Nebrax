# AWJ-PAY-H3-01e — واجهة استردادات البوابة (الويب)

DATE: 2026-10-23 · ADR-0007 (accepted) · يعتمد على H3-01b/c/d (مدموجة)

## القيود المحاسبية الناتجة
**لا قيد جديد.** واجهة مستخدم فقط فوق API الشريحة 01d؛ القيد الوحيد (A5: مدين 1130 + الطرف / دائن 1170) من H3-01c.

## ما أُضيف (`web/src/modules/payment-refunds/`)
- `RefundsPanel` (قائمة + تبويب «تحتاج تدخلاً» + مرشح الحالة من الخادم): اعتماد وإرسال / رفض بسبب ≥ 5 أحرف / إلغاء / حسم الحالة غير المعروفة (هذا استردادنا · لم يُطبَّق) / إعادة ترحيل المحجوب بفترة مقفلة. الأزرار تُخفى بحسب الصلاحية، ولا يرى الطالب أزرار الاعتماد والرفض لطلبه (الخادم يفرضها أيضاً).
- `RequestRefundDialog` (مصادر الاسترداد المؤهَّلة وسعة الدفعة وشرح المانع من `refund-context`، مفتاح منع تكرار مُولَّد) و`ResolveExternalDialog` (حسم علم الاسترداد الخارجي).
- `contract.ts`: ترجمة رموز الرفض الثابتة ar/en مع السقوط على نص الخادم (يشمل `operation_rejected`).
- تكامل في `PaymentsOnlinePage`؛ كتلة `paymentRefunds` في `ar.json`/`en.json`.

## الاختبارات
`RefundsPanel.test.tsx` (7 × لغتين) و`contract.test.ts` (6) + مجموعات الصلاحيات/الرسائل؛ الحزمة الكاملة 698 ملفاً/8384 اختباراً ناجحة، و`npm run build` ناجح. لا أخطاء TypeScript في الوحدات الجديدة (أخطاء قائمة سلفاً في ملفات اختبار أخرى).

## حدود
فحص بصري RTL بمتصفح حقيقي لم يُنفَّذ في هذه الجلسة. استرداد Sandbox الحقيقي PENDING(EXT-01). H3-02 (خصم الاسترداد من التسوية) خارج النطاق.
