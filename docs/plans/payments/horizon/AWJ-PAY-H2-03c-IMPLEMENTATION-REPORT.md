# AWJ-PAY-H2-03c — سجل «الدفعات الإلكترونية» `/payments/online` (تقرير التنفيذ)

الأفق: AWJ-PAYMENTS-HZ-01 · يعتمد على ترحيل الالتقاط (H2-02c) ومعالجة المحجوب (H2-02d). **لا أثر محاسبي**: الشاشة والـ API قراءة فقط؛ إعادة الترحيل تستدعي `POST /payment-attempts/{id}/repost` القائم (H2-02d) الذي يرحّل عبر `PaymentService` فقط.

## القيود المحاسبية الناتجة
**لا شيء جديد.** لا قيد يُولَّد من `GET /payment-attempts` ولا من `GET /payment-attempts/{id}`. أثر زرّ «إعادة الترحيل» هو نفسه المعتمد في ADR-0006 M1 (بلا تغيير): مدين 1170 (تسوية البوابة) / دائن 1130 (العملاء) + الطرف، بالتاريخ المحاسبي الأصلي، وفق H2-02d؛ وتبقى الدفعة «محجوبة» بلا قيد إن كانت الفترة مقفلة.

## البحث البصري (إلزامي) — ما شوهد وما لم يتوفر
- **External Evidence:** سجلات المدفوعات في لوحات Stripe/Moyasar خلف تسجيل الدخول؛ لا لقطات إدارة علنية (نفس فجوة الدليل المسجَّلة في H2-03b). المأخوذ من التوثيق النصي: قائمة مدفوعات بحالة وتصفية بالحالة، وتفصيل بخط زمني للأحداث.
- **AWJ Decision:** نمط القائمة القائم في المنتج (`PageHeader` + `Tabs` + `DataTable` + `Pagination`) وتفصيل جانبي `Sheet` بدل صفحة جديدة؛ شارات دلالية بنص (لا لون وحده)؛ تبويب «محجوبة بفترة مقفلة» بنقطة تنبيه وعدّاد؛ تبويب «تحتاج مراجعة».
- **Rejected / Not Adopted:** عرض `body` أحداث المزوّد أو معرّف الدفع لدى المزوّد أو `checkout_url` (أسرار/PII بلا حاجة)؛ إعادة ترحيل جماعية (قرار بشري لكل دفعة بسبب مسجَّل)؛ تعديل التاريخ المحاسبي من الشاشة (ADR-0004 §3: لا تغيير تلقائي).

## ما بُني
| البند | التفصيل |
|---|---|
| `GET /payment-attempts` (جديد، `payments.view`) | قائمة محاولات طلبات دفع الفواتير فقط (`payable_key` بادئته `invoice_payment_request:`)، ترتيب الأحدث، ترقيم (`per_page` ≤ 100). مرشّحات: `capture_status`، `posting_status`، `needs_review`، `invoice_id`. الصفوف: الفاتورة (رقم)، البوابة (اسم/مزوّد/بيئة)، الحالات، المبلغ والملتقط والعملة، أسباب المراجعة، سبب الحجب، التاريخ المحاسبي، الطوابع |
| `GET /payment-attempts/{id}` (جديد، `payments.view`) | نفس الصف + `postings` (السندات المرحَّلة: مخصَّص/فائض + رقم السند) + `timeline` مرتَّب: إنشاء ← أحداث المزوّد (النوع والنتيجة فقط) ← التقاط ← ترحيل ← قرارات إعادة الترحيل (الفاعل والسبب والنتيجة) |
| **لا يكشف** | الرمز العام وهاشه، `checkout_url`، `provider_payment_id`، `idempotency_key`، `body` أحداث المزوّد، أسرار البوابة |
| `/payments/online` | تبويبات (الكل · محجوبة بفترة مقفلة [عدّاد + نقطة] · تحتاج مراجعة)، مرشّح حالة المزوّد في «الكل»، جدول (الفاتورة ← رابط، المبلغ، الحالة بلغة الإدارة + علامات المراجعة، البوابة، التاريخ)، تفصيل جانبي بخط زمني وسندات مرحَّلة وتنبيه سبب الحجب (فترة/سنة) |
| إعادة الترحيل | زرّ يظهر فقط لمن يملك `payments.resolve_blocked` ولدفعة `blocked_period`؛ حوار بسبب ≥ ٥ أحرف (يُقصّ، حدّ ٥٠٠)، نتيجة `posted` ⇒ نجاح، `blocked_period` ⇒ تنبيه «ما زالت الفترة مقفلة» (القرار مسجَّل)، ورموز الخادم (`not_blocked` · `forbidden` · …) تُترجَم |
| الوصول | رابط «الدفعات الإلكترونية» في رأس `/payments`؛ المعاينة (demo) وبلا `payments.view` ⇒ حالة فارغة بلا أي استدعاء |
