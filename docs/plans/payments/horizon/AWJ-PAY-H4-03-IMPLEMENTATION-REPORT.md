# AWJ-PAY-H4-03 — فاتورة وقيود طلب المتجر عند تأكيد الدفع (D-13 خيار A) — تقرير التنفيذ

**الحالة:** مُنفَّذ **ومغلق افتراضياً**. لا أثر محاسبي حتى تتحقق: بوابة النشر + مرجع EXT-05 + سياسة المستأجر + نمط الأسعار الشاملة. هجرة إضافية واحدة (`commerce_order_postings`).

## ما بُني
| البند | التفصيل |
|---|---|
| `CommerceInvoiceOnPayment` | الشروط الثلاثة؛ `gateOpen()` يشترط `tax_opinion_ref` (EXT-05) |
| إعدادات | `sales.commerce_invoice_trigger` (`none`/`on_payment_confirmed`)، `sales.commerce_price_tax_mode` (`inclusive`)؛ رفض 422 للتفعيل والبوابة مغلقة |
| `CommerceOrderPostingService` | فاتورة + استهلاك الحجز + سند A1 + مِرساة، داخل معاملة المنسّق وبنقطة حفظ للرفض |
| `PaymentAttemptPostingService` | تفويض الـpayable التجاري، حجب الفترة، `runPending` يختار الجاهز فقط |
| `PaymentOrchestrator` | `posting_status=pending` لالتقاط طلب المتجر فقط حين `active()` |
| المستمع | `CompleteCommerceOnlinePayment` يرحّل بعد تثبيت النية |
| `commerce_order_postings` | مِرساة ثابتة؛ UNIQUE (طلب، فاتورة، محاولة، سند) |

## الاختبارات
`CommerceInvoiceOnPaymentTest` (9): افتراضياً لا أثر · كل شرط لازم · رفض الإعداد · فاتورة+سند+استهلاك+idempotent · الشحن · فترة مقفلة وإعادة صريحة · معدل غير 15% · manual_link · حارس عدم الكتابة المباشرة. `CommerceInvoicePostingPostgresConcurrencyTest`: ست عمليات ترحيل/تثبيت متزامنة ⇒ فاتورة وسند ومِرساة واحدة بلا جمود.

## المخاطر والمتبقي
- **EXT-05** (الرأي الضريبي: أسعار شاملة، ضريبة الشحن، التوقيت) شرط التفعيل — لا يُفتح قبله ولا لمستأجر حي دون موافقتك.
- فاتورة ZATCA مبسّطة تُصدر بالمسار القائم لـ`InvoiceService::post` (بلا إرسال: الإرسال معطَّل).
- لا استرداد بوابة لطلبات المتجر (يبقى `not_refundable`)، ولا معالجة معدل ضريبي مختلف، ولا تكافؤ `/commerce/v1`.
- التقاط تحت `not_postable` يحتاج إجراء بشرياً (لا شاشة مراجعة بعد).
