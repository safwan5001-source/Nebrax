# AWJ-PAY-H2-02b — طلب دفع الفاتورة والدفع الجزئي لكل رابط

**الحالة:** منفَّذ. **لا أثر محاسبي** (لا سند ولا قيد؛ الترحيل H2-02c).

## ما بُني
| البند | التفصيل |
|---|---|
| `InvoicePayable` (`Payable`) | المبلغ = المتبقي من الفاتورة (يُعاد حسابه) أو مبلغ جزئي مُتحقَّق منه سلفاً؛ الصلاحية: الطلب مفتوح وغير منتهٍ والفاتورة مرحَّلة بمتبقٍ موجب وطرفها كما التُقط |
| `InvoicePaymentRequestService` | `create` (فاتورة مرحَّلة بمتبقٍ وطرف، بوابة صالحة ومتحقَّق منها، ضابط التفعيل، فاعل بـ`payments.manage`، طلب مفتوح واحد لكل فاتورة) · `cancel` (يستعلم المزوّد أولاً: دفع ملتقَط لا يُلغى `payment_captured`؛ ثم يلغي المحاولة النشطة والطلب؛ idempotent) · `startAttempt` عبر `PaymentOrchestrator::start` |
| D-16 | `allow_partial=false` افتراضياً؛ مبلغ ≠ المتبقي يُرفض `partial_not_allowed` ما لم يُفعَّل للرابط، ويُرفض `amount_exceeds_remaining` إن تجاوز المتبقي، و`invalid_amount` لغير الموجب. المبلغ = المتبقي مسموح دائماً |
| D-24 | التقاط فوري فقط؛ لا مسار تفويض |
| API | `GET/POST /invoices/{id}/payment-requests` · `POST /payment-requests/{id}/cancel` · `POST /payment-requests/{id}/attempts` (رأس `Idempotency-Key`، `amount_minor` اختياري، `throttle:30,1`). القراءة `payments.view`، الكتابة `payments.manage`. أخطاء `{error:{code,message}}` بأكواد ثابتة (409 للتعارضات، 503 لتعذّر المزوّد) |
| الاستجابة | بلا `token_hash`؛ `latest_attempt` فيه رابط الدفع للنشطة فقط |

## الاختبارات (`InvoicePaymentRequestTest`، 11، SQLite وPostgreSQL)
افتراضات الإنشاء ولا أثر محاسبي · رفض فاتورة غير مرحَّلة/بوابة غير صالحة/غير متحقَّقة/تاريخ ماضٍ/ضابط تفعيل مغلق · طلب مفتوح واحد وفاتورة مسدَّدة · محاولة كاملة idempotent · الجزئي (ممنوع افتراضياً، مسموح لرابط، سقف المتبقي، غير الموجب) · طلب منتهٍ/مغلق · فاتورة سُدِّدت أثناء الطلب · الإلغاء (idempotent، يلغي المحاولة، يرفض الملتقَط) · RBAC (staff لا يكتب، accountant يكتب) وأكواد الأخطاء والعشري المرفوض · عزل المستأجر (404 لكل المسارات).
