# AWJ-PAYMENTS-HZ-01 — طابور المهام

LAST_UPDATED: 2026-10-22
STATUS: **G0 مغلقة (المالك 2026-10-22)** — القرارات في `docs/decisions/ADR-0004-payments-orchestration-g0.md`. PAY-H0-01 مدموج (PR #1596، `80cbb3c`). شرائح H1 مصرّح بها بالترتيب؛ ما بعد H1 يتبع بواباته (G1–G6). آلية D-12 (ADR-0004 §3) **تنتظر اعتماداً قبل PAY-H2-02**.

## قواعد الطابور

- كل شريحة = فرع من أحدث `origin/main` + PR مستقل. **لا PRs مكدّسة.** التابعة لا تبدأ قبل دمج اعتمادياتها و`POST_MERGE_REVIEW: PASS`.
- **كل Merge بموافقة المالك الصريحة** (D-19). لا Deploy.
- backend ⇒ `php artisan test` كاملاً (SQLite محلياً + SQLite/PostgreSQL في CI). `web/`/`storefront/` ⇒ build + test.
- أثر مالي ⇒ جدول القيود الناتجة في وصف الـPR قبل طلب المراجعة.
- `DONE` = معيار الإغلاق مثبت بأدلة + مدموج + POST_MERGE_REVIEW. لا إغلاق من Mock وحده: كل محوّل حقيقي يُغلق بتحقق Sandbox فعلي مسجّل، والتفعيل الحي في H8-04 بموافقة.
- مهام المالك/الخارجية (`OWN`/`EXT`) تبقى في الطابور حتى تُغلق، ولها معيار إغلاق مثل غيرها.
- الأولوية: **P0** صحة مالية/أمن/عزل · **P1** وظيفة أساسية · **P2** تحسين/تشغيل.
- الحالة: `IN REVIEW` · `READY` · `BLOCKED(<سبب>)` · `PENDING` (اعتماديات لم تكتمل) · `DONE`.
