# AWJ-PAY-H2-02c — ترحيل التقاط الدفع الإلكتروني (تقرير التنفيذ)

الأفق: AWJ-PAYMENTS-HZ-01 · الأساس: ADR-0006 (M1–M8) · القرارات: D-16، D-24، D-26، ADR-0004 §3 (R1)

## ما بُني

| المكوّن | الدور |
|---|---|
| `PaymentAttemptPostingService` | ينسّق فقط: يقفل المحاولة ← الطلب ← الفاتورة، يفحص الفترة، ثم `PaymentService::create/post` (سند مخصّص ± سند زائد) في **معاملة واحدة** |
| `PaymentOrchestrator` (تعديل) | عند أول انتقال إلى `captured` لـPayable طلب فاتورة: `posting_status='pending'` + حدث `PaymentAttemptCaptured` بعد الالتزام. **لا يرحّل ولا يستدعي PaymentService** (يحرسه الاختبار الساكن القائم) |
| `PostCapturedPaymentAttempt` (مستمع) | متزامن؛ يلتقط أي استثناء ويبلّغ عنه فلا يفشل webhook، والالتقاط يبقى `pending` |
| `payments:post-captured` (كل 5 دقائق) | شبكة أمان للمعلّق؛ يستثني المحتجَز (M6) والمحجوب بفترة (R1 صريح فقط) |

لا Migration جديدة (المخطط من 02a). لا مسار HTTP. لا صلاحية جديدة. لا مساس بـZATCA/XML/الضريبة/الفاتورة (الفاتورة تتأثر بـ`paid_amount`/`payment_status` فقط عبر `PaymentService`).

## مصفوفة القيود الناتجة (فاتورة 1,150.00 ر.س = 115000 هللة؛ كلها مثبتة باختبارات)

| الحالة | سندات | القيد (مدين / دائن) | الفاتورة | المحاولة |
|---|---|---|---|---|
| **M1 عادية** | سند 1 مخصّص 115000 | مدين **1170** 115000 / دائن **1130 + طرف** 115000 | `paid` | `posted` |
| **M2 جزئية** (allow_partial) | سند 1 مخصّص 50000 | مدين 1170 50000 / دائن 1130 + طرف 50000 | `partial` (الطلب مفتوح) | `posted` |
| **M3 زائدة** (المتبقي 95000) | سند 1 مخصّص 95000 + سند 2 غير مخصّص 20000 | سند1: مدين 1170 95000 / دائن 1130+طرف 95000 · سند2: مدين 1170 20000 / دائن 1130+طرف 20000 | `paid` | `posted` + `overpayment` |
| **M3ب زائدة كلياً** (المتبقي 0) | سند وحيد غير مخصّص 115000 | مدين 1170 115000 / دائن 1130+طرف 115000 | لا تغيير | `posted` + `overpayment` |
| **M4 مكررة** | لا شيء جديد | لا قيد | لا تغيير مضاعف | `posted` مرة واحدة |
| **M5 فترة/سنة مقفلة** | لا سند | **لا قيد** | لا تغيير | `blocked_period` + سبب (`period`/`year` + المعرّف)، التاريخ لا يتغير |
| **M6 مبلغ/عملة مختلفان** | لا سند | لا قيد | لا تغيير | `pending` محتجَز للمراجعة (لا يُزاحم المطابِق) |
| **M7 غير ملتقطة** | لا شيء | لا قيد | — | بلا حالة ترحيل |
| **M8 التقاط متأخر** | كـM1/M3ب حسب المتبقي | كما المناظرة | كما المناظرة | `posted` + `late_capture` |
| **R1 بعد فتح رسمي** | كـM1… بالتاريخ الأصلي | كما المناظرة | كما المناظرة | `posted` (`$explicit=true` فقط؛ لا تلقائياً) |

`accounting_date` = تاريخ التقاط المزوّد بتوقيت `Asia/Riyadh` (اختبار: 22:30 UTC ⇒ اليوم التالي). `payment_method` = `bank` على الحساب البنكي الرئيسي (طرف النقد يحلّه `CashBankAccountService` كباقي سندات البوابة؛ الأثر المحاسبي الفعلي على 1170 لا البنك).

## الاختبارات

- `PaymentAttemptPostingTest` (16، sqlite وPG): M1–M8، التجزئة، الزائد، التكرار، **انهيار بين السندين** (تراجع كلي ثم إعادة تنتج المجموعة مرة واحدة)، UNIQUE في القاعدة، فترة/سنة مقفلة، R1 الصريح، تاريخ الرياض، **عزل المستأجر**، المطابِق، حارس ساكن (لا LedgerService/journal/ZATCA/InvoiceService في الخدمة)، عدم تغيّر أعمدة `zatca_*`.
- `PaymentAttemptPostingPostgresTest` (3، pcntl، تفشل ولا تُتخطّى على PG بلا pcntl): ترحيل متزامن لالتقاط واحد ⇒ سند وقيد واحد؛ زائد متزامن مع سداد خارجي ⇒ لا تجاوز للمستحق والمخصص+الفائض = الملتقط؛ سباق مع قفل فترة ⇒ مرحَّل أو محجوب لا نصف حالة؛ بلا جمود (مكرَّر 3 مرات).
- RBAC: لا مسار HTTP جديد؛ المحرّك يعمل بلا فاعل. Backward compat: Payable غير هذا النوع لا يتلقى حالة ترحيل ولا حدثاً (اختبارا `PaymentAttempt*` القائمان بلا تعديل).

## حدود معلنة

- M6 (الاحتجاز) لا مسار بشري لحسمه بعد: يبقى `pending` ويظهر في المراجعة؛ الحسم قرار لاحق (لا قرار جديد هنا).
- معالجة المحجوب بشرياً (`payments.resolve_blocked`، تنبيه، جاهزية الإقفال) = H2-02d. API العام = H2-02e.
- المستمع متزامن (`QUEUE_CONNECTION=sync`)؛ نقله لطابور عند وجود عامل لا يحتاج إعادة كتابة (الحدث والمعالجة idempotent).
- EXT-01 مفتوح: كل شيء بمزوّد وهمي ولا مفاتيح حقيقية.
