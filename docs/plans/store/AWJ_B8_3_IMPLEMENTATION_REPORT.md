# AWJ B8-3 — محرر سياسات التاجر (تقرير التنفيذ)

**Base:** `origin/main@3f331dd49e46b94f8a415bca3b3ea5881e62247b` · **الفرع:** `claude/b8-3-policy-editor` · **No Merge · No Deploy**

## 1) ما الذي تغيّر
محرر عربي أولاً للسياسات الأربع (الشحن، الخصوصية، الإرجاع، الشروط) داخل لوحة **«المحتوى»** في Customizer، يعيد استعمال عقد B8-1 `pages[].content` ومسار الحفظ/النشر/الإصدارات القائم. **لا CMS ولا جدول ولا API ولا هجرة.**

- **الواجهة:** زر «تحرير النص» لكل سياسة (لا للصفحات الأخرى) يفتح محرراً بتبويب لغة (العربية/English) وحقل عنوان وحقل نص Markdown، وتبويب «تحرير/معاينة». الاتجاه `rtl` للعربية و`ltr` للإنجليزية. حقول بحجم 16px على الجوال (تجنّب تكبير iOS) وأهداف لمس 44px.
- **الحدود:** عدّاد `n / 80` للعنوان و`n / 20,000` للنص (بالـcode points كما الخادم)، وخطأ مضمَّن باللغة نفسها عند التجاوز («تجاوزت الحد بمقدار N حرفاً — اختصر النص قبل الحفظ»)، وحقل `aria-invalid`.
- **المعاينة الآمنة:** `PolicyMarkdownPreview` يبني عناصر React فقط (لا `dangerouslySetInnerHTML`): عناوين h2–h4، فقرات، قوائم، اقتباس، عريض/مائل، وروابط `https|mailto|tel` فقط بعد إزالة المحارف المموِّهة، مع `rel="noopener nofollow ugc"`؛ HTML الخام يُجرَّد، والصور تُحذف، والرابط غير الآمن يتحول إلى نص. تقريبٌ لعرض الخادم (B8-2) لا نسخةٌ منه.
- **حالة السياسة (مسودة):** شارة «مخفية» (الصفحة غير مفعّلة) / «مفعّلة بلا نص» (الزائر يرى «غير موجودة») / «جاهزة — تظهر للزوار بعد نشر النسخة»، وفقرة تقول إن ما يُكتب مسودة.
- **الحفظ والنشر:** التعديلات تمر عبر `patch({pages})` فتفعّل «مسودة غير محفوظة» وحمايتها، وتُحفظ بـ«حفظ المسودة» مع `revision` النسخة، وتُنشر وتُرجَع بالنسخ كأي إعداد.
- **تعيين خطأ 422:** `savePresentationVersion` يُرجع الآن `issues` (كان النشر والجدولة فقط)؛ `describePublishIssues` يُنتج جملة محددة: «تعذّر الحفظ… الخصوصية (العربية): نص السياسة يتجاوز 20,000 حرف». ومحلياً تظهر أخطاء الحقول الدقيقة مباشرة بنفس قواعد الخادم.
- **إصلاح حاسم:** مطبِّع web كان يقتطع النص صامتاً إلى 20000/80 عند كل تعديل (فيستحيل تجاوز الحد وترى الخطأ). صار يحتفظ بالنص كما كُتب ويُعلَم عنه (`policyContentIssues`)؛ الخادم هو السلطة (422). توأم `storefront/` (عرض فقط) لم يتغير.
- `pagesHint` القديم لم يُمَسّ (يستعمله تذييل المعاينة)؛ أُضيف `policiesHint`.

## 3) الاختبارات والنتائج (محلياً)
- **web vitest — كل `store-experience-builder`: 162 ملفاً / 3069 اختباراً ناجحاً** (تشمل الجديدة: 13 + 3، وانحدار حفظ/نشر/إصدارات/تعارضات Customizer القائمة).
- تغطي الجديدة: تحرير AR/EN وحفظ `pages[].content`؛ حدود 80/20,000 (بما فيها الرموز فوق-BMP)؛ تعيين 422 إلى سياسة/لغة/حقل؛ القذر/النظيف؛ مسودة مقابل جاهزة/مخفية/فارغة؛ توافق وثيقة قديمة (لا مفتاح `content` ولا تغيير `title`)؛ عدم وجود HTML غير آمن في المعاينة (script/img/svg/javascript:/ترميزات)؛ تكافؤ مفاتيح AR/EN.
- **PHP (الخلفية لم تتغير):** `StorefrontPolicyContentTest` + `StorefrontPublicPolicyApiTest` + Draft/Version API على **PostgreSQL 16 حقيقي: 89 ناجحاً**؛ presentation/golden على sqlite: 392 ناجحاً (RBAC `commerce.manage` 403/401، عزل المستأجر/المتجر 404، حجب المتون عن اللقطة العامة، الرفض 422 الذري).
- `tsc`: لا أخطاء في الملفات الجديدة/المعدّلة (أخطاء ملفات اختبار قديمة غير مرتبطة موجودة على main). `next build`: انظر الـPR/CI.
- لا lint مضبوط لـweb (لا ESLint في المستودع)؛ CI يفرض `vitest` و`next build`.

## 4) المخاطر والفجوات
- **حالة «منشورة فعلاً» لا تُعرض:** الشارة تصف المسودة فقط؛ إظهار ما هو حيّ الآن يحتاج لقطة منشورة داخل المحرر (تحسين لاحق).
- المعاينة تقريب (محوّل Markdown صغير في الواجهة)؛ الحاكم هو الخادم.
- تعيين الحقل الدقيق من استجابة 422 يظهر كجملة في الإشعار، بينما الأخطاء المضمَّنة تأتي من نفس القواعد محلياً؛ لا إبراز للحقل من نص الخادم.
- لا اختبار e2e على iPhone حقيقي؛ التصميم يعتمد 16px/44px ولم يُفحص بصرياً على جهاز.
- الاقتطاع الصامت أُزيل من web فقط لسياسات المحرر؛ مستند قديم محفوظ لا يُمَس.

## 5) الخطوة التالية
