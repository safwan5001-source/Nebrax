## Environment facts that shape every result
* **Un-hydrated pages under the managed hostname.** `next dev` blocks its HMR WebSocket for hosts outside `allowedDevOrigins` (localhost / shop.lvh.me ...), and such a page never hydrates (no `__react*` keys on any node, 30 s+). Browsing `http://vd5-a.store.vd5.test:3102` (README method) therefore renders SSR markup only: no `onError` fallback, no effects. All hydration-dependent checks use `hostproxy.mjs` (localhost:3310 -> :3102, Host rewritten to the managed host; Origin of plain requests follows Host so Server Actions pass). Pure SSR/HTTP checks use the managed host directly.
* Public `store/v1`: 30 req/min per IP; SSR, the image proxy and every hydrated Server Action re-render share 127.0.0.1. `reset-throttle.sh` is called before loads (recorded, not "fixed"). S-11 records what an empty bucket looks like.
* Dev mode only: no prod build was run (dev vs prod caveat for S-10/S-11). The dev overlay requests `/__nextjs_font/geist-latin.woff2` -> 403 through the QA proxy (noise, filtered, 8 occurrences = 1 per load).
* The home presentation silently keeps only 30 sections (`StorefrontPresentationNormalizer::MAX_HOME_SECTIONS`): my first matrix publish dropped the tail (`customContent`, hidden) of S1's seeded home. Restored at the end (new published revision/version ids on S1; seeded section list is identical again).

## Defects (not fixed, per the rules)
* **D-S-1 medium** — English home shows Arabic value names. Repro: `curl --resolve vd5-a.store.vd5.test:3102:127.0.0.1 http://vd5-a.store.vd5.test:3102/sa/en` -> discovery tiles carry `name`, not `name_en` (556 failing `name` checks in `json/S-1-results.json`, `shots/S-1/en-*`), while `/sa/en/products` renders "Image circle". Pre-existing (legacy sections behave the same, S-3). Suspect: `storefront/src/lib/commerce/data-sections.ts` `fetchDiscoveryValues` uses `getLocale()` (request locale is the default there) instead of the `locale` that `DiscoverySection` already receives.
* **D-S-2 medium (a11y)** — carousel focus leaves a half-clipped tile. Repro: S1 section `carousel / swipe-rail` (rows 2), 390x844 RTL, Tab through items: items 5-6 sit at x -58..78 (scroller edge 8) with `scrollLeft` 0; the browser does not scroll because the item is partly visible (`harness-sf/dbg-kbd390.mjs`, `shots/S-9-carousel-390-focus.png`). Suspect: `DiscoveryItems.tsx` `CAROUSEL` (native snap scroller, no focus handler).
* **D-S-3 medium (a11y, store-wide, shown on discovery)** — fixed mobile bottom bar obscures focused links (WCAG 2.2 2.4.11). Repro: 390x844, Tab into a discovery link near the viewport bottom: tile at 701..844 or 763..844 under `nav.fixed.bottom-0.h-store-bottom-nav` (top 783) (`shots/S-9-bottom-bar-obscures-focus-390.png`). Suspect: no `scroll-padding-bottom` for the bottom bar in the storefront layout CSS.
* **D-S-4 improvement/risk** — an empty throttle bucket makes the home lose ALL discovery sections and even the store name / product shelf ("no products" empty state), `shots/S-11-T1-throttled-ssr.png`; images 502 `no-store` (tiles degrade to icon/initial, fine). Environment fact here; confirm in production that the per-IP key is the shopper, not the shared Next server egress.
* **D-S-5 improvement** — `textPosition: beside` + counts: the visible count is pushed to the far inline end, detached from its label (`shots/S-1/ar-1280-ig-beside.jpg`).
* **D-S-6 improvement** — `overlay` on `md` (80px) frames: the 2-line caption covers the glyph/image (known accepted item 6; reconfirmed with real data, `shots/S-1/ar-1280-ep.jpg`).
* **D-S-7 improvement** — `icon-grid` replaces image-only values by the facet-default icon, so three different image values all show the same gift glyph (by design, rule 3; `shots/S-1/ar-1280-mi.jpg`).
* **D-S-8 low (not VD)** — home presentation save silently truncates beyond 30 sections (no 422); dropped the hidden `customContent` of S1 during QA. Proxy 404s for malformed shapes come from Next's router with `no-cache, must-revalidate` (dev) instead of `no-store`, and `?x=1` on a valid image path is served 200 (distinct cache keys; harmless).
