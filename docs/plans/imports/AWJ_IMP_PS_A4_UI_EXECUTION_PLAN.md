### 2.3 عقد الأخطاء (يحكم رسائل الواجهة — **المفتاح هو `reason` لا `message`**)

الشكل: `{message, reason, details?}` (`PartnerStatementReviewException`). `403` لـ`AuthorizationException`؛ `422` لمدخل/رفض موحَّد؛ `409` لحالة/قِدَم/تعارض؛ `429` لـthrottle؛ `403` لبوابة القدرة (موقوفة/معطّلة).

| الفئة | الأسباب (`reason`) | معالجة الواجهة |
|---|---|---|
| قِدَم | `run_stale`, `statement_changed`, `run_is_not_the_reviewed_run`, `void_policy_changed` | شريط «تغيّر الدفتر/الكشف» + زر «تشغيل مطابقة جديدة»؛ `void_policy_changed` = إعادة محاولة تلقائية واحدة ثم رسالة |

## 4. Mobile UX

مبدأ: **الجوال مسار عمل كامل لا نسخة مصغَّرة** — المراجعة تُبنى كـ«صف انتقاء» (triage) لا كجدول جنباً إلى جنب.

| العنصر | سطح المكتب | الجوال |
|---|---|---|
| القائمة | `DataTable` + فلاتر شريط | بطاقات `MobileRecordItem` (الطرف ← الدور/الفترة ← الحالة ← تقدّم المراجعة)؛ الفلاتر في `Sheet` سفلي + شرائح فلتر مرئية |
| المعالج | خطوات أفقية + جداول | **شاشة لكل خطوة** + تذييل ثابت (السابق/التالي)؛ ربط الأعمدة كبطاقات (عمود ← حقل) لا جدول؛ معاينة العيّنة بتمرير عمودي ببطاقات |
| مساحة المراجعة | لوحتان: كشفهم ⇄ دفاترنا | **قائمة بطاقات السطور** بشرائح نتيجة (تمرير أفقي) ← فتح السطر في `Sheet` كامل الشاشة: السطر، ثم المرشّحون **متراصّون عمودياً**، ثم شريط إجراءات ثابت (اعتماد/تجاوز/استبعاد/ربط) |
| التقدّم | عدّاد ثابت | شريط تقدّم لاصق «١٢٠/٣٤٠ محسوم» + زر «التالي غير المحسوم» |
| الإغلاق/الإبطال/الاستبدال | حوار | `Sheet` كامل الشاشة بخطوتين (مراجعة الملخص ← تأكيد)؛ الإبطال بنمط تدميري، زر التأكيد معطّل حتى سبب ≥3 أحرف |
| الجداول العريضة (سجل، تصدير) | جدول | بطاقات؛ التصدير يفتح مشاركة/تنزيل الملف |

**قواعد الجودة:** أهداف لمس ≥44px؛ لا تفاعل hover وحده؛ الأرقام والمبالغ `dir=ltr` بأرقام 0–9 (قاعدة `INTL-PHONE`/`ltr-number`)؛ RTL أولاً؛ ترقيم 25–50 مع «تحميل المزيد»؛ لا تمرير أفقي للصفحة؛ حالات الفراغ/الخطأ/التحميل عبر `nebrax/states`؛ حفظ مسودة **سبب القرار** محلياً (بلا بيانات مالية) عند فقدان الاتصال؛ تحذير صريح عند 429 مع إعادة تلقائية. اختبارات Playwright بحجم جوال (Pixel/iPhone) ضمن كل شريحة، لا في A4e وحدها.

**بحث بصري (بروتوكول الأفق §UI):** هذه الوثيقة **لم تُجرِ** بحثاً بصرياً خارجياً (لا طُلب هنا ولا أُتيح). يلزم قبل A4b تحديداً (أعقد شاشة) فصلُ `External Evidence` / `AWJ Decision` / `Rejected` وفق البروتوكول، لمنتجات مرجعية للمطابقة المحاسبية (كشف بنكي/كشف مورد). **هذا شرط بوابة لـ A4b لا افتراض.**

## 6. Settings Integration (PS-A4d)

### 6.1 القائم (يُعاد استعماله، لا نظام موازٍ)

- المفتاح: `Settings::DEFAULTS['partner_statements']['void_separation'] = 'strict'` في `tenants.settings` (JSON)، يُقرأ بـ`PartnerStatementVoidSeparation::effective()` — أي قيمة غير `flexible` حرفياً ⇒ `strict`.
- القاعدة (PostgreSQL وSQLite) تقرأ **صف المستأجر نفسه** وتفرض تطابق السياسة المسجَّلة في حدث الإبطال/الاستبدال، وتعيد التحقق عند الانتقال؛ على PostgreSQL تأخذ `FOR SHARE` على صف المستأجر.
- لا مسار كتابة للمستخدمين (جدار ساكن في `PartnerStatementVoidSupersedeApiTest`: لا ذِكر لـ`void_separation` في `app/Http` و`routes`، ولا `Settings::put('partner_statements', …)`).

### 6.2 مسار الكتابة الآمن المقترح

| الجانب | التصميم المقترح | المرجع في المشروع |
|---|---|---|
| الخدمة | `PartnerStatementPolicyService::update(User $actor, string $mode, string $reason)`: معاملة ← `Tenant::lockForUpdate()` (قراءة طازجة) ← مقارنة ← `Settings::put('partner_statements', ['void_separation' => …], $tenant)` ← حدث تدقيق في المعاملة نفسها؛ **لا كتابة إن لم يتغيّر شيء** | `AiActionTenantEnablementService::update` (النمط نفسه حرفياً) |
| ترتيب الأقفال | قفل صف المستأجر وحده ومعاملة قصيرة، دون أقفال استشارية/مِرساة ⇒ لا دورة مع مسار الإبطال (الذي يأخذ صف المستأجر `FOR SHARE`/المِرساة بعد أقفاله الاستشارية)؛ يُثبَّت باختبار سباق PostgreSQL (إبطال × تغيير السياسة) | سباق A3e الموثَّق (409 `void_policy_changed`) |

| التدقيق | جدول append-only `partner_statement_policy_events` (مستأجر، فاعل، من/إلى، سبب، وقت) — **يحتاج Migration (في A4d وبعد الموافقة)**؛ لا يوجد مدقّق عام للإعدادات (`AiAuditRecorder` للـAI حصراً) | سابقة `SalesChannelSettingEvent` (`CompanyWide`، مُلحق فقط) |
| القراءة | `GET` يعيد: السياسة الفعّالة، **هل هي مخزَّنة صراحةً أم افتراضية**، آخر تغيير (فاعل/وقت/سبب)، وعدّاد «نهائيات أُغلقت بواسطة المستخدم نفسه ضمن آخر X» اختياري (غير مطلوب) | |
| الجدار الساكن | يُعدَّل **عمداً** في A4d: يُسمح بمسار كتابة واحد فقط، من الخدمة الجديدة وحدها (اختبار ساكن يعدّ مواضع `Settings::put('partner_statements'`، ويُثبت أن المتحكّم الوحيد الذي يستدعيها هو الجديد) | تعديل صريح لشرط المالك في A3e §1.6 |
| الواجهة | `/settings/partner-statements` (بطاقة «فصل مهام الإبطال»): شرح بالمخاطر؛ تبديل `flexible` بحوار تحذير + سبب؛ شارة «افتراضي/مخصَّص»؛ سجل التغييرات | قياس على شاشات الإعدادات القائمة (`finance-settings`, `accounting-settings`) |

**ما لا يفعله A4d:** لا يضيف سياسات جديدة (مثلاً الاعتماد الجماعي) إلا بقرار — وفق CLAUDE.md قاعدة 6 ووثيقة Policy Charter. إن قُرِّر أن الاعتماد الجماعي سياسة، فمفتاحه يُضاف في المجموعة نفسها `partner_statements` عبر `Settings::DEFAULTS` (لا Registry موازٍ) — انظر D-A4-04.

### A.3 قواعد التصنيف المقترحة للجرد

1. **ثابت** (محاسبي/أمني/RBAC/بوابة تفعيل) ← لا يُعرَض كخيار مستأجر.
2. **سياسة عمل** لها >1 طريقة صحيحة ← تُجرَد، بافتراض يحمي القائم (قاعدة 6).
3. **بوابة نشر (env)** ← تُسجَّل كحالة تشغيل لا إعداد.
