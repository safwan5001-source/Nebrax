# جسر درج النقدية المحلي — Nebrax POS

## الغرض والنطاق

هذه الطبقة تربط **Nebrax Web POS** بدرج نقدية موصول بطابعة حرارية عبر RJ11/RJ12. الخادم السحابي لا يفتح USB ولا serial ولا طابعة شبكة محلية؛ المتصفح على محطة الكاشير يستدعي جسرًا محليًا مقيدًا، والجسر وحده يرسل نبضة **ESC/POS** للطابعة.

> لا يُعد نجاح HTTP من الجسر نجاحًا ظاهريًا للدرج. لا تعرض Nebrax حالة `opened` إلا عندما يصل إلى API إيصال HMAC صادر من الجسر المقترن بعد قبول مسار الطابعة للنبضة. لا تملك واجهة المتصفح مسارًا لصنع `opened` بنفسها.

| الطبقة | المسؤولية | لا تفعل |
|---|---|---|
| Nebrax API | الصلاحية، الجلسة، إنشاء الأمر قصير العمر، التدقيق، التحقق من إيصال الجسر | لا تصل إلى USB أو printer أو شبكة المحطة |
| Web POS | يطلب أمرًا مصادقًا، يستدعي `127.0.0.1`، ويبلغ API بالنتيجة | لا يحمل سرًا دائمًا ولا يرسل ESC/POS |
| Local Hardware Bridge | يتحقق من Origin وpairing وHMAC وanti-replay، ثم يرسل نبضة محددة | لا يوفر raw command أو shell endpoint أو binding على LAN |
| طابعة ESC/POS | تستقبل `ESC p m t1 t2` وتنبض قناة الدرج | لا تعطي تأكيد مستشعر في هذا الإصدار |

## المسار التشغيلي

1. يضغط الكاشير زر **فتح درج النقدية**، أو ينجح checkout نقدي بينما `cash_drawer_auto_open_after_cash` مفعّل.
2. يتحقق API من جلسة POS المفتوحة والفرع والصلاحية في المسار اليدوي. في المسار التلقائي لا يبدأ أي شيء قبل `commit` الناجح للفاتورة وسندات القبض.
3. ينشئ `LocalBridgeCashDrawerAdapter` أمرًا صالحًا 45 ثانية فقط، يتضمن `action_id` و`device_id` وnonce وHMAC.
4. يرسل Web POS الأمر الثابت إلى `POST http://127.0.0.1:<port>/v1/cash-drawer/open`.
5. يتحقق الجسر من Origin المسموح، pairing secret، انتهاء الصلاحية، HMAC، وعدم إعادة `action_id`. ثم يرسل نبضة ESC/POS الثابتة للطابعة.
6. يوقّع الجسر النتيجة بإيصال HMAC. يتحقق API من الإيصال، يسجل `TYPE_CASH_DRAWER_OPEN_ATTEMPT` مع النتيجة، ويحدّث آخر حالة تشغيلية للجهاز.

فشل الجسر أو الطابعة لا يرمي استثناءً إلى `PosService::checkout` ولا يعكس invoice أو payment أو inventory أو ledger. تظهر للمستخدم رسالة تحذير فقط ويظل البيع ناجحًا.

## التثبيت والتشغيل

يتطلب الجسر Node.js 20 أو أحدث على **محطة POS نفسها**. بدايةً انسخ مجلد `local-hardware-bridge` إلى مسار محلي دائم على المحطة ثم نفذ:

```bash
cd local-hardware-bridge
npm run init -- --origin https://YOUR-POS-ORIGIN --printer "EPSON TM-T20III"
npm start
```

يطبع أمر `init` رمز pairing مرة واحدة وينشئ ملف إعداد خاصًا في `~/.nebrax/cash-drawer-bridge.json` بصلاحية مستخدم. لا تضع رمز pairing في دليل أو لقطة شاشة عامة. في Windows شغّل، مرة واحدة وبحساب محطة POS، script `scripts/install-windows-startup.ps1 -BridgeDirectory <path-to-local-hardware-bridge>` لتسجيل تشغيل `npm start` عند تسجيل الدخول؛ لا يحتاج الكاشير بعدها إلى طرفية يومية. لا يجب تشغيله كمسؤول ما لم يتطلب تعريف الطابعة ذلك.

| إعداد الجسر | القيمة الافتراضية | المعنى |
|---|---:|---|
| `host` | `127.0.0.1` | لا يقبل binding إلى LAN أو `0.0.0.0` |
| `port` | `17463` | يمكن تغييره إلى منفذ محلي بين 1024 و65535 |
| `allowedOrigins` | origin واحد صريح | لا تقبل `*` أو path أو query |
| `printer.transport` | `windows_spooler` على Windows | `windows_spooler` أو `tcp` |
| `drawerChannel` | `0` | قناة ESC/POS: `0` أو `1` |
| `pulseOnMs` / `pulseOffMs` | `120` / `240` | بين 2 و510 ms، تحول إلى وحدات ESC/POS ذات 2 ms |
| `timeoutMs` | `3000` | حد انتظار قصير لمسار الطابعة |

يدعم مسار Windows طباعة RAW عبر Winspool مباشرة إلى queue الطابعة. يدعم مسار TCP طابعة ESC/POS تستمع على `host:port`، مثل `192.168.1.50:9100`. لا يعلن الجسر اكتشافًا عامًا للطابعات ولا يعرض قائمة نظام التشغيل عبر HTTP.

## الاقتران وتهيئة Nebrax

1. افتح **إعدادات POS ← أجهزة نقاط البيع**، واختر جهاز المحطة الصحيح.
2. شغّل الجسر على المحطة نفسها ثم اختر **اقتران الجسر**.
3. أدخل عنوان localhost المطابق ورمز pairing الذي ظهر عند التهيئة.
4. يتصل المتصفح بالجسر المحلي مباشرة. يعيد الجسر سرًا عشوائيًا جديدًا، ويحفظه API مشفرًا فقط داخل إعدادات ذلك الجهاز. لا يعيده مورد API أو الواجهة بعد الاقتران.
5. من **تهيئة نقاط البيع** اختر `الجسر المحلي الآمن`، ثم فعّل الدرج. لا يقبل الخادم التفعيل إذا لم يوجد جهاز POS نشط مقترن في الفرع.
6. فعّل `فتح الدرج تلقائياً بعد الدفع النقدي الناجح` فقط إذا كان هذا سلوك المتجر المطلوب.
7. افتح جلسة POS على الجهاز واستخدم **اختبار فتح الدرج**. الاختبار يسجل ضمن جلسة فعلية ولا توجد عملية مالية منه.

## نموذج التهديد والحماية

| تهديد | الحماية |
|---|---|
| موقع خارجي يحاول فتح الدرج | الجسر يرفض Origin غير الموجود حرفيًا في `allowedOrigins`، ولا يرسل CORS wildcard أو response قابل للقراءة |
| طلب بلا pairing | يرفض الجسر السر غير المعروف قبل أي نبضة |
| إعادة أمر فتح صالح | `action_id` يستخدم مرة واحدة، والأمر ينتهي خلال 45 ثانية |
| موقع Nebrax مزور أو متصفح يرسل نجاحًا | API يتحقق من إيصال HMAC الذي ينشئه الجسر، فلا يكفي `{"status":"opened"}` |
| أمر ESC/POS اعتباطي أو shell injection | لا يوجد endpoint raw command أو parameters نصية للطابعة عبر HTTP؛ الجسر يبني البايتات الثابتة `1B 70 m t1 t2` فقط، ومسار Windows يستدعي script ثابتًا بمعاملات arguments لا shell |
| تعطل الجسر أو الطابعة | timeout قصير و`bridge_unavailable`/`printer_unavailable`، مع عزل كامل عن البيع والقيود |
| سر pairing في واجهة المستخدم | لا يعود السر في `PosDeviceResource`، ويحفظ API القيمة المشفرة فقط |

## الرموز الموحدة للنتائج

| الحالة | المعنى التشغيلي |
|---|---|
| `opened` | قبل الجسر مسار ESC/POS وصدّق API الإيصال |
| `unsupported` | driver أو platform لا يدعم المسار المحدد |
| `not_configured` | الجسر أو pairing أو الطابعة غير مهيأ |
| `bridge_unavailable` | لم يصل المتصفح إلى الجسر المحلي |
| `printer_unavailable` | لم يقبل مسار الطابعة نبضة ESC/POS |
| `permission_denied` | فشل Origin/pairing/HMAC أو الصلاحية |
| `failed` | خطأ تشغيلي محدد لا يكشف تفاصيل سائق محلي |

## الاختبار الفعلي على محطة POS

1. أوصل درج النقدية بمنفذ RJ11/RJ12 لطابعة ESC/POS، **ولا توصله بخط هاتف**.
2. اطبع إيصالًا عاديًا من نظام التشغيل أولًا؛ هذا يثبت تعريف الطابعة والاتصال، وليس الدرج.
3. شغّل الجسر واختبر `GET /v1/health` محليًا. يجب أن يستمع على `127.0.0.1` فقط.
4. اقترن من Nebrax على نفس المتصفح والمحطة، ثم تحقق أن صفحة الأجهزة تعرض اسم الطابعة والحالة `مقترن`.
5. افتح جلسة POS على الجهاز واضغط **اختبار فتح الدرج**. النجاح المتوقع هو سماع/رؤية فتح الدرج مع ظهور `opened` ووقت آخر نجاح.
6. أوقف الجسر وأعد الاختبار. يجب أن تظهر `bridge_unavailable` بلا نجاح كاذب.
7. أعد تشغيل الجسر أو افصل الطابعة. يجب أن تظهر `printer_unavailable` أو `not_configured` وفق الحالة، بلا نجاح كاذب.
8. اضغط الفتح اليدوي كمستخدم بلا `pos.cash_drawer.open`. يجب أن يرفض API ولا ينشئ حدث فتح.
9. نفذ بيعًا نقديًا ناجحًا بعد تفعيل الفتح التلقائي. يجب أن تترحل الفاتورة والدفع أولًا، ثم يفتح الدرج. إن فشل الجسر، تبقى الفاتورة والدفع والمخزون والقيد ناجحة.
10. نفذ بيع بطاقة أو تحويل. لا يجب أن يرسل النظام أي أمر درج تلقائي.

## ما هو مدعوم وما لم يُدعم بعد

| مدعوم الآن | غير مدعوم بعد |
|---|---|
| Windows RAW spooler لطابعة ESC/POS | macOS print queue adapter |
| TCP ESC/POS لطابعة معلومة `host:port` | اكتشاف طابعات LAN أو USB عبر HTTP |
| قناتا drawer `0` و`1` ونبضتان قابلتان للضبط | مستشعر مادي يؤكد حركة الدرج فعليًا |
| فتح يدوي، اختبار، وفتح تلقائي بعد cash checkout | طباعة الإيصال عبر هذا الجسر |
| localhost + Origin allowlist + pairing + HMAC + anti-replay | وصول LAN أو public bridge |

> قبول RAW spooler أو TCP للنبضة يعني أن طبقة الطابعة قبلت بايتات ESC/POS، وليس أن الجهاز قد قرأ مستشعرًا فيزيائيًا للدرج. إن كان مطلوبًا إثبات موضع الدرج الفيزيائي، يلزم جهاز يدعم drawer-open sensor/SDK في مرحلة لاحقة.
