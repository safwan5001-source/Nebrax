# ADR-008: Expense Draft Builder

- **Status:** Accepted
- **Scope:** PR-8
- **Decision owner:** Intelligent Document Center and Accounting domains

## Context

حالة `ready_for_draft` تعني أن دليل المستند أصبح مكتمل المراجعة؛ وهي لا تعني تفويضًا بترحيل مصروف أو إنشاء قيد يومي أو دفع. يظل نموذج المصروف في Nebrax رأسًا ماليًا واحدًا: قيمة الأساس والضريبة والإجمالي تخص Expense واحدًا، بينما تبقى سطور الإيصال المستخرجة دليل مراجعة فقط. لذلك يتطلب تحويل حزمة `expense` المراجعة حدًا ذريًا يعيد قراءة الحقيقة الموثوقة من الحزمة، ويستدعي خدمة المجال المعتمدة بدل أن يقبل حقائق مالية من المتصفح أو يكتب جداول محاسبية مباشرة.

## Decision

ينفذ PR-8 `ExpenseDocumentDraftBuilder` بوصفه تطبيق `TransactionDraftBuilder` الوحيد لمسار Expense. يتلقى الباني `DraftBuildContext` العام و`ExpenseDraftBuildOptions` الذي يقيد إدخال العميل في `account_id`، و`category_id` الاختياري، و`cost_center_id` الاختياري، و`payment_method`. لا يقبل أي مبلغ أو ضريبة أو إجمالي أو عملة أو مستأجر أو فرع أو شريك أو بيانات استخراج خام من العميل.

داخل معاملة قاعدة بيانات خارجية مقفلة، يعيد الباني تحميل الحزمة، والنتيجة الحالية المقفلة، وسجل المراجعة، والمطابقات المؤكدة في نطاق المستأجر والفرع. ينتقل سير العمل حصريًا بواسطة `DocumentWorkflowService` من `ready_for_draft` إلى `creating_draft` ثم `draft_created`. إنشاء المصروف يتم **فقط** من خلال `ExpenseService::create()`؛ لا يكتب الباني `expenses` أو أي جدول قيد أو دفعة كتابة مباشرة، ولا يستدعي `ExpenseService::post()`.

| المجال | القرار الملزم |
|---|---|
| نموذج المصروف | Expense واحد برأس مالي واحد؛ لا توجد Expense lines أو منتجات منشأة من سطور الدليل. |
| العملة | `SAR` فقط في هذا الإصدار؛ لا تحويل ولا أسعار صرف مستنتجة. |
| الحساب | حساب Expense نشط، غير تجميعي، ومرئي في نطاق الفرع عند تفعيل تخصيص الحسابات. |
| الخيارات | التصنيف ومركز التكلفة اختياريان لكنهما نشطان ومرئيان؛ الدفع محصور في `cash` أو `bank` أو `credit`. |
| الشريك | لا ينشأ شريك. `credit` يتطلب مطابقة `header.counterparty` واحدة، مؤكدة، حالية، نشطة ومرئية لمورد؛ النقد والبنك لا ينشئان دفعًا. |
| الأثر المحاسبي | المسودة لا تنشئ قيدًا أو سطر قيد أو حركة مخزون أو دفعًا أو اعتمادًا. |

## Financial interpretation

تظل القيم المالية أعدادًا صحيحة بوحدة هللة. يجب أن توجد قيمة أساس موجبة صريحة (`subtotal_minor`) وضريبة وإجمالي متسقان، وأن تتطابق القيم المشتقة من `ExpenseService::create()` مع الدليل المراجع ضمن تسامح هللة واحد المعرّف في عقد المجال. لا يسمح هذا الإصدار بمبالغ سالبة أو صفرية أو متجاوزة أو كسور أو تحويلات `float`/`double`.

> في المستند شامل الضريبة، لا يعكس PR-8 الضريبة من الإجمالي ولا يخمّن الأساس. البناء مسموح فقط عندما يكون `subtotal_minor` أساسًا صريحًا مراجعًا، وتتحقق معادلة الأساس والضريبة والإجمالي. هذه القاعدة تفشل مغلقًا عندما تكون دلالة الأساس أو تخصيص الضريبة ملتبسة.

لا يحتوي رأس المخطط على معدل ضريبة موثوق؛ لذلك يستنتجه الباني من سطور الدليل فقط عند وجود معدل صحيح متجانس غير ملتبس. وجود معدلات متعددة، أو معدل غير صحيح، أو عدم اتساق مع إجمالي الضريبة يرفض البناء قبل إنشاء Expense أو رابط أو انتقال نهائي. لا تتحول سطور الدليل في أي حالة إلى أسطر مصروف أو منتجات أو وحدات.

## Link migration and lifecycle

ينقل PR-8 `document_transaction_links` من مرجع شراء بمفتاح أجنبي حصري إلى رابط منطقي آمن متعدد الأنواع: `transaction_type + transaction_id`. الهجرة الجديدة تفك المفتاح الأجنبي المقيّد بشراء فقط، وتحافظ على سجلات شراء الموجودة، وتتيح النوعين `purchase` و`expense`. يبقى الفهرس الفريد على المستأجر والفرع والحزمة والنوع، ولا يمكن تحديث الرابط أو حذفه بعد إنشائه.

الاسترجاع الطبيعي للهجرة يعمل عندما لا توجد روابط Expense. وإذا وُجد رابط Expense، يتوقف `down()` عمدًا بدل حذف سجل تدقيق أو تحويله خطأً إلى Purchase. هذا اختيار حفظ بيانات صريح؛ لا يطبّق أي migration إنتاجي ضمن هذا القرار.

تعرض مراجعة المستند `linked_transaction` الآمن، الذي يحوي فقط معرّف الرابط والنوع ومعرّف المعاملة ورقمها وحالتها ووجهة داخلية. يبقى الرابط مرئيًا بعد انتقال Expense الطبيعي إلى `posted` أو `cancelled`، وتعيد محاولة البناء الصالحة المرجع نفسه كإعادة تشغيل idempotent. ترفض خدمة/متحكم Expense حذف مسودة مرتبطة برسالة نطاق آمنة قبل لمس المرفقات أو بيانات المعاملة؛ تعطيل الواجهة مجرد تحسين تجربة وليس حد الأمان.

## API and UI

المسار الكتابي هو `POST /document-batches/{batch}/create-expense-draft`. يتطلب الاستحقاق الكتابي لـ`document_center.core` وصلاحية RBAC المستقلة `documents.center.build_draft`. الطلب الضيق يطلب النسخة المتوقعة وسبب القرار والحساب وطريقة الدفع والخيارات الاختيارية فقط، ويرفض صراحة الحقول المالية والنطاقية والدليل الخام التي لا يملك العميل حق تقريرها.

تعرض واجهة المراجعة CTA لمسودة Expense فقط عندما يكون نوع المستند `expense`، والحالة `ready_for_draft`، والصلاحية موجودة، ولا يوجد رابط سابق. يطلب الحوار خيارات مرجعية مرئية وسببًا، ويشرح أن القيم المالية من الدليل المراجع فقط. بعد النجاح يستبدل CTA برابط Expense وحالته. يعرض نموذج Expense الجديد رابط **استيراد من مستند** إلى الحزم الجاهزة فقط، بينما تعرض صفحة التفاصيل رابط المصدر وتعطّل حذف المسودة المرتبطة.

## Consequences and deferrals

يثبت هذا القرار إنشاء مسودة Expense واحدة قابلة للمراجعة وربطها بدليلها دون خلق أثر مالي. لا ينفذ PR-8 ترحيلًا أو دفعة أو اختيار خزينة أو بنكيًا أو تسوية مورد أو مخزون أو ذكاء اصطناعي أو استدعاء شبكة مزود أو تخزين دائم أو Redis أو عامل أو ClamAV أو Render أو نشر. كما لا يضيف موردًا أو تصنيفًا أو مركز تكلفة أو حسابًا جديدًا تلقائيًا. تظل سياسة الضرائب متعددة المعدلات، والعملات الإضافية، والدفعات، والترحيل، وتفاصيل المصروف متعددة السطور قرارات نطاق مستقلة لاحقة.
