## 1. Ground rules that apply to every item

1. **One PR per bounded task**, own branch, base = current `origin/main` (verify SHA), no stacked dependent PRs by default.
2. **Pre-PR protocol (CLAUDE.md):** full `php artisan test` (no `--filter`) green on **SQLite and PostgreSQL**; for any financial operation the PR body carries the resulting journal entry as a table (accounts, debit, credit); `npm run build` (+ Vitest) for any `web/` change.
3. **Negative-case library** — every Zone C PR must include the cases that apply from this list, not only the happy path: cross-tenant read/write → 404; cross-branch (restricted user) → 404 and *no state change*; role without the permission → 403; deactivated / revoked principal → 403; idempotent replay → same result, no duplicate side effect; concurrent execution on PostgreSQL → no deadlock, no duplicate ICV, no gap; failure mid-way → full rollback (no orphan QR/XML/ICV/journal); secrets never in response bodies, exceptions or logs; `Http::preventStrayRequests()` (no outbound traffic from any test); environment isolation (developer/simulation/production never share credentials, chain or attempts).
4. **Official-validator rule.** No ZATCA-facing shape is "accepted" by an AWJ-vs-AWJ test. From REM-11 onward the SDK result (XSD, EN16931, KSA, QR, SIGNATURE, PIH stages) is the gate; tests that currently encode non-conformant behaviour (two-field body, genesis PIH, 64-byte tag 7) are replaced **deliberately, with justification**, never "fixed" as regressions (A2 finding N8).
5. **Flag-off by default.** `ZATCA_SUBMISSION_DISPATCH_ENABLED` stays `false`; nothing in this backlog enables transmission. Enabling is a separate go-live decision (plan §6 gates G1–G…).
6. **Pre-production data policy** (`AWJ_PRE_PRODUCTION_DATA_POLICY.md`) applies only while REM-00A has not shown otherwise; whether any real taxpayer data exists is **NOT VERIFIED**.
7. **Cross-horizon rule** (`CURRENT-STATE.md`): changes to invoices, VAT, payments, tenant/branch permissions or locks must not silently trigger Delivery-horizon work; any overlap needs a specific ownership review.
