# أَوْج / AWJ — Pre-Production Data Policy

**اعتماد:** صفوان — 2026-09-06  
**النطاق:** مشروع أَوْج بالكامل، ويُطبّق فورًا على تدقيق Products & Inventory الحالي.

## القاعدة الحاكمة

أَوْج ما زال في مرحلة ما قبل الإنتاج. جميع المستأجرين والحسابات والفواتير والمخزون والإعدادات والسجلات والبيانات الموجودة حاليًا بيانات **تجريبية وغير ملزمة**، ولا تمثل بيانات عملاء Production يجب الحفاظ عليها.

بناءً عليه:

1. لا يجوز التضحية بالتصميم الصحيح أو سلامة المحاسبة أو الأمن أو Tenant Isolation أو وضوح النموذج المعماري من أجل الحفاظ على بيانات تجريبية قديمة.
2. لا نضيف تعقيد Backward Compatibility أو migrations انتقالية معقدة إذا كان الغرض الوحيد منها حماية بيانات تجريبية حالية.
3. يجوز قبل أول Production حقيقي تغيير defaults أو schema أو constraints أو migrations، وتنظيف/إعادة تهيئة/حذف البيانات التجريبية، عندما يكون ذلك هو الطريق الأنظف إلى أساس Production صحيح.
4. لا تُعتبر قيمة إعداد أو سلوك قديم «عقدًا يجب الحفاظ عليه» لمجرد وجود مستأجرين تجريبيين يستخدمونه اليوم.
5. تبقى Backward Compatibility مهمة للكود والعقود المعمارية/API المقصودة عندما يكون كسرها غير ضروري أو سيخلق مخاطر مستقبلية؛ الاستثناء هنا يخص **البيانات التجريبية الحالية** وليس السماح بكسر النظام بلا سبب.
6. Tenant Isolation، الدقة المحاسبية، سلامة المخزون، الأمن، القيود المرجعية، idempotency، وسلامة الترحيل تبقى متطلبات إلزامية ولا تُخفف بسبب كون البيانات الحالية تجريبية.
7. أي reset أو destructive cleanup لاحقًا يجب أن يكون مقصودًا ومحدودًا ومراجَعًا؛ هذه القاعدة لا تمنح إذنًا تلقائيًا لـMerge أو Deploy أو Production Release.

## أثرها على Products & Inventory Audit

- لا يُحتفظ بـ`allow_negative_stock=true` أو أي default آخر لمجرد حماية مستأجرين تجريبيين قائمين؛ نعتمد سياسة Production الصحيحة قبل الإطلاق.
- عند إصلاح UOM/barcode/cost authorization/reference integrity يمكن اختيار schema/constraint الأنظف دون بناء migration معقدة لترميم بيانات تجريبية غير مهمة.
- عند التعارض بين «الحفاظ على بيانات تجريبية» و«بناء invariant صحيح قبل Production»، ينتصر الـinvariant الصحيح.

## شرط ما قبل أول Production

قبل اعتبار أَوْج جاهزًا لأول بيانات حقيقية، يجب أن تكون defaults والقيود والسياسات المعتمدة هي الحالة النظيفة النهائية، وأن تُزال أي استثناءات انتقالية كان سببها الوحيد بيانات الاختبار.
