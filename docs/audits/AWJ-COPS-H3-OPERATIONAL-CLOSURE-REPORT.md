## 2. التحقق من أثر الإقرار (R-10): الحالة والأثر المالي/المخزني

### 2.1 ما لم أستطع فعله

**لم أتحقق بالقراءة من حالة CORD-2026-00005 في الإنتاج.** لا أملك في هذه الجلسة وصولاً للقراءة إلى قاعدة بيانات الإنتاج ولا رمز API لمستأجر، ولن أطلب أيّاً منهما. أداة Railway لا تعرض بيانات الطلبات. فهذا البند **غير متحقَّق منه مباشرةً على الطلب الحقيقي**.

### 2.2 ما تحقّقت منه (الكود + الاختبارات)

شغّلت في هذه الجلسة، على نسخة مطابقة لـ`main` (ملفا الخدمة والاختبار بلا فروق):

```
php artisan test --filter='CommerceOrderAcknowledgementTest|CommerceOrderFeedTest|CommerceStaffOrderApiTest'
→ 51 passed (2824 assertions)
```

الاختبار `acknowledging_silences_the_alert_for_everyone_without_changing_or_removing_the_order` يثبت بعد الإقرار:

| الفحص | النتيجة المؤكَّدة بالاختبار |
|---|---|
| `commerce_orders`: `status`، `accepted_at`، `cancelled_at`، `total`، `acceptance_mode` | **بلا تغيير** |
| حالة `commerce_payment_intents` | **بلا تغيير** |
| `commerce_order_fulfillments` للطلب | **0 صفوف** (لا يبدأ تنفيذ) |
| `journal_entries` للمستأجر | **0** |
| `stock_movements` للمستأجر | **0** |
| بقاء الطلب في `attention` | **نعم** (`alert.pending=false`، `acknowledged=true`) — لا يخرج من قوائم العمل |
| تفاصيل الطلب للموظف بعد الإقرار | `status=confirmed` |
| الحدث المُسجَّل | `order.acknowledged` واحد، `data` فارغة، بلا PII |
| تكرار الإقرار (من مستخدم آخر/بعد الإلغاء) | idempotent: صف واحد وحدث واحد، الوقت لا يتغيّر |

كما يحرس الاختبار `only_the_service_writes_acknowledgements_and_the_locks_and_event_order_hold` أن الكاتب الوحيد هو `CommerceOrderAcknowledgementService` وأن ترتيب الأقفال (النية ← الطلب ← الحدث آخراً) محفوظ. وجود الإقرار لا يمسّ `LedgerService` ولا `InventoryService` بحكم التصميم (ADR-30 R-10).

### 2.3 فحص تأكيدي بسيط يملكه المالك (قراءة فقط، دقيقة واحدة)

على الطلب CORD-2026-00005 في `/commerce/orders/{id}`:
1. **الحالة التشغيلية** كما كانت قبل الإقرار (مثلاً «بانتظار القبول» إن كان الوضع يدوياً، أو «مؤكَّد» إن كان تلقائياً) — لم تتحوّل إلى «مقبول/جاهز» بسبب الإقرار.
2. قسم **التنفيذ**: «لم يبدأ».
3. **لا فاتورة ولا سند** مرتبطين بالطلب (والدفع حسب طريقته: COD/استلام لا يُنتج قيداً بسبب الإقرار).
4. الخط الزمني يحمل حدث «تم الإقرار» واحداً.

إن ظهر أي مخالف لذلك فهو **عيب يوقف الاستمرار**.

## 4. عزل المستأجرين والصلاحيات

### 4.1 الأدلة القائمة (مراجعة بالقراءة + تشغيل موجَّه)

`permissions_isolation_scope_and_input_are_enforced` (اجتاز ضمن الـ51) يثبت لـ`POST commerce/orders/{id}/acknowledge`:

| الحالة | النتيجة |
|---|---|
| بلا مصادقة | 401 |
| دور `accountant` (بلا `commerce.orders.view`) | 403 |
| جسم يحمل `tenant_id` | 422 (الهوية من الرمز لا المدخل) |
| معرّف غير موجود / ليس UUID | 404 |
| **مستأجر آخر (owner)** | **404 موحَّد، ولا إقرار يُكتب** |
| مستخدم مقيَّد بمخزن آخر | 404 موحَّد |
| مقيَّد بمخزن الطلب | 200 |
| البوابة مغلقة | 404 كطلب مفقود (`the_closed_gate_answers_404_like_a_missing_order`) |

بالإضافة: اختبارات التزامن على PostgreSQL (`CommerceOrderAcknowledgementPostgresTest`: إقرارات متزامنة ← صف وحدث واحد؛ إقرار × إلغاء؛ إقرار × التقاط دفع؛ إقرار × قبول يدوي/تحصيل COD بلا جمود) — تعمل في CI على `pgsql`؛ وقد نجح فحص `php artisan test (L11, pgsql)` على PR #1971 (head `80aef89`) قبل دمجه. لم أشغّلها محلياً (تتطلب PostgreSQL وpcntl).
قراءات القائمة/attention/التغذية: تغطيها `CommerceStaffOrderApiTest` و`CommerceOrderFeedTest` (رؤية المخازن، عدم N+1، استجابات بلا PII) وقد اجتازت.

### 4.2 الحكم

الأدلة القائمة **كافية** ولا حاجة لفحص إضافي موجَّه جديد. **لم أنفّذ أي فحص عزل على الإنتاج** (لا يُسمح ولا حاجة له).

### 4.3 فجوة معلنة (ليست جديدة)

محدِّد المصادقة على مضيفات التجزئة المشترك بين المشترين (حد IP للمتجر) خارج نطاق H3 ومعلن في تقارير B2C؛ لا يخص مسارات الموظف هنا.

## 7. التوصية

1. **الاستمرار تشغيلياً**: لا مانع مرصود (0 أخطاء 5xx، نشر ناجح، اختبار iPhone للمسار الأساسي ناجح، عزل المستأجر والصلاحيات مثبتان باختبارات اجتازت).
2. **خلال أول يوم تشغيل**: تنفيذ فحص §2.3 على CORD-2026-00005، ثم بنود §3 غير المنفَّذة (الأهم: تبويبان + إقرار بين جهازين).
3. **مراقبة**: معدل 5xx على nibras-api، وشكاوى الطاقم من تنبيه لم يصل (تُصنَّف ضمن حدّ R1 ما لم يكن المتصفح مفتوحاً ومرئياً).
4. **التراجع المتاح فوراً**: ضبط `COMMERCE_ORDER_ALERTS_ENABLED=false` (القراءات الحقيقية للطلبات تبقى؛ يتوقف التنبيه واللوحة الحيّة فقط).
5. **خارج النطاق ولم يُبدأ**: H4، Web Push (H3-P)، H3-6.
