# AWJ Document Platform V2 — PR3-B: تفعيل ملف الإخراج (Output Profile) في المحرر والمعاينة والطباعة وPDF

> الحالة: جاهز للمراجعة — **لا دمج ولا نشر دون موافقة صريحة.**
> النطاق: واجهة `web/` + هذا التقرير فقط. **لا تغيير في الخلفية ولا API ولا قاعدة البيانات ولا ZATCA ولا الضرائب/الإجماليات.**

## 1) الخلاصة التنفيذية

| البند | النتيجة |
|---|---|
| الدورة الكاملة | اختيار المقاس في المحرر ← معاينة ← حفظ ← نشر مراجعة ← طباعة / PDF — تعمل للفاتورة الضريبية والمبسّطة وعرض السعر والإشعار الدائن/المدين وأمر الشراء |
| نقطة قرار واحدة | `resolveDocumentOutputSpec(templateId, profile)` تستهلكها المعاينة والطباعة وPDF معاً، فلا تتباين الأبعاد |
| غياب الملف | السلوك السابق حرفياً (A4 210×297 + `@page` كما كان) — مثبت بـ12 اختبار متصفح |
| ملف لا يدعمه القالب | يُعامل كغائب (فشل آمن)، لا إخراج بمقاس مخمَّن |
| المراجعات المثبّتة | الملف يُقرأ من المراجعة المثبّتة نفسها (`resolveTemplateRevisionDefinition`) فالمستند المرحَّل يبقى بملفه التاريخي |
| حفظ التعريف | لا يُسقط أي مفتاح (`...definition` ثم الحقول المعروفة) — محروس باختبارين |
| الاختبارات | Vitest كامل **12484 ✓** · Playwright **99 ✓ + 1 متخطّى (WebKit غير مثبّت)** · `tsc` 0 أخطاء · `next build` ✓ |

### خلل حقيقي كشفه اختبار PDF الفعلي وأُصلح
غلاف ورقة المعاينة (`DocPageSheet`) كان يحتفظ بعرض الورق (210مم) وحشو الهوامش أثناء **الطباعة**، فيتجاوز مساحة الطباعة (الورق − هوامش `@page`) فيُصغّر Chromium الصفحة كلها ويُزيح المحتوى (قياس: الحبر عند 5.7مم بدل 14مم، والمستند 143مم بدل 182مم). لم يكن اختبار DOM وحده ليكشفه. الإصلاح: `print:!w-auto print:!max-w-none print:!p-0 print:!m-0` على الغلاف. بعده تطابق الحبر الهوامش في كل الحالات.

## 2) المقاسات المدعومة والمؤجَّلة

الإعلان يحكمه الدليل فقط (`supportedPaper` + `minContentWidthMm` في `registry/templates.ts`)؛ **لا يُعلَن مقاس لم يُثبَت تخطيطه**.

| القالب | مدعوم (عمودي/أفقي حيث يُذكر) | أدنى عرض محتوى مُثبَت |
|---|---|---|
| classic · modern · modern-v2 · erp · quotation-proposal · purchase-order-formal | A4 · A4 أفقي · A5 أفقي · Letter · Legal | 182مم |
| retail · retail-v2 | A4 · A4 أفقي · A5 أفقي · Letter (**بلا Legal**) | 182مم |
| classic-v2 | الكل أعلاه + **A5 عمودي + A6 أفقي** | 128مم |
| erp-v2 · minimal · minimal-v2 | الكل أعلاه + **A6 أفقي** | 132مم |
| الحراري 58 / 80 | عرضه من القالب (لفة) — بلا تغيير عن PR #2068 | — |
| مقاس مخصص | للقوالب التي أعلنت `minContentWidthMm` بشرط عرض المحتوى ≥ حدّها (40–420 × 40–600 وفق العقد) | — |

**مؤجَّل صراحةً (يحتاج إعادة تصميم قالب، خارج النطاق):**
- **A6 عمودي** لكل القوالب (كتلة الأطراف والجدول لا تُنزَّل بلا إعادة تصميم).
- **A5 عمودي** لما عدا classic-v2، و**A6 أفقي** لما عدا classic-v2/erp-v2/minimal/minimal-v2.
- **Legal** لـretail/retail-v2 (لم يُثبَت تخطيطهما عليه).
- مخصص لقالب لا يعلن `minContentWidthMm`.

## 3) التدفّق المدمج (Narrow) — بدل تصغير A4 أعمى
عندما يقلّ عرض المحتوى عن **150مم** (`NARROW_CONTENT_WIDTH_MM`):
- تُخفى أعمدة التعريف فقط: `number` و`product_code` و`barcode` — **الوصف والكمية والسعر والضريبة والإجمالي تبقى كلها** (تتحقق الاختبارات من 7 رؤوس وحضور المبالغ).
- حشو خلايا وخط مدمجان (`[data-doc-narrow]` في `globals.css`) ولا كسر لكلمات الرؤوس وسط الكلمة.
- لا تغيير في أي ضريبة أو إجمالي — عرض فقط.

## 4) نموذج الهوامش
- هوامش الملف تُضاف إلى حشو القالب نفسه، وتُطبَّق في الطباعة عبر `@page { size; margin }` وفي PDF عبر إزاحة الصورة داخل `jsPDF` (`buildPdfBlob`) فتتطابق المعاينة والطباعة وPDF.
- الرول (الحراري): لا هوامش (`margin:0` كما PR #2068).
- **فرق تاريخي معلن:** بلا ملف إخراج، الطباعة القديمة تُظهر 182مم (هامش `@page` العام 14مم) بينما PDF القديم 210مم كاملة. لم يُغيَّر عمداً (لا تحويل تلقائي للمخرجات القديمة).

## 5) نتائج المقارنة: معاينة ↔ طباعة ↔ PDF (Chromium حقيقي)
القياس من ملفات الأدلة (`web/test-results/output-profile/*.json` تُولَّد عند تشغيل المواصفة) على بيانات تركيبية (3 أسطر، RTL/LTR، أرقام عربية/لاتينية، QR، شعار، توقيع، تذييل).

| المقاس | قوالب مختبرة | حجم صفحة الطباعة | حجم صفحة PDF المُصدَّر | تساوي عدد الصفحات |
|---|---|---|---|---|
| A4 | 12 | 210×297 | 210×297 | 10/12 (فرق ±1 صفحة في اثنين) |
| A4 أفقي | 12 | 297×210 | 297×210 | 12/12 |
| A5 أفقي | 12 | 210×148 | 210×148 | 12/12 |
| Letter | 12 | 216×279 | 216×279 | 12/12 |
| Legal | 10 (بلا retail) | 216×356 | 216×356 | 10/10 |

مع كل حالة: عرض الورقة وجذر المستند يطابقان (الورق − الهامشين) بتفاوت ≤ 1مم؛ لا عناصر خارج الجذر ولا تداخل خلايا؛ **الحبر على كل صفحة مطبوعة وكل صفحة PDF داخل الهوامش** (يُقاس بـ`pdftoppm`).

**مستند طويل (classic-v2، 40 سطراً):** ≥ 2 صفحة في الطباعة والتصدير في كل المقاسات (A4: 4/4 · A4 أفقي: 4/4 · A5: 5/5 · A5 أفقي: 8 طباعة / 7 تصدير · A6 أفقي: 11 / 10)، والصفحة الأخيرة تحوي الإجمالي.

**فروق مفهومة وغير عيبية:** عدد الصفحات قد يختلف ±1 بين الطباعة (ترقيم HTML بقواعد كسر الصفحات) والتصدير (تقطيع صورة نقطية) — كان قائماً قبل PR3-B؛ الحجم والهوامش والمحتوى متطابقة.
**كلمات مقسومة (`splitWords`):** في المقاسات الواسعة (A4 فأكثر) تظهر عدّادات غير صفرية في بعض خلايا العناوين العربية الطويلة، وهي **سلوك A4 القائم قبل PR3-B** (المرجع المقارَن)؛ أما في المقاسات الضيقة فالمعيار **صفر** صارم ويتحقق (RTL وLTR).

## 6) الحالات الأخرى المثبتة
- **بلا ملف** (12 قالباً): `@page` حرفياً `@media print { @page { size: 210mm 297mm; } }`، وPDF 210×297.
- **غير مدعوم يرجع للقديم:** classic A6/A5، classic-v2 A6 عمودي، classic بهوامش 20، classic-v2 مخصص 120×200، retail/retail-v2 Legal.
- **مخصص مدعوم:** classic-v2 150×210 يُطبَّق بعرض محتوى 130مم.
- **الحراري 58/80:** بلا انحدار، بملف مطابق أو بدونه.
- **iPhone 13 (محاكاة Chromium):** A5 بلا تمرير أفقي، وPDF بمقاس الورق لا مقاس المعاينة المصغّرة.
- **المحرر:** رحلة كاملة (ar سطح مكتب / en iPhone): المقاس، الاتجاه، الهوامش، التحقق (حجب مدخل غير صالح برسالة مترجمة)، المعاينة المحدَّثة. القالب الحراري والأنواع غير المربوطة تُعلَن بلا عناصر قابلة للتعديل.

## 8) المخاطر والمتبقي
1. **لا طابعة فعلية:** الطباعة محاكاة بـ`page.pdf` (يلتزم بـ`@page`)؛ سلوك سائق/ورق حقيقي غير مختبر.
2. **WebKit/Safari غير مثبّت** هنا؛ iPhone = محاكاة Chromium. اختبار الجهاز الحقيقي شرط قبل التفعيل الواسع.
3. **صفحات غير موصولة (تبقى سلوكاً قديماً):** فاتورة المشتريات، سندات القبض/الصرف (خارج النطاق)، ومستندات أخرى؛ المحرر يعلن ذلك ويقفل الحقول لها ولا يَعِد بأثر.
4. اختبار الطباعة على صفحات المنتج الحقيقية (وليس حاضنة `/document-qa`) غير ممكن آلياً هنا؛ المسار نفسه (`printDocument` + `resolveDocumentOutputSpec`) مغطّى بوحدات واختبارات الحاضنة.
5. مواصفات Playwright يدوية (Web CI لا يشغّل Playwright).
6. لا تغيير خلفي: عزل المستأجر والصلاحيات يبقيان كما اختبرهما PR3-A؛ المحرر للقراءة فقط لمن لا يملك صلاحية التعديل (مغطّى بالاختبار الجزئي للمكوّن).
