# استيراد الصور بالجملة — وضع «استبدال الصور الموجودة» (`media_mode=replace`)

**الحالة:** منفَّذ ومختبَر، **بلا دمج ولا نشر**. فرع: `claude/product-image-replacement-import-cq5svp`.

## 1) فحص المعمارية (ما أُعيد استعماله)

| الطبقة | القائم | القرار |
|---|---|---|
| قراءة الأرشيف | `ProductImageArchiveService` (Zip Slip، ضغط، تشفير، تكرار أسماء، فحص كل صورة) | **أُعيد استعماله كما هو** |
| فحص الصورة | `ProductImageInspector` (MIME/امتداد/بكسل/بصمة SHA-256) | كما هو |
| تخزين الصورة | `ProductMediaService::store` (أصل + مشتقات + صف + تنظيف عند الفشل) عبر `DocumentStorageService`/R2 | **أُعيد استعماله** داخل مسار جديد، لا مسار تخزين موازٍ |
| مطابقة الصور بالصفوف | `ProductImportMediaService::archiveSources` (`SKU.ext` رئيسية، `SKU__N.ext` إضافية) | كما هو |
| المهمة الدائمة | `/import-jobs` + `ImportPreviewService` (معاينة مربوطة بالبصمة) + `ProductCatalogImportAdapter::applyChunk` (قطعة = savepoint) | وضع جديد داخل المحوّل نفسه، لا مجال جديد |
| الواجهة | `/products/import` (ملف + أرشيف + معاينة + تأكيد) | اختيار وضع جديد + معاينة استبدال |

لم يُبنَ نظام موازٍ: الإضافة الجديدة هي (أ) `ProductMediaService::replaceProductGallery` و(ب) فرع «استبدال» في `ProductImportMediaService` و(ج) فرع `applyReplacementChunk` في المحوّل.

## 2) السلوك مقابل المتطلبات

| # | المتطلب | التنفيذ |
|---|---|---|
| 1 | إبقاء وضع الإضافة | الافتراضي. مسار `plan()`/`apply()` الأصلي لم يُعدَّل؛ بصمة المعاينات القانونية لم تتغيّر (مفتاحا الاستبدال لا يظهران إلا فيه). اختبارات الإضافة القائمة تمرّ دون تعديل |
| 2 | اختيار «استبدال الصور الموجودة» | مجموعة اختيار (radio) في صندوق الأرشيف بصفحة `/products/import` |
| 3 | SKU داخل المستأجر | المطابقة بـ `Product::query()->where('sku')` (نطاق المستأجر). لا باركود/معرّف/روابط في هذا الوضع. SKU مفقود/مكرر/غير موجود في المؤسسة = خطأ يمنع التنفيذ |
| 4 | `SKU.jpg` و`SKU__2.jpg` | `archiveSources` القائم؛ الرئيسية أولاً (الغلاف) ثم الإضافية بالترتيب |
| 5 | معاينة | منتجات متأثرة، صور تُضاف/تُزال/تبقى، صفوف بلا تغيير، وتفصيل «الحالية مقابل الجديدة» لكل منتج |
| 6 | تأكيد صريح | `confirm_media_replacement` جزء من الخيارات المربوطة بالبصمة؛ غيابه = `needs_approval`، ويفشل الفحص المسبق للتنفيذ قبل أي كتابة |
| 7 | الرفع والتحقق أولاً، والإزالة بعد نجاح البدائل | `replaceProductGallery`: فحص كل الصور → إضافة البدائل → (فشل ⇒ رجوع كامل) → إعادة ترتيب → حذف الصفوف القديمة |
| 8 | لا حذف فعلي لملف مستعمل | الحذف الفعلي بعد الالتزام النهائي (`DB::afterCommit`) وبعد التأكد أن لا صف `product_media` آخر يشير إلى القرص+المسار نفسيهما |
| 9 | لا بيانات منتج/مالية | `applyReplacementChunk` لا يستدعي `ProductImportService`. الاختبار يثبت: الاسم/السعر/التكلفة/التتبع كما هي، لا قيود محاسبية، لا حركات مخزون |
| 10 | فشل جزئي وإعادة محاولة | معاملة فرعية لكل منتج؛ بصمة المحتوى تجعل الإعادة idempotent؛ انقطاع بين الإضافة والإزالة يُستكمل في المحاولة التالية؛ مجاميع تراكمية عبر القطع |
| 11 | اختبارات | `tests/Feature/ProductImageReplacementImportTest.php` (14) + واجهة (7 اختبارات جديدة: عقد النموذج + معاينة الاستبدال) |
| 12 | PR بلا دمج/نشر | يُفتح PR جاهزاً للمراجعة فقط |

## 3) قرارات تصميم يجب أن يعرفها المالك

1. **ملف الجدول ما زال مطلوباً** (عمود SKU فقط يكفي). لأنه يحدّد *نطاق* العملية الهدّامة صراحةً (الصور المطابقة لـ SKU غير المذكور في الجدول لا تُطبَّق)، وهو عقد المهمة الدائمة القائم. استيراد «ZIP وحده» بلا جدول ممكن لاحقاً لكنه مجال/وحدة جديدة تُقرَّر بشكل منفصل.
2. **منتج بلا صورة في الأرشيف لا يُمسّ معرضه إطلاقاً** — لا مسح ولا استبدال بفراغ؛ والمعرض لا يُفرَّغ أبداً (الاستبدال بقائمة فارغة مرفوض في الخدمة).
3. **الاستبدال عبر المهمة الدائمة فقط**: المسار المتزامن `/products/import/apply` يرفضه (422) لأن عملية تُزيل ارتباط صور تستحق معاينة مربوطة وخيارات مجمَّدة واستئنافاً. وتشغيلة الاستبدال لا تدعم «الإصلاح الجزئي بملف مصحَّح» (لا بيانات منتج فيها)؛ تُعاد بالملفين نفسيهما.
4. **نطاق الاستبدال = معرض المنتج المشترك فقط.** صور قيم الخيارات والمتغيّرات (ألوان/مقاسات) لا تُمسّ.
5. **سياسة العمل** ليست إعداد مستأجر: هي اختيار صريح لكل تشغيلة مع تأكيد (قاعدة 6 — لا يوجد معنيان معقولان لحدث واحد هنا؛ الأداة تفعل ما طُلب بالضبط).

## 4) أماكن استعمال الملفات (قاعدة 8)

لا جدول آخر يخزّن مسار/قرص صورة المنتج؛ المراجع إلى `product_media.id` هي `ai_action_execution_images.product_media_id` و`product_option_values.image_media_id` (كلاهما `nullOnDelete`، الأخير يخصّ وسائط قيم الخيارات لا المعرض المشترك). لذلك الحارس المنفَّذ فعلياً هو «لا صف `product_media` آخر على القرص+المسار»؛ إن ظهر مستهلك جديد للمسار الفعلي يضاف إلى `deleteFilesUnlessReferenced`.

## 5) حدود معلنة

- فشل **معاملة القطعة الخارجية** بعد نجاح منتج (حدث غير متوقع) يرجع صفوف قاعدة البيانات، وتبقى ملفات البدائل الجديدة المكتوبة يتيمة في التخزين (السلوك نفسه لوضع الإضافة اليوم)؛ الملفات القديمة لا تُحذف لأن حذفها بعد الالتزام. الإعادة تعيد استعمال بصمات المحتوى فلا تتضاعف الصفوف.
- مصدر الصور هنا الأرشيف فقط؛ أعمدة الروابط في الجدول تُتجاهل في هذا الوضع.
- لا ترحيل بيانات ولا هجرة (لا تغيير مخطط).
