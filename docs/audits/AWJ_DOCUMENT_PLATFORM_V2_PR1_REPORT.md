### التصميم المختصر
- **الضغط:** `compress:true` فقط (Flate بلا فقد). **لا JPEG** — لحماية العربية والشعار وQR والباركود (التجربة: 10.70 → 0.46 MB لصفحة نموذجية؛ `FAST/MEDIUM/SLOW` 0.49/0.54/0.46 ⇒ لا مكسب يبرّر تعقيد الخيارات).
- **التقطيع:** (1) ما تبقّى إن اتّسع (+2px تسامح تقريب) يُؤخذ كاملاً؛ (2) عند الحاجة يُفضَّل أقرب حد آمن يترك ذيلاً ≥ 10% من الصفحة (فتنتقل الإجماليات مع التذييل معاً)، وإلا يُستعمل آخر حد آمن كما كان.
- **قصّ الفراغ الختامي:** لورق الصفحات الثابت فقط (A4/Letter/Legal) بمسح من أسفل الكانفاس حتى أول بكسل غير أبيض (+16px أمان). **الحراري (ارتفاع مفتوح) خارج القصّ** حفاظاً على سلوكه.

### 5.1 ملاحظة TypeScript
`tsc --noEmit` على كامل `web/` يُظهر أخطاء **سابقة الوجود** في ملفات اختبار/e2e غير مرتبطة (مثل `e2e/pos-ui-v3-visual-verify.spec.ts`، `pos/settings/configuration/page.test.tsx`)؛ `next build` (المُشغَّل في Web CI) ينجح. المقياس: **55 خطأ على `main` و55 بعد الـ PR، وصفر منها في ملفات الـ PR** (أصلحتُ خطأ نوع واحداً ظهر في اختباري أثناء العمل).

### 5.2 ما لا يغطيه Web CI
Playwright غير مشغَّل في Web CI (Vitest + build فقط). مواصفة `pdf-export-reliability.spec.ts` يدوية: 
```bash
cd web && PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=<chrome> npx playwright test e2e/pdf-export-reliability.spec.ts --project=desktop
```
الحماية الآلية في CI = `pdf-real-output.test.ts` + `pdf-page-breaks.test.ts` (Node، بلا متصفح).

## 6. المخاطر والمتبقي

| # | البند | الحالة |
|---|---|---|
| 1 | **لا طبقة نص** (بحث/نسخ/وصول/PDF/A-3) | **متبقٍ بالكامل — قرار معماري** (§8). الضغط ليس علاجاً. اختبار `GAP DOC-P0-1` يوثّقه |
| 2 | **Safari/WebKit الحقيقي** | غير مُختبَر. الجوال = محاكاة Chromium (viewport/DPR/touch) فقط؛ لا يثبت سلوك Safari. حد مساحة canvas في iOS (~16.7M بكسل ≈ 4–5 صفحات عند `scale:2`) **خطر مفترض لم يُقَس**: هذا الـ PR لم يغيّر `scale` ولا حجم الكانفاس |
| 3 | قصّ الفراغ الأبيض الختامي | يقرأ `getImageData` للكانفاس (يحتاج كانفاساً غير ملوَّث، وهو شرط `toDataURL` أصلاً). عند أي فشل يرجع للارتفاع الكامل (سلوك قديم). الخطر الوحيد: خلفية ملوّنة تتجاوز البياض إلى حد النهاية (تُعدّ حبراً فلا تُقصّ) |
| 4 | الخلفية البيضاء الفاتحة جداً (≥250/255) تُعدّ «فراغاً» | إن وُجد حبر باهت جداً (>= 250) في ذيل المستند فقد يُقصّ؛ عتبة 250 + هامش أمان 16px. لم يظهر في 14 تصديراً |
| 5 | ذيل أقل من 10% لا يمكن تفاديه | إن لم يوجد حد آمن أبكر يعطي ذيلاً معقولاً يُستعمل آخر حد آمن (سلوك قديم). المحتوى الحقيقي الصغير في صفحة أخيرة مقبول (ليس يتيماً بلا حبر) |
| 6 | **رأس الجدول لا يتكرر** في صفحات PDF اللاحقة (الطباعة تكرره) | **خارج النطاق**، موجود سابقاً (DOC-P1-2 في التدقيق: PDF ≠ طباعة) |
| 7 | الهوامش: PDF الصوري بلا هامش (كما كان) | **لم يتغير** عمداً: توحيد الهوامش جزء من «ملف الإخراج» (المرحلة 2) |
| 8 | **فشل e2e سابق** `document-qa` «مصفوفة متعامدة» | سابق لهذا الـ PR (مثبَت على `main`) — يحتاج إصلاح توقّع الارتفاع في مواصفته، خارج النطاق |

بحسب خطة التدقيق (§10)، بعد دمج هذا الـ PR:

1. **PR2 — ملف الإخراج (Output Profile):** حقل إضافي في تعريف المراجعة (مقاس/اتجاه/هوامش/وضع رول) افتراضه A4 الحالي، ومصدر واحد يشتق منه `@page` وحجم PDF، **ويصلح `@page: 80mm auto` غير الصالح (DOC-P0-2) بعد اختبار جهاز حرارية حقيقية**. هذا يوحّد الهوامش بين المعاينة والطباعة وPDF (DOC-P1-2).
2. **سبايك PDF بطبقة نص (قبل أي محرك):** مقارنة مقاسة — (أ) تحسين الحالي، (ب) طباعة المتصفح إلى PDF، (ج) توحيد مولّد jsPDF المتجه، (د) Chromium خادمي — بمعايير: الحجم، طبقة النص، دقة العربية، حتمية الترقيم، تكلفة التشغيل، وجدوى PDF/A-3 مع REM-24. **هذا الـ PR يوفّر خط الأساس المقاس** (الحجم الآن ≈0.15–0.35 MB/صفحة، الترقيم حتمي) لتلك المقارنة.
3. **اختبار جهاز:** iPhone/Safari حقيقي لمستند ≥ 5 صفحات (حد canvas)، وطابعتان حراريتان 58/80.
4. متابعة منفصلة: إصلاح توقّع `rootHeight` في مواصفة `document-qa` السابقة.

**قرار مطلوب منك:** هل تدمج هذا الـ PR قبل PR2؟ (لا دمج ولا نشر دون موافقتك.)
