# عقد إقرار تحصيل الوردية — مبيعات العدادات ↔ التحصيل حسب طريقة الدفع

> **الحالة:** منفَّذ ومغلق خلف بوابة نشر (`FUEL_SHIFT_COLLECTION_DECLARATION_ENABLED=false`). لا دمج ولا نشر ولا تفعيل دون موافقة صريحة.
> **مستقل عن** `FUEL_SHIFT_CASH_RECEIPTS_ENABLED` (D1/D2/D5): لا يفتحها ولا يتجاوز سياستها ولا يقرأ إعدادها. تبقى مغلقة.
> **تشغيلي فقط:** لا سند قبض، لا فاتورة، لا قيد، لا مدخل خزينة، لا حركة مخزون، ولا مساس بـ`payments`/`fuel_sales`/`fuel_sale_payment_receipts` أو بـZATCA.

## 1. ما أُعيد استعماله وما أُضيف

| المطلوب | المصدر القائم المُعاد استعماله | الجديد |
|---|---|---|
| سعر اللتر الفعّال | `FuelEffectivePriceReadService` ← `FuelStationProductPriceService::resolve()` (محطة ← افتراضي المؤسسة، بلا fallback إلى `Product.sale_price`) | لا شيء |
| تقريب المبلغ | `InvoiceLinePrecision::fromItem()` (half_up مرة واحدة لكل منتج — نفس بيع الوقود الرسمي) | لا شيء |
| طرق الدفع المسموحة للمحطة | إعداد المحطة `fuel_sales_allowed_payment_method_ids` (نشطة + نقد/بنك) — استُخرج من `FuelSaleController::paymentMethods` إلى `FuelStationPaymentMethods` ليستعمله المساران | خدمة صغيرة مشتركة (لا قائمة موازية ولا إنشاء طرق/حسابات) |
| نقد الدرج والعهدة والتسليم | `FuelShiftCashExpectationService::live()` | لا شيء |
| قفل الوردية والنطاق | `FuelShiftService::lockOpenShift` (صار public) + `AuthorizesFuelStationScope` | لا شيء |
| الأحداث والتدقيق | `FuelShiftEvent` (نوعان جديدان: `collection_declared`, `collection_frozen`) | نوعان |
| التخزين | — | جدولان: `fuel_shift_collection_declarations` (واحد لكل وردية) و`fuel_shift_collection_revisions` (append-only) |

## 2. حساب المبيعات (`FuelShiftSalesCalculator`، قراءة فقط)

```
لكل فوهة (نشطة أو لها قراءة في الوردية):  mL = إغلاق − افتتاح
لكل منتج:  المبلغ = round_half_up(mL × سعر اللتر / 1000)       (+ ضريبة المؤسسة الافتراضية إن كان نمط السعر tax_exclusive)
المجموع   = Σ المنتجات   — فقط إن لم توجد أي ثغرة، وإلا amount_minor = null
```

| الحالة | الأثر |
|---|---|
| قراءة افتتاح/إغلاق ناقصة | `missing_reading` ← لا مبلغ (اللترات تُعرض مع `milliliters_complete=false`) |
| إغلاق < افتتاح (شاذة) | `closing_below_opening` ← الفوهة مستبعدة ولا مبلغ |
| لا سعر فعّال / منتج غير فعّال / وحدة غير صالحة | `price_unavailable` / `product_unavailable` ← لا مبلغ |
| نمط ضريبة السعر غير معيَّن | `tax_mode_unset` ← لا مبلغ |
| سعر بدأ أثناء الوردية أو اختلف عند الفتح عن التقييم | `price_changed_during_shift` ← لا مبلغ (لا نوزّع لترات بين سعرين بالتخمين) |
| لا فوهات | `no_nozzles` |

**لا إجمالي جزئي يُقدَّم كإجمالي ولا فرق نهائي من مبيعات غير موثوقة.** النتيجة تقدير تشغيلي من العدادات — ليست فواتير بيع، ولا تتضمن البيع الآجل ولا التسويات غير المسجّلة (مستبعدة افتراضياً وتُعلن في `disclaimers`).

## 3. الإقرار والمطابقة

- **`GET fuel-stations/shifts/{id}/collection`** (`fuel.shift.view`): الطرق الحالية بمعرّفاتها + الإقرار المحفوظ + المبيعات + المطابقة + الدرج. مفتوحة الوردية ⇒ حساب حيّ؛ مغلقة ⇒ اللقطة المجمّدة فقط.
- **`POST fuel-stations/shifts/{id}/collection`** (`fuel.shift.cash_count`): `{idempotency_key, base_revision, lines:[{payment_method_id, amount_minor}]}`.
  - يلزم **كل** طريقة مفعّلة الآن (ولو 0) وبمعرّفها؛ طريقة معطّلة/غير موجودة ⇒ 422 `FUEL_COLLECTION_METHOD_NOT_ALLOWED`؛ طريقة مفعّلة مفقودة ⇒ 422 `FUEL_COLLECTION_METHODS_CHANGED`؛ مبلغ غير صحيح/مكرر ⇒ 422 `FUEL_COLLECTION_INVALID`.
  - الفرق = **المُحصَّل − مبيعات العدادات**؛ موجب = زيادة، سالب = عجز، صفر = مطابق. غير نهائي (`null`) ما لم تكتمل المبيعات.
  - **منع التكرار:** مفتاح idempotency فريد للمؤسسة + بصمة الحمولة: إعادة نفس المفتاح والحمولة ⇒ 200 `replayed` بلا أثر؛ المفتاح لحمولة/وردية أخرى ⇒ 409 `idempotency_conflict`؛ `base_revision` لا يطابق الحالية ⇒ 409 `stale_revision` (+`current_revision`)؛ حمولة مطابقة للمحفوظة بمفتاح جديد ⇒ 200 `unchanged` بلا نسخة جديدة؛ مفتاح قديم يُعاد بعد نسخة أحدث لا يُرجِع الإقرار.
  - يُستبدل الإقرار (نسخة جديدة) ما دامت الوردية مفتوحة، ثم **يُجمَّد عند `close`** داخل المعاملة نفسها (تعيد حساب المبيعات وتحفظ لقطة الدرج). لا إقرار ⇒ الإغلاق كما كان (الإقرار غير مشروط للإغلاق). التجميد **لا يعتمد على البوابة**: إقرار حُفظ والبوابة مفتوحة يُجمَّد عند الإغلاق ولو أُغلقت بعدها (البوابة تحكم الكتابة والعرض فقط).
- **فصل نقد الدرج** (`drawer`): عهدة الافتتاح · المسلَّم للخزنة · النقد المعدود، و«نقد المبيعات الذي يدلّ عليه الدرج» = المعدود − العهدة − وارد غير المبيعات + الصادر (يشمل التسليم) + المصروف (معكوس معادلة المتوقع)، مقابل النقد المُقَرّ به بطرق النقد (`cash_cross_difference_minor`).

## 4. الصلاحيات والتدقيق (D8)

| المورد | الصلاحية |
|---|---|
| قراءة العرض | `fuel.shift.view` + نطاق المحطة (404 موحّد) |
| حفظ الإقرار | `fuel.shift.cash_count` + قفل الوردية + نطاق الفاعل |
| قيم المبيعات/الأسعار/الفرق/نقد الدرج المستنتج | `fuel.sale.view` وإلا `visible:false` (اللترات تبقى ظاهرة) |
| أحداث `collection_*` في الخط الزمني | مفاتيح `sales_minor`/`difference_minor`/`cash_cross_difference_minor` تُحذف عمّن لا يملك `fuel.sale.view` |

كل حفظ فعلي = صف `fuel_shift_collection_revisions` (الفاعل، الوقت، المفتاح، السطور) + حدث `collection_declared`؛ والتجميد = `collection_frozen`.

## 5. الأقفال

الوردية `FOR UPDATE` (نفس `close` وحركات النقد) ← صف الإقرار `FOR UPDATE`. لا قفل مِرساة مستأجر ولا قفل حساب لأن الخدمة لا تُرحّل قيداً؛ فلا تعارض مع ترتيب `collectPayment`/`PaymentReversalService`.

## 6. أثر التغيير على اعتماد المشرف وسجل الورديات المغلقة

- `approve()` و`reviewCashVariance()` **بلا تغيير** (لا يشترط الاعتماد وجود إقرار ولا يتأثر بفرقه).
- تفاصيل الوردية (مشرف/بائع) تعرض الإقرار المجمّد للقراءة فقط عند وجوده؛ الورديات المغلقة قبل التفعيل لا إقرار لها ⇒ «لم يُسجَّل توزيع تحصيل» (لا Backfill).
- حقول `expected_operational_cash_minor`/`cash_variance_minor`/لقطة `fuel_shift_cash_variances` **كما هي** — نقد الوردية المتوقع لا يشمل مبيعات الوقود تحت الأساس الافتراضي، لذا قد يُظهر «زيادة» تساوي نقد المبيعات؛ فرق التقاطع في الدرج يفسّر ذلك.

## 7. قرارات بحاجة إلى المالك (لم تُفرض)

| # | القرار | الوضع الحالي |
|---|---|---|
| Q1 | هل يُشترط حفظ الإقرار قبل إغلاق الوردية؟ (سياسة تُضبط، القاعدة 6) | غير مشروط؛ تحذير في حوار التأكيد فقط |
| Q2 | هل يرى البائع (بلا `fuel.sale.view`) قيمة المبيعات والفرق، أم يبقى العدّ «أعمى» والمراجعة للمشرف؟ (D8 غير محسوم) | أعمى: اللترات فقط |
| Q3 | هل فرق مطابقة التحصيل غير الصفري يمنع الاعتماد أو يطلب ملاحظة؟ | لا يؤثر على الاعتماد |
| Q4 | معالجة البيع الآجل والتسويات غير المسجّلة في المطابقة | مستبعدة ومُعلنة |
| Q5 | تفعيل البوابة على مؤسسة تجريبية بعد اختبار آيفون فعلي | مغلقة |

## 8. التراجع

`down()` يرفض متى وُجد إقرار. الهجرة إضافية بالكامل (جدولان) ولا تمسّ جداول قائمة. إغلاق البوابة يعيد المسارين إلى 404 ويعيد `close` إلى سلوكه السابق حرفياً (الإقرارات المحفوظة تبقى للقراءة التاريخية داخل قاعدة البيانات).
