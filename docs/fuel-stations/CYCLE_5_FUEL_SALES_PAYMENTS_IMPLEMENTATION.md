# Cycle 5 — المبيعات الرسمية لوقود المحطات وسندات القبض

**الحالة:** قيد المراجعة قبل طلب الدمج.
**النطاق:** بيع وقود رسمي، فاتورة Nebrax، صرف مخزون وCOGS دقيقان، وسند قبض مستقل.
**خارج النطاق:** تسعير تعاقدي أو أساطيل أو RFID أو AVI أو محفظة/قسائم أو ائتمان عميل متخصص أو driver forecourt أو تسوية فروق نقد Cycle 4.

> يبقى الشفت في Cycle 4 سجلاً تشغيلياً مستقلاً. لا تتحول قراءة العداد أو حركة نقد الشفت إلى بيع أو دفعة من تلقاء نفسها، ولا يغيّر التحصيل الرسمي حركة نقد الشفت أو فرق نقده.

## العقد المنفذ

ينشئ النظام `FuelSale` أولاً كمسودة. لا تملك المسودة أثراً على المخزون أو الفاتورة أو القيد. عند **finalization**، تقفل الخدمة البيع وتحدد السعر الخادمي الفعال، وتثبت لقطة تسعير، وتنشئ فاتورة Nebrax رسمية، وتصرف كمية الوقود من مخزن المحطة الصريح، وتستهلك `FuelCostBasis` الدقيق، وتثبت قيد COGS عبر محرك الأستاذ. تصبح الفاتورة عندئذٍ ذمة مدينة إلى أن يرحّل المستخدم سند قبض مستقل.

| الحقيقة | المصدر والقاعدة |
|---|---|
| بيع الوقود | `FuelSale` مرقّم ومقفل بعد finalization، يربط المحطة والمخزن والفوهة والخزان والمنتج والشفت الاختياري. |
| السعر | `FuelStationProductPrice` مؤرخ ومدقق، بأولوية **Station Override → Tenant Default → Fail Closed**. |
| سعر غائب | يرفض finalization بالرمز `FUEL_PRICE_NOT_CONFIGURED`؛ لا يوجد fallback إلى `Product.sale_price` أو قائمة أولى أو سعر يرسله العميل. |
| الكمية | قيمة صحيحة بوحدة mL. تعرض الفاتورة وZATCA اللترات كنسبة دقيقة. |
| قيمة السطر | `quantity_mL × price_per_liter_minor ÷ 1000` مع **round-half-up** مرة واحدة عند حد القيمة النقدية، وبلا float. |
| الفاتورة | `InvoiceService` هو محرك الفاتورة وAR وZATCA الرسمي، مع عقد كميات/تسعير نسبي عام في `InvoiceLine`. |
| COGS والمخزون | مخزن المحطة الصريح وحالة `FuelCostBasis` الدقيقة فقط؛ لا `avg_cost` ولا baseline ضمني ولا مخزون سالب صامت. |
| التحصيل | `PaymentService` فقط ينشئ ويرحّل سند قبض مخصصاً للفاتورة. لا ينشئ `FuelSale` قيد قبض بنفسه. |

## التسعير المؤرخ والتدقيق

السعر ليس خاصية متغيرة في `FuelProduct` أو `Product`. يحفظ `FuelStationProductPrice` المنتج والسعر بالهللات لكل لتر ونطاق الفعالية والحالة ومنشئ/معتمد التغيير وسبب التدقيق. لا يعدّل السجل التاريخي؛ إنما تنشأ قاعدة فعالية جديدة. تمنع الخدمة التداخل بين نطاقات السعر في المصدر نفسه، ثم تحل المصدرين بالترتيب المعتمد. تحفظ `FuelSale` والفاتورة البسط والمقام وباقي التقريب وسياسة التقريب، لذلك لا يعيد تغيير سعر لاحق تفسير بيع أو فاتورة سابقة.

يمر **نمط VAT لسعر اللتر** عبر `fuel_price_tax_mode`، وهو إعداد مدقق بأولوية **Tenant Default → Station Override** وبقيمتين حصراً: `tax_inclusive` و`tax_exclusive`. لا تقرر الواجهة النمط ولا يستنتج من `Product.sale_price`. عند غياب إعداد صريح، تستخدم خدمة الإعدادات `tax_inclusive` فقط حين يعرّف onboarding بلد المستأجر بالسعودية؛ أما البلد المجهول أو غير السعودي فيفشل finalization قبل إنشاء أي مستند رسمي حتى يعين المستأجر أو المحطة سياسته صراحةً. تحفظ `FuelSale.fuel_price_tax_mode` اللقطة النهائية، وتحتفظ `Invoice.tax_inclusive` باللقطة المحاسبية المقابلة.

| نمط السعر | ما يمثله `price_per_liter_minor` | سلوك `InvoiceService` |
|---|---|---|
| `tax_inclusive` | السعر النهائي الظاهر للعميل | `tax_inclusive=true`؛ يستخرج VAT من قيمة السطر الرسمية ولا يضيفها مرة ثانية. |
| `tax_exclusive` | سعر الوقود قبل VAT | `tax_inclusive=false`؛ يضيف محرك الفاتورة VAT وفق معدل الضريبة المعتمد. |

| مثال | الحساب الدقيق | القيمة الرسمية |
|---|---:|---:|
| 1,234 mL بسعر 230 هللة/لتر | `1234 × 230 ÷ 1000 = 283.82` هللة | 284 هللة وفق half-up |
| تمثيل ZATCA | الكمية `1.234 L` والسعر `2.30 SAR/L` | قيمة السطر `2.84 SAR` |

## التحصيل وربط الشفت

ينشئ إجراء التحصيل `FuelSalePaymentReceipt` كسجل ربط append-only ومفتاح idempotency، ثم يستدعي `PaymentService` لإنشاء وترحيل سند قبض وتخصيصه بالكامل للفاتورة. تقرأ الخدمة قائمة طرق الدفع المعتمدة للمحطة من `FuelStationSettingsService`؛ القائمة الفارغة fail-closed، ولا تقبل إلا طرق دفع نشطة ومصرحاً بها. يسمح التحصيل الجزئي أو البيع المؤجل فقط عند تفعيل سياسة المحطة/المستأجر الصريحة.

إذا ارتبط البيع بشفت مفتوح وكانت طريقة السند نقدية، يضاف حدث `official_cash_payment_recorded` إلى الشفت **للمقارنة والتدقيق فقط**. لا ينشئ هذا الحدث `FuelShiftCashMovement`، ولا يعدل `expected_operational_cash_minor` أو `cash_variance` أو يعالج فرقاً معلقاً. يبقى ذلك عقد الفصل الملزم من Cycle 4.

## الصلاحيات والوصول

تظل بوابة `fuel_stations.core` التجارية وحارسها الخادمي إلزاميين على كل endpoint. أضيفت صلاحيات `fuel.sale.view` و`fuel.sale.create` و`fuel.sale.finalize` و`fuel.sale.collect` و`fuel.sale.price.manage`. يسجل ترحيل Cycle 5 لقطة قبل/بعد لتوافق الأدوار القائمة التي كانت تملك `fuel_stations.view/manage`، ويمنع rollback إذا عدّل المستأجر الدور لاحقاً حتى لا تمحى منح صالحة بصمت. لا يمنح دور مخصص جديد صلاحية بيع من `fuel_stations.*` ضمنياً.

## واجهات وعقود API

واجهة `/fuel-stations/sales` تعرض المسودة ثم الإنهاء ثم التحصيل كسلسلة ظاهرة للمستخدم. لا تدخل السعر أو الإجمالي في الواجهة؛ يحددها الخادم عند finalization. يعرض حوار التحصيل المتبقي الرسمي وطريقة الدفع، ويصرح نصاً أن سند القبض لا يغير نقد الشفت. توفر API كذلك endpoints للأسعار المؤرخة ولإعدادات طرق دفع المحطة والبيع المؤجل، مع سجلات إعداد مدققة.

## عناصر مؤجلة إلى دورات لاحقة

| العنصر المؤجل | سبب التأجيل |
|---|---|
| تسعير عميل أو عقد أو أسطول | يحتاج طبقة أهلية/تفويض وتسوية فوق سعر المحطة الأساسي. |
| Fuel card وRFID وAVI والتكاملات الطرفية | لا يوجد بعد عقد vendor-neutral موحد أو صلاحية تفويض/settlement مكتملة. |
| إرجاع بيع نهائي واسترداد قبض | يجب أن يمر بإشعار دائن وعكس Payment صريحين؛ لا حذف أو تحرير لـFuelSale المقفل. |
| تسوية نقد الشفت | فرق Cycle 4 يبقى `pending_review` ولا يعالجه Cycle 5 تلقائياً. |
| driver forecourt أو مزود ATG | يظل خارج النطاق قبل دورة التكاملات vendor-neutral. |

## التحقق

تشمل الاختبارات المركزة دقة سطر الفاتورة وround-half-up، وحجم ZATCA النسبي، وتحديد السعر المؤرخ وfail-closed، وfinalization idempotent، وصرف المخزون وCOGS الدقيق، وسند قبض PaymentService، وفصل نقد الشفت، وRBAC/entitlement عبر API، وحارس كتالوج الترقيم. وتغطي سياسة VAT الافتراض السعودي، وoverride المحطة، وعدم إضافة VAT مرتين في السعر الشامل، وإضافة VAT في السعر الحصري، وثبات لقطة البيع والفاتورة بعد تغيير الإعداد، وتكرار سطر نسبي بلا فقد الكمية. تسجل نتائج مجموعة SQLite وPostgreSQL والواجهة الكاملة في قسم التحقق النهائي بطلب الدمج.
