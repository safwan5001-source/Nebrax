# Cycle 4 — الشفت التشغيلي والـForecourt

**الحالة:** جاهز للمراجعة على فرع `fuel-stations-cycle-4-shifts`.

> **قرار النطاق الملزم:** هذا التنفيذ يثبت دورة شفت تشغيلية كاملة، لكنه لا ينشئ محركاً موازياً للمبيعات أو المدفوعات أو الفواتير أو ZATCA. قراءة العداد هنا دليل تشغيلي، وليست `FuelSale`؛ وحركة النقد هنا حركة صندوق تشغيلية، وليست `Payment`.

## 1. الهدف والحدود

يبني Cycle 4 سجلاً مدققاً للشفت من الفتح إلى القفل: النقد الافتتاحي، العاملون، قراءات العداد والخزان، الحركات النقدية الموثقة، العدّ الختامي، فرق النقد التشغيلي، اعتماد المشرف، وطلب التصحيح بعد القفل. يحافظ التصميم صراحةً على الفصل بين **مخزون الدفاتر**، و**الدليل الفيزيائي**، و**دليل ATG**؛ فلا تغيّر قراءة خزان أو قراءة ATG المخزون أو التسوية أو التكلفة.

| داخل Cycle 4 | مؤجل إلى Cycle 5 أو دورة صريحة لاحقة |
|---|---|
| فتح/إغلاق/اعتماد وقفل الشفت | `FuelSale` الرسمي |
| قراءات عدادات واحتساب لترات تشغيلية | `Payment` أو tender نقدي رسمي |
| قراءات خزانات physical وATG كأدلة | فاتورة أو AR أو Revenue أو VAT أو ZATCA |
| حركة نقدية تشغيلية وعدّ نقد | COGS أو خفض مخزون من قراءات العداد |
| فرق نقد `pending_review` وطلب correction | معالجة محاسبية تلقائية لفروق النقد أو الخزان |

## 2. نموذج البيانات والعزل

تضيف الهجرة `000111_create_fuel_shift_operations` نموذج `FuelShift` وسبعة سجلات تابعة: تعيين العامل، قراءة العداد، قراءة الخزان، حركة النقد، فرق النقد، طلب التصحيح، وحدث التدقيق. كل هذه السجلات ترث `BaseModel` وتُصنّف `BranchScoped`، وتُربط بمحطة وفرع المستأجر؛ لذلك لا تظهر شفتات فرع أو مستأجر آخر في الاستعلامات الاعتيادية أو في API.

يستخدم `FuelShift` مولد أرقام Nebrax الموحد عبر `GeneratesDocumentNumbers`، ونطاق الرقم هو الفرع. تمنع الفهارس الفريدة تعدد الشفتات المفتوحة للمحطة نفسها، وتمنع تكرار دليل القراءة أو حركة النقد. تُعاد نتيجة الدليل المتكرر idempotently بدلاً من إنشاء سجل ثانٍ.

| سجل التدقيق | القاعدة |
|---|---|
| قراءة العداد/الخزان | append-only، دليل فريد، ومرحلة `opening` أو `closing` |
| حركة النقد | append-only أثناء الشفت المفتوح فقط؛ لا تقبل حركة صرف أو مصروف يفوق النقد التشغيلي المتاح |
| فرق النقد | صف واحد لكل شفت؛ لا تُسوّى تلقائياً |
| طلب التصحيح | طلب مدقق فقط بعد القفل؛ لا يحرر حقيقة الشفت الأصلية |
| أحداث الشفت | append-only مع الفاعل والحمولة والوقت |

## 3. دورة الحياة التشغيلية

يفتح الشفت لمحطة نشطة في فرع المستخدم، مع منع شفت ثانٍ مفتوح للمحطة. تسجل الخدمة العاملين والقراءات والحركات فقط ما دامت الحالة `open`. عند الإغلاق تحسب كمية العداد التشغيلية من فرق قراءات الفوهات، وتحتفظ بفرق الخزان التشغيلي منفصلاً عن أي reconciliation رسمي. تنتقل الحالة من `open` إلى `closed`، ثم من `closed` إلى `approved` فقط؛ ولا يمكن تعديل السجل المقفل مباشرة.

| الحالة | ما يسمح به | ما يمنع |
|---|---|---|
| `open` | تعيين العاملين، القراءات، الحركات النقدية، الإغلاق | شفت آخر للمحطة نفسها، إدخال رسمي للمبيعات أو المدفوعات |
| `closed` | اعتماد المشرف أو طلب correction | إضافة دليل أو تعديل النقد/القراءات |
| `approved` | طلب correction مدقق فقط | أي تغيير مباشر للشفت أو سجلاته التابعة |

تقرأ الخدمة إعدادات المحطة من `FuelStationSettingsService` وحدها، مع توريث المستأجر ثم override المحطة. تشمل السياسات إلزام قراءات الفتح/الإغلاق، النقد الافتتاحي، طاقم الشفت، عدّ النقد، اعتماد المشرف، السماح بإغلاق فرق النقد المعلق، وحدود تفاوت العداد والخزان. إن فُعلت سياسة منع فرق الخزان التشغيلي غير المحلول، يُرفض الإغلاق بوضوح، من دون تسوية مخزون ضمنية.

## 4. النقد والآثار المحاسبية

النقد المتوقع داخل هذا النطاق يساوي النقد الافتتاحي زائد `cash_in` ناقص `cash_out` و`expense` الموثقة. لا تدخل مبيعات أو دفعات أو أي tender رسمي في هذه المعادلة، لأنها ليست موجودة في Cycle 4. ينتج الفرق الصفري `not_required`، بينما ينتج الفرق غير الصفري `pending_review` ويظل محفوظاً حتى المراجعة المستقبلية. تسمح صلاحية المراجعة المنفصلة بتسجيل المراجع وملاحظته مرة واحدة في سجل التدقيق، لكنها **لا تغيّر** الحالة أو مبلغ الفرق ولا تنشئ تسوية أو قيداً أو حركة مخزون.

| العملية في Cycle 4 | JournalEntry | StockMovement | أثر مالي تلقائي |
|---|---:|---:|---|
| فتح الشفت | لا | لا | لا |
| قراءة عداد أو خزان أو ATG | لا | لا | لا |
| حركة نقدية تشغيلية | لا | لا | لا |
| إغلاق بفرق نقد صفري أو غير صفري | لا | لا | لا |
| اعتماد وقفل الشفت | لا | لا | لا |
| مراجعة فرق نقد معلّق | لا | لا | لا |
| طلب correction | لا | لا | لا |

> لا يستخدم Cycle 4 حساب 5180، ولا حساب عجز/زيادة نقد، ولا fallback محاسبي، ولا `LedgerService`، لأن قرار النطاق يلزم بـ **اكتشاف الفرق وحفظه ومراجعته** لا تسويته أو ترحيله تلقائياً.

## 5. RBAC والتوافق الرجعي

تضاف صلاحيات `fuel.shift.view` و`fuel.shift.open` و`fuel.shift.close` و`fuel.shift.approve` و`fuel.shift.correct` و`fuel.shift.cash_count` و`fuel.shift.cash_variance_review` إلى كتالوج RBAC. تفرض المسارات الصلاحية الدقيقة من الخادم إلى جانب الحارس التجاري `fuel_stations.core`.

تعالج الهجرة الأدوار القائمة عند تنفيذها: يأخذ الدور الذي يملك `fuel_stations.view` صلاحية عرض الشفت، ويأخذ الدور الذي يملك `fuel_stations.manage` صلاحيات الشفت الإدارية المكافئة. تخزن الهجرة لقطة before/after لكل دور تم تعديله كي تعيد rollback الآمن فقط عندما لم يغير المستأجر الدور لاحقاً؛ وترفض rollback الذي قد يمحو تعديل صلاحية لاحقاً. لا تمنح الأدوار المخصصة الجديدة أي صلاحية شفت ضمنية: يجب اختيار `fuel.shift.*` صراحةً.

## 6. API والواجهة

يوفر API قائمة وعرضاً وإجراءات فتح الشفت، تعيين العامل، قراءات العداد والخزان، الحركة النقدية، الإغلاق، مراجعة فرق النقد، الاعتماد، وطلب التصحيح.
 تستعمل جميع الكتابات `FormRequest` مخصصاً، ويعيد المورد حقائق تشغيلية صريحة مثل `operational_liters` و`expected_operational_cash_minor` و`cash_variance` من دون إعادة تسميتها بيعاً أو تحصيلاً.

تضيف الواجهة المسار `/fuel-stations/shifts` وربطه من مساحة عمل المحطات. تعرض صفحة RTL الجداول والملخصات وحالات التحميل والفراغ والخطأ وحوارات الفتح والقراءة والحركة النقدية والإغلاق والاعتماد وسجل التدقيق. تُعطّل إجراءات الشفت عندما لا يملك المستخدم الصلاحية، وتشرح سبب الإجراء والحدود قبل الإرسال.

## 7. عقد Cycle 5

أي دورة تضيف مبيعات وقود أو مدفوعات رسمية يجب أن تبقى منفصلة عن سجلات Cycle 4. يمكنها الرجوع إلى الشفت كـcontext تشغيلي ومدخل للتقارير، لكنها لا يجوز أن تعيد تفسير `operational_liters` كمبيعات أو `cash_movements` كمدفوعات. يجب أن تملك Cycle 5 مصادرها الرسمية الخاصة للفواتير/المبيعات/الدفعات وضرائبها وتكلفتها وحركات مخزونها، وتحدد بقرار صريح متى وكيف تقارن تلك الحقائق الرسمية بنتائج الشفت التشغيلية.

## 8. التحقق المنفذ أثناء التطوير

غطت اختبارات الخدمة lifecycle، منع شفتين مفتوحين للمحطة، عزل المستأجر والفرع، الدليل idempotency، عدّ النقد، فرق النقد المعلق، منع القيد أو حركة المخزون، سياسات الإغلاق، اعتماد المشرف، القفل، وطلبات التصحيح. يغطي اختبار API الاستحقاق التجاري وRBAC الدقيق والعقد التشغيلي والاستجابة. اكتملت المجموعة الكاملة بنتيجة **1303 passed / 7632 assertions مع اختبار واحد متخطى** على SQLite، وبنتيجة **1304 passed / 7634 assertions** على PostgreSQL. كما نجحت اختبارات الواجهة **38 files / 169 tests** وبناء Next.js.
