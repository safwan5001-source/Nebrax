## 2. التعارض (C-1) — ما الذي يحدث فعلاً

`FuelShiftSettlementPreviewService::build` و`FuelShiftSettlementEvaluator::evaluate` يحسبان لكل فوهة:

```
residual = metered − erp          // erp = مبيعات A النهائية فقط
```

سند التعبئة (B) **لا يدخل `erp`**. النتيجة تحت `post_on_close` لفوهة سُجِّلت عليها تعبئة صهريج:

1. لترات التعبئة تبقى داخل `residual` ⇒ التسوية تُنشئ لها **فاتورة بيع آجلة للعميل النقدي** ⇒ تُعامَل التعبئة **كبيع** (يخالف القرار التشغيلي المعتمد: لا فاتورة/إيراد/ضريبة/ذمة تلقائياً عند التعبئة).
2. التسوية تخصم المخزون والمجمّع وتقيّد COGS لتلك اللترات.
3. ثم ترحيل سند التعبئة (B) يخصم **الكمية نفسها** مرة ثانية من المخزن والمجمّع ويقيّد مدين الوسيط/دائن المخزون ⇒ **خصم مزدوج**: رصيد المخزن والمجمّع ينقصان ضعف اللترات، و1140 ينقص مرتين.

الوضع الحالي المحجوب (PR-6B-0 → 6B-3/4): مانع `settlement_mode_conflict` يمنع ترحيل **أي** سند في محطة وضعها المخزَّن `post_on_close`، ويمنع عكسه. هو حاجز مؤقت كلّي لا يعالج السبب؛ ولا يغطي سيناريو التسوية التي **سبقت** الترحيل (تسوية تعمل ثم تبقى التعبئات المعلّقة).

مسارات تكرار أخرى فُحصت:

| السيناريو | الحكم |
|---|---|
| A + B على اللترات نفسها | لا يتقاطعان: كل لتر يُسجَّل إما بيعاً (فوهة+قراءة) أو سند تعبئة؛ لكن **لا فحص** أن مجموعهما ≤ قراءة العدّاد. ⇒ يُعالَج بالمطابقة (§4). |
| C بعد B (ترحيل التعبئة قبل التسوية) | خصم مزدوج بسبب المعادلة أعلاه. |
| C ثم B | نفس الأثر. |
| إلغاء سند أثناء وردية مفتوحة | آمن: `recorded → voided` قبل أي ترحيل، والإغلاق يقفل الوردية `FOR UPDATE` فتتسلسل مع قفل `FOR SHARE` للتعبئة؛ بعد الإغلاق لا إلغاء ولا تسجيل ⇒ **مجموعة التعبئات ثابتة عند الإغلاق**. |
| عكس سند مرحَّل بعد تسوية | يعيد المخزون بينما اللترات خرجت فعلاً من العدّاد ⇒ فرق مادي غير مفسَّر **[قرار مالك]** — يبقى العكس محجوباً تحت `post_on_close`. |

## 3. خطة الإصلاح (ما يُنفَّذ، وما يُرفع)

**قاعدة وحيدة:** كل لتر خرج من الفوهة يُخصم **مرة واحدة فقط**، من المسار الذي سُجِّل به. لترات سندات التعبئة تُخصم بترحيل السند (B) حصراً، فلا تدخل بقية التسوية (C) أبداً.

1. **استبعاد لترات التعبئة من بقية التسوية** (إصلاح الجذر، يعمل دائماً بلا علم لأنه سلامة لا ميزة): `residual = metered − erp − tanker` حيث `tanker` = مجموع سندات الفوهة والوردية بحالة `recorded` (الملغاة مستبعدة). مصدر واحد مشترك `FuelShiftNozzleLiters` للمعاينة والمُقيِّم والمطابقة. الأسطر تحمل `tanker_milliliters`، وبصمة المعاينة تتضمنه **حين يكون > 0 فقط** (لا تتغيّر بصمة وردية بلا تعبئات).
   - `residual < 0` ⇒ المانع القائم `FUEL_SETTLEMENT_ERP_EXCEEDS_METER` (المسجَّل بيعاً + تعبئة يتجاوز العدّاد).
   - لا يلمس أي فاتورة أو قيد قائم.
2. **وسم التسوية الجديدة** `policy_snapshot.tanker_exclusion = true` وعمود `fuel_shift_settlement_lines.tanker_milliliters` (nullable؛ `NULL` = تسوية سابقة لهذا التعديل **لم تستبعد** التعبئات). لا Backfill ولا تعديل لتسوية مرحَّلة.
3. **مانع دقيق بدل المانع الكلّي** عند ترحيل السند: يُرفع `settlement_mode_conflict` الكلّي، ويحلّ محله `settlement_covers_fill` — يُحجب الترحيل **فقط** إن وُجدت تسوية مرحَّلة لوردية السند **لم تستبعد** التعبئات (سطر الفوهة `tanker_milliliters IS NULL`). تسوية لاحقة (جديدة) تستبعدها تلقائياً، فلا ازدواج. الفحص يُعاد داخل معاملة الترحيل تحت أقفالها.
4. **بقاء حجب العكس تحت `post_on_close`** كما هو **[قرار مالك D-8-1]**: عكس سند مرحَّل بعد تسوية يعيد المخزون بلا تفسير مادي.
5. **المطابقة عند الإغلاق** (خلف بوابة نشر جديدة مغلقة `FUEL_SHIFT_METER_RECONCILIATION_ENABLED`): لكل فوهة تُجمَّد لقطة `M, D, T, U` وحالتها، والمطابقة **لا تنشئ أثراً مالياً أو مخزنياً**.
6. **تصنيف الفروق ومراجعتها** بالصلاحية `fuel.shift.meter_variance_review` (محجوزة منذ PR-3، owner/admin عبر `*`): سجل مراجعة ثابت لكل فرق، **تصنيف وصفي فقط بلا أي أثر محاسبي**، وهو شرط للاعتماد (البوابة مفتوحة فقط).
7. **التاريخي محفوظ:** لا تعديل لقراءات أو قيود أو تسويات مرحَّلة؛ اللقطات والمراجعات إلحاقية بحراس قاعدة بيانات.

## 4. المطابقة — التعريفات

لكل فوهة في وردية مغلقة:

```
M = إغلاق − افتتاح                      (mL، من قراءات العدّاد)
D = Σ مبيعات مباشرة نهائية (status=finalized, source=station)
T = Σ سندات تعبئة بحالة recorded
U = M − D − T                           (غير مفسَّر)
```

| الحالة | الشرط |
|---|---|
| `incomplete` | قراءة افتتاح/إغلاق ناقصة، أو إغلاق < افتتاح (قراءة خاطئة، لا يُحسب U) |
| `balanced` | U = 0 |
| `within_tolerance` | 0 < |U| ≤ `shift_meter_tolerance_milliliters` (الإعداد القائم، الافتراضي 0) |
| `variance` | |U| > التفاوت — **U > 0** لترات خرجت بلا تسجيل؛ **U < 0** المسجَّل أكثر من العدّاد (بيع+تعبئة > القراءة) |

- مبيعات بحالة `draft` لا تُحسب في D وتُعرض معلومة منفصلة `draft_sale_milliliters`.
- الصرف الداخلي (D في §1) غير مبني ⇒ صفر، ويُعلَن في `not_checked`.
- **لا تفاوت مخترع**: يُعاد استعمال `shift_meter_tolerance_milliliters` (كان مسجَّلاً بلا مستهلك).
