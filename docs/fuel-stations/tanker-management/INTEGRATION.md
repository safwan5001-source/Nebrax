# التكامل المعماري | ERP + تطبيق محطات الوقود
**الحالة:** عقد تكامل وظيفي مبدئي؛ تفاصيل API والجداول لا تعتمد إلا بعد فحص الشيفرة.

## المصدر الرسمي لكل مجال
- Master data: المستأجر، المحطة، المضخات، الفوهات، الخزانات، المنتج، الموظفون، الأدوار، العميل.
- تطبيق المحطات: إدخال التعبئة، الوردية، القراءات، طلب سند التسليم وعرض حالته.
- خدمات AWJ: تحقق الصلاحيات، التحقق من الرصيد/الخزان والقراءات، حركات المخزون، الترقيم، حفظ السندات، دفتر المسحوبات والتسوية.
- مبيعات AWJ: إنشاء الفواتير الضريبية وإشعاراتها بحسب الخدمات المعتمدة.
- مالية AWJ: السداد، المطابقة، المستحقات وتسوية المدفوعات.
- التقارير: قراءة أحداث وخدمات المصدر، لا قاعدة بيانات مالية ثانية داخل التطبيق.

## حدود المستأجر
tenant_id يحدد كل قراءة وكتابة وربط على طبقة الخدمة وقاعدة البيانات؛ منع معرفات عميل/صهريج/مضخة من مستأجر آخر حتى لو عُرفت IDs. تعيين صلاحيات المحطة والفرع والموظف بالإضافة للمستأجر.

## سلامة التشغيل
- idempotency key للعمليات القادمة من الجوال ومقاومة الإرسال المتكرر.
- atomic transaction لحفظ سند التعبئة والحركة المرتبطة به عندما تتيح البنية ذلك، أو آلية موثوقة للتعافي.
- سجل تدقيق: منفذ العملية، وقتها، الورديّة، التعديل، الإلغاء، التحقق من قراءة العداد.
- منع تعديل سند معتمد دون مسار تصحيح/إلغاء مضبوط.
- خطة واضحة للتعامل مع العمل دون شبكة وعدم مزامنة بيانات مالية مرتين.
- لا تُفترض أسماء APIs أو جداول جديدة قبل تقرير الاكتشاف.

## واجهات الجوال / RTL
اختيار سريع للمضخة والفوهة وصاحب الصهريج، تأكيد كمية التعبئة والسند، حالات اتصال واضحة، كشف مسحوبات مختصر، صلاحيات PIN/تبديل المستخدم وفق آليات المحطة الحالية.

## حدود تتبع مخزون الصهاريج
- مخزون **الخزان في المحطة فقط** داخل نطاق التتبع التشغيلي الحالي؛ لا خزانات أو مستودعات صهاريج افتراضية لأصحاب الصهاريج.
- مصدر صرف المخزون هو واقعة تعبئة الوقود؛ سند التعبئة والفاتورة اللاحقة يحتفظان بمراجع مناسبة تمنع خصم المخزون مرتين.
- وحدة المبيعات تستخدم المنتج المخزني الرسمي القائم، مع مسار «فاتورة لكمية سبق صرفها» إذا كانت بنية AWJ تدعمه أو بعد تطويره؛ لا يُنشأ صنف ديزل غير مخزني بديل تلقائيًا.

## إدخال الموظف اليدوي وسندات الورق
- لا يُفترض وجود جهاز تحكم أو API للمضخات: كمية التعبئة تأتي من **إدخال الموظف اليدوي** بناءً على شاشة المضخة، والقراءات التراكمية تُدخل يدويًا أثناء إجراءات الوردية.
- واجهة التطبيق: اختيار صاحب الصهريج، المضخة، الفوهة، كمية اللترات، رقم السند الورقي، التقاط صورة بكاميرا الآيفون أو إرفاق ملف، ثم مراجعة وحفظ التعبئة.
- يولد الخادم معرف/رقم عملية إلكترونيًا، ويخزن رقم السند الورقي منفصلًا؛ يتم التحقق من تكرار السند وفق سياسة نطاق الترقيم التي يحددها التصميم.
- تخزين المرفقات في خدمة ملفات آمنة تابعة للمستأجر، بروابط وصول مصرح بها، وتوثيق المستخدم وتوقيت الإرفاق دون تعديل تاريخ التعبئة.
- لوحة الإغلاق تجمع كميات التعبئات **لكل فوهة** وتقارنها بفارق قراءة عداد نهاية الوردية وبدايتها. لا تعتمد التسويات المخزنية تلقائيًا بسبب الفرق.
- مطابقة معاملات حفظ التعبئة/المرفق مع الصلاحيات والـ idempotency، ورفض الكميات السالبة/الصفرية والقراءات غير المنطقية وفق قواعد معتمدة.
