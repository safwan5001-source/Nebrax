# TANKER-PR4 — سندات تعبئة الصهاريج (تقرير التنفيذ)

**الحالة:** جاهز للمراجعة — لا دمج ولا نشر من هذا الـPR، ولا تغيير لإعدادات Railway أو Feature Flags. **البوابة الجديدة مغلقة افتراضياً** (`FUEL_TANKER_FILLS_ENABLED`) وهي **منفصلة** عن بوابة PR-1 المفعّلة؛ لا تُفتح دون قرارك.
**النطاق:** سجل تشغيلي لكل تعبئة صهريج. **لا خصم مخزون، ولا حركة مخزون، ولا قيد، ولا فاتورة، ولا تحصيل، ولا عمولة، ولا مخزون داخلي للصهريج.** مسار البيع المباشر لم يُمسّ. المرحلة: Beta/Development.

## ما نُفّذ
| البند | التفصيل |
|---|---|
| الجدول | `fuel_tanker_fills` (هجرة إضافية واحدة، لا Backfill، لا تعديل لجدول قائم). `BranchScoped`، يرث `BaseModel` (عزل المستأجر). |
| الخدمة | `FuelTankerFillService` — **الكاتب الوحيد**: `record()` (تسجيل/إعادة) و`void()` (إلغاء). لا تستدعي أي خدمة مخزون أو قيد أو فاتورة أو دفع. |
| الـAPI | `GET fuel-stations/tanker-fills` (مرشّحات: محطة، وردية، صاحب صهريج، صهريج، فوهة، حالة، رقم سند، فترة؛ ترقيم) · `GET …/{id}` · `POST …` (تسجيل) · `POST …/{id}/void` (إلغاء بسبب). |
| البوابة | `FUEL_TANKER_FILLS_ENABLED` (`fuel_stations.tanker_fills_enabled`، **false**) بعد بوابة PR-1: مغلقةً ⇒ 404 موحَّد قبل أي صلاحية. |
| الصلاحيات | `fuel.tanker.fill.view|record|void` — owner/admin عبر `*` فقط؛ لا `MATRIX` ولا قالب موظف ولا دور مخزَّن. جلسة PIN لا تصل المسارات (لا واجهة تشغيلية لموظف المحطة). |
| الترقيم | `FTF-YYYY-00001` في `DocumentNumberingCatalog` (يظهر في إعدادات الترقيم بتسمية ar/en). |
| وثائق وويب | قسم `CLAUDE.md`، تسميات الصلاحيات (`perm_areas.fill`) وكيان الترقيم ar/en. **لا شاشة جديدة.** |

## القرارات المطبَّقة (من تعليمات المالك وPR-3)
1. **التعبئة من مضخة وفوهة فعليتين:** تُحلّان من الفوهة (المضخة والخزان والمنتج مشتقة)، وتُفحص ملكيتها للمحطة وحالتها (نشطة)، وتطابق منتج الفوهة والخزان وأي منتج مُرسَل، ووحدة mL/L.
2. **صاحب الصهريج إلزامي دائماً، والصهريج اختياري وفق `tanker_selection_required`** (الافتراضي اختياري). صهريج لا يتبع الصاحب أو غير نشط مرفوض.
3. **السند الورقي مستقل عن FTF:** حقلان منفصلان في الجدول والـAPI والتدقيق.
4. **منع تكرار السند:** على مستوى المحطة افتراضياً (`tanker_voucher_unique_scope`)، ويتعارض السند إذا غطّى نطاق **الكاتب** السجل القائم **أو** غطّى نطاق **السجل القائم** الكاتب (فلا يتوقف الحكم على ترتيب التسجيل ولا على اختلاف سياسات المحطات)، ويُسلسَل السند نفسه داخل المؤسسة بقفل استشاري على PostgreSQL، **الأصفار البادئة محفوظة** (`04052` و`4052` سندان مختلفان)، **السند الملغى يبقى محجوزاً** (الصف لا يُحذف أبداً، مُشغّل قاعدة بيانات).
5. **سعة الصهريج:** `allow_with_confirmation` (الافتراضي): 422 `capacity_overrun_confirmation_required` بتفاصيل السعة/الكمية/التجاوز حتى يصل `confirm_capacity_overrun: true`، ثم يُسجَّل المنفّذ والوقت؛ `block` يرفض حتى مع التأكيد؛ `allow` يسجّل التجاوز بلا تأكيد. السعة غير المحددة (NULL) لا تُقارَن (لا حدّ مخترع). تُحفظ لقطة السياسات المطبَّقة.
6. **قيد `allowed_operations`:** فوهة لا تشمل `tanker_fill` ⇒ 422 `nozzle_operation_not_allowed`. **البيع المباشر لا يتأثر** (كما اعتمدت: يشمله القيد عند التكامل لاحقاً).
7. **الوردية الموحَّدة:** تُربط بالوردية المفتوحة الوحيدة للمحطة؛ لا تعبئة بلا وردية مفتوحة (`shift_required`)، ولا تُنشأ وردية؛ وردية مرسَلة تخالف المفتوحة مرفوضة.
8. **الكمية:** `quantity_liters` (نص أو عدد بثلاث منازل) أو `quantity_milliliters` (صحيح) — واحد فقط؛ تخزين mL صحيح؛ صفر/سالب/أكثر من 3 منازل/كسر مفقود الدقة ⇒ 422.
9. **Idempotency:** `idempotency_key` إلزامي (فريد للمؤسسة). الإعادة بالمفتاح نفسه تعيد السجل الأول (200، `meta.replayed`) حتى بعد إغلاق الوردية؛ اختلاف المحتوى ⇒ 409 `idempotency_key_reused` (بصمة SHA-256 لنية الطلب؛ علم التأكيد لا يدخلها).
10. **التدقيق:** `tanker_fill.recorded|voided` في `fuel_station_audit_events` بالفاعل والمحطة والفوهة والوردية؛ والسجل نفسه يحفظ `recorded_by`/`recorded_at` (ساعة الخادم وحدها) و`voided_by/at/reason`.
11. **لا شركة مستفيدة مطلوبة:** لا حقل ولا قبول لـ`partner_id`.

## الأمان والعزل
- المستأجر من الجلسة وحدها؛ `tenant_id` و`branch_id` وأي مفتاح غير معلن ⇒ 422. محطة خارج فرع/مخزن/إسناد المستخدم أو من مؤسسة أخرى ⇒ 404 موحَّد قبل أي أثر. سجل مؤسسة أخرى لا يُرى ولا يُلغى.
- صلاحية مستقلة لكل فعل (عرض/تسجيل/إلغاء)، والخدمة تعيد فحص الصلاحية (دفاع في العمق). مفتاح المنع يُرفض كاملاً دون كشف سجلات خارج النطاق.

## الأقفال والتزامن
ترتيب الأقفال (`FUEL-LOCK-ORDER`): المحطة `FOR NO KEY UPDATE` ← الفوهة `FOR SHARE` ← المضخة/الخزان `FOR KEY SHARE` ← الوردية `FOR SHARE` ← صاحب الصهريج/الصهريج `FOR SHARE` ← مِرساة الترقيم ← الإدراج.
قفل المحطة يسلسل تعبئات المحطة (فلا يُسجَّل السند نفسه مرتين تزامنياً)، والفهرس الفريد خط الدفاع للنطاقات الأوسع. قفل الوردية `FOR SHARE` يتعارض مع `FOR UPDATE` للإغلاق: **لا تعبئة تُسجَّل بعد لحظة الإغلاق**.

## النشر والتراجع
- هجرة إضافية واحدة (جدول جديد + مُشغّلات/قيود قاعدة بيانات). البوابة مغلقة فلا يظهر شيء لأي مؤسسة ولا يتغيّر أي سلوك. تفعيل لاحق = متغيّر بيئة `FUEL_TANKER_FILLS_ENABLED=true` بقرارك المنفصل.
- التراجع: `down()` يرفض متى وُجد أي سند (لا حذف لبيانات). بلا بيانات يُسقط الجدول والدوال.
- **توصية قبل التفعيل:** (1) Safari آيفون الفعلي للشاشات التي ستُبنى لاحقاً، (2) قرار PR-6 المحاسبي كي لا تتراكم سندات بلا خصم مخزني، (3) قرار نطاق منع التكرار النهائي لكل مؤسسة (الافتراضي: المحطة).
