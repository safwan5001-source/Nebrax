# AWJ Fuel Stations — Help Center V1 (تقرير الفحص المعماري والتسليم)

> **النطاق:** مركز مساعدة تشغيلي واحد لوحدة محطات الوقود، يُعرض داخل تطبيق «محطات أَوْج» المستقل وداخل وحدة المحطات في ERP بمحتوى واحد.
> **خارج النطاق (بقرار المهمة):** المساعد الذكي. لا تغيير في منطق الورديات/المبيعات/المخزون/المحاسبة، ولا هجرة، ولا API جديد، ولا نشر.

## 1. تقرير الفحص المعماري

### 1.1 ما وُجد
| العنصر | الحالة قبل V1 | القرار |
|---|---|---|
| مركز مساعدة أَوْج العام | موجود: محتوى ثنائي اللغة في `web/src/modules/help-center/content.ts` (17 مقالاً)، صفحات `/help` و`/help/[slug]` داخل `(app)`، بحث عربي (`normalizeHelpSearch`)، ورقة سياقية `ContextualHelpTrigger` في `Topbar`، رسائل `helpCenter` | **يُعاد استعماله ولا يُستبدل**: نفس نمط المحتوى (`LocalizedText` ar/en)، نفس تطبيع البحث، نفس مكوّن `Sheet`، نفس رسائل `helpCenter` للنصوص المشتركة. لم يُعدَّل شيء منه. |
| غلاف وحدة المحطات (ERP) | `FuelWorkspaceShell` مستقل (لا `Topbar` العام)، فلا يظهر فيه زر المساعدة العام ولا يصله `/help` ضمن سياقه | يُضاف رابط «مركز المساعدة» في قائمة الوحدة وزر «؟» سياقي في رأس الغلاف |
| تطبيق المحطات `/fuel-stations/ops/**` | غلاف جوال بتنقل سفلي، جلسة PIN مقيَّدة، **قاعدة «التطبيق وحده»** (`app-only.test.ts`): لا روابط خارج `/fuel-stations/ops` | المساعدة مسارات داخل التطبيق نفسه (`/fuel-stations/ops/help`)؛ لا يصلح `/help` العام لأنه تحت `(app)` ويتطلب جلسة ERP كاملة ولا تفتحه جلسة PIN |

### 1.2 قرارات التصميم
1. **مصدر محتوى واحد:** `web/src/modules/help-center/fuel/` (محتوى ثابت، بلا قاعدة بيانات، بلا ارتباط بمستأجر). التطبيق وERP يستوردان الملفات نفسها؛ ما يختلف هو الروابط التي يعرضها كل سطح.
2. **لا نظام موازٍ:** استُخدم `helpLocale`/`normalizeHelpSearch`/`Sheet` القائمة. أُضيف محرك بحث صغير للوقود لأن بنية الدليل أغنى من مقال ERP العام (حقول، مشكلات، صلاحيات)؛ لم يُنسخ `HELP_ARTICLES` ولم يُعدَّل `searchHelpArticles` حتى لا تتأثر مقالات ERP الـ17 واختباراتها.
3. **نموذج الدليل** (`types.ts`): وصف الوظيفة (`overview`)، الصلاحيات (مفاتيح + تسمية)، إجراءات مرقَّمة (`procedures`)، شرح الحقول والأزرار (`fields`)، الأخطاء وحلولها (`problems`)، ملاحظات، **`unavailable`** (وظائف غير متاحة موثَّقة صراحةً)، الشاشات المرتبطة (`appHref`/`erpHref`)، الفئة المستهدفة، وسطح التنفيذ (`app|erp|both`).
4. **عزل الروابط بين السطحين:** في التطبيق تُعرض روابط `appHref` فقط (قاعدة «التطبيق وحده» تُحرس باختبار يُصيّر كل دليل ويفحص كل `href`). في ERP تُعرض روابط `erpHref`، وروابط التطبيق تظهر معلَّمة «فتح في تطبيق المحطات».
5. **المساعدة السياقية:** `modules/help-center/fuel/context.ts` مصدر الربط الوحيد (شاشة ← دليل)؛ المكوّنات بلا شروط مسارات. شاشة بلا دليل (عقود الشركات، AVI/RFID، الأجهزة) يوجّه زرها إلى المركز بدل اختلاق شرح.
6. **الدليل التفاعلي:** `FuelHelpGuidePlayer` خطوة واحدة على الشاشة بخط كبير وأزرار 48px وشريط تقدم؛ لا يخزّن ولا يكتب ولا ينفّذ عملية نيابةً عن المستخدم.
7. **الصلاحيات صدقاً:** كل مفتاح مذكور في دليل له تسمية، ويتحقق اختبار من وجوده في `app/Support/Rbac.php` (لا مفتاح مخترع)، ومن أن كل تسمية مستعملة.
8. **لا وظيفة تشغيلية:** المركز لا يستدعي الـAPI إطلاقاً (يحرسه اختبار المتصفح: لا طلب غير GET ولا طلب خاص بالمساعدة).

#### 1.3 ما لم يُفعل عمداً
- لا ترجمة لمحتوى المساعدة خارج العربية/الإنجليزية (مطابق لنطاق المهمة).
- لم تُربط مقالات الوقود بمركز `/help` العام: مستأجر بلا تطبيق المحطات سيرى أدلة لا تخصه. قرار منفصل (انظر §6).

## 5. AWJ Smart Guide — المرشد الذكي (تطبيق المحطات فقط)

### 5.1 تقييم Driver.js مقابل بناء محرك خفيف
| المعيار | Driver.js | محرك مخصَّص (المعتمد) |
|---|---|---|
| تبعية جديدة | نعم (حزمة + قفل) | لا (≈ 600 سطر، بلا تبعية) |
| RTL/LTR | غير مدعوم أصلاً (يلزم تعويض CSS) | منطقي أصلاً (`start/end`، أسهم تنقلب) |
| بطاقة بهوية أَوْج (رموز `--primary`/`--fo-*`، سفلية على الجوال فوق التنقل) | تخصيص عبر CSS/`onPopoverRender` ومحاربة أنماطه | مباشر |
| عدم تعطيل التشغيل | يضع طبقة تلتقط اللمس افتراضياً (يلزم تعطيلها) | `pointer-events: none` أصلاً |
| صلاحيات + عنصر مخفي/غائب | خطوات ثابتة؛ المنطق خارجه | الخطة تُبنى وقت التشغيل من الصلاحيات و**DOM الظاهر** |
| إمكانية الوصول (تركيز، `aria-live`، Esc، تقليل حركة) | جزئي | مدمجة ومختبرة |
| سلسلة التوريد | تبعية خارجية في تطبيق مالي | لا شيء جديد |
**القرار:** محرك مخصَّص. لا يُعاد النظر إلا إن ظهرت حاجة لما لا يغطيه (مثل جولات متعددة الصفحات تلقائياً).

### 5.2 البنية (`web/src/modules/station-ops/guide/`)
`tours.ts` (تعريف بيانات الجولات + محدِّدات العناصر) · `plan.ts` (خطة وقت التشغيل: صلاحيات ثم عناصر ظاهرة) · `guide-overlay.tsx` (Spotlight + تعتيم + بطاقة + حركة) · `guide-context.tsx` (المزوّد: الجولة النشطة، البدء التلقائي، التقدّم) · `progress.ts` (تخزين لكل مؤسسة/مستخدم) · `tours-panel.tsx` (لوحة المركز + زر «ابدأ جولة هذه الشاشة»). يُركَّب `GuideProvider` داخل غلاف التطبيق وحده؛ **لا يُستورد من وحدة ERP** (والمركز نفسه يبقى موحداً: لوحة الجولات تُمرَّر كـ`extraSection` فيه من التطبيق فقط).

| المتطلب | التنفيذ |
|---|---|
| جولة ترحيبية عند أول دخول | `welcome` تبدأ تلقائياً مرة لكل (مؤسسة، مستخدم) بعد ~0.9 ثانية؛ تُعطَّل تحت الأتمتة (`NODE_ENV=test`/WebDriver) إلا بمفتاح `awj.station-guide.force` |
| Spotlight وتعتيم | إطار برتقالي فوق العنصر الحقيقي + تعتيم بـ`box-shadow`؛ بطاقة وسطية للخطوات بلا هدف |
| بطاقات وحركة ناعمة | انتقال الإطار 280ms، ظهور البطاقة 200ms، شريط تقدم مقسَّم |
| التالي/السابق/التخطي/التقدم | أزرار 48px، `Esc` = تخطي، `role=progressbar` |
| جولات مستقلة | `welcome` · `shifts` · `sales` · `collection` (التسليم والتحصيل) · `stock` (الخزانات والاستلام) — من عناصر موجودة فعلاً (يحرس الاختبار وجود كل مرساة في المصدر) |
| إعادة الجولات | «المساعدة ← الجولات التفاعلية»: بدء/متابعة/إعادة؛ وزر «ابدأ جولة هذه الشاشة» في ورقة «؟». جولة التسليم تحتاج وردية فتُشغَّل من شاشتها |
| حفظ التقدّم | `localStorage` بمفتاح (مؤسسة، مستخدم): `in_progress`+الخطوة / `completed` / `skipped` + نسخة الجولة (نسخة أحدث تُعاد) |
| الصلاحيات | الجولة تظهر بصلاحياتها، والخطوة بصلاحياتها (مثل `fuel.sale.view`، صلاحيات الاستلام)، وعنصر غير ظاهر في DOM يُتخطّى |
| لغتان واتجاهان | نصوص `stationOps.guide.*` ar/en (يحرسها اختبار تكافؤ المفاتيح وحارس «لغة الموظف») |
| لا تعطيل ولا إجراء مالي | الغلاف `pointer-events:none`؛ لا `.click()` ولا إرسال ولا شبكة في ملفات المرشد (اختبار ساكن)؛ زر «تأكيد التسليم» يُبرَز ولا يُضغط |
| الوصول وتقليل الحركة | `aria-modal=false` (لا يحبس التركيز)، نقل التركيز للبطاقة و`aria-live`، `prefers-reduced-motion` يوقف الانتقالات والتمرير الناعم |
| عناصر مخفية/غائبة | تُحذف من الخطة (العدّاد صادق)، وعنصر يختفي أثناء الجولة يُتخطّى؛ خطة بلا أي عنصر مبرَز لا تبدأ |

### 5.3 حدود معلنة
- **التقدّم محلي لكل جهاز/متصفح** (لا API تفضيلات مستخدم في الخادم اليوم). مزامنته عبر الأجهزة تحتاج تخزيناً خادمياً بقرار منفصل.
- لا يعمل البدء التلقائي تحت الأتمتة/WebDriver (لحماية الاختبارات)؛ يُفرض بالمفتاح.
- الجولة لا تنتقل بين الشاشات تلقائياً؛ تغيّر الشاشة يوقفها ويحفظها «بدأتها ولم تكتمل».
- **لم يُختبر على Safari/iPhone حقيقي:** البيئة تحوي Chromium فقط (لا WebKit). أُضيفت البنود 32–45 إلى `AWJ_FUEL_OPS_SAFARI_IPHONE_CHECKLIST.md`.

## 7. قرارات تنتظر المالك
1. **عرض أدلة الوقود في `/help` العام:** يوصى بإظهارها هناك فقط للمستأجر المفعَّل له `fuel_stations.core` (يتطلب قراءة `GET /applications/nav-state`). أُجِّل لأنه تغيير في سطح ERP العام خارج هذه المهمة.
2. **اعتماد المحتوى مراجَعاً تشغيلياً:** صيغ الأدلة مشتقة من الشاشات والرسائل الحالية؛ تُراجع بيد مشرف محطة حقيقي قبل التعميم.
3. **تحقق Safari/iPhone الحقيقي** شرط قبل التعميم (الاختبار هنا Chromium بمقاس آيفون): البنود 32–45 في قائمة التحقق.
4. **مزامنة تقدّم الجولات عبر الأجهزة** (تتطلب تخزيناً خادمياً لتفضيلات المستخدم).
