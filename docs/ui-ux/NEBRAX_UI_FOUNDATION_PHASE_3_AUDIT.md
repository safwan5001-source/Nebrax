# Phase 3 — Audit: Create / Edit / Detail الفعلية

مسحٌ للشجرة الفعلية قبل أي تعديل. **العقود الموثّقة هنا لا تتغيّر في هذه المرحلة**؛
غرض الجدول أن يكون مرجع مراجعةٍ يُقارَن به بعد الترحيل.

## ١. الخلاصة: ما يوجد فعلاً

| الوحدة | Create | Edit | Detail |
|---|---|---|---|
| المشتريات | `/purchases/new` | `/purchases/[id]/edit` | `/purchases/[id]` |
| المصروفات | `/expenses/new` | `/expenses/new?edit=<id>` | `/expenses/[id]` |
| سندات القبض | `/receipt-vouchers/new` | `/receipt-vouchers/new?edit=<id>` | `/receipt-vouchers/[id]` |
| القيود اليومية | — (آلية) | — (غير قابلة للتعديل) | `/journal-entries/[id]` |
| القيود اليدوية | `/manual-journals/new` | `/manual-journals/new?edit=<id>` | `/manual-journals/[id]` |

**ثلاث حقائق بنيوية تحكم النطاق:**

1. **التعديل ليس مساراً مستقلاً في ثلاث وحدات من أربع.** المصروفات وسندات القبض
   والقيود اليدوية كلها تعيد استخدام صفحة الإنشاء عبر `?edit=<id>` وتقرأ المعرّف من
   `useSearchParams()`. المشتريات وحدها تملك `/[id]/edit` حقيقياً (وهو غلافٌ من عشرة
   أسطر حول `PurchaseForm` نفسه الذي يخدم الإنشاء). **لم يُنشأ أي مسار جديد** لمطابقة
   توقّعٍ اسمي.
2. **القيود اليومية لا تملك إنشاءً ولا تعديلاً — وهذا صحيح لا نقص.** `/journal-entries`
   سجلّ القيود المرحَّلة في دفتر الأستاذ؛ القيد إمّا آليٌّ مولَّد من مستند
   (`entry_kind: automatic`) أو منشأٌ عبر `/manual-journals` (`manual`) أو عكسيّ
   (`reversal`). القيد بعد الترحيل **immutable** بقاعدة معمارية في `CLAUDE.md`.
   فمسار الإنشاء/التعديل الفعلي لهذه الوحدة هو `/manual-journals` — وهو ما رُحِّل.
3. **`/purchases/[id]` ليست «صفحة تفاصيل» بالمعنى المقصود في هذه المرحلة.** انظر §٤.

## ٢. النماذج (Create/Edit)

### `/purchases/new` · `/purchases/[id]/edit` → `components/purchases/purchase-form.tsx`
- **المكوّنات:** `Card`×7، `Combobox`، `Select`، `Input`، `NumberPreviewField`،
  `PartnerDialog`، `ProductDialog`، محرّر بنود بأسطر ديناميكية.
- **الحفظ:** `submit(post: boolean)` — زرّان: «حفظ مسودة» و«حفظ وترحيل».
- **Endpoint:** `POST /purchases` · `PUT /purchases/{id}` · ثم `POST /purchases/{id}/post` عند الترحيل.
- **Payload:** JSON بالهللات (`riyalToMinor`)، بنود + خصم/شحن/تسوية + `tax_inclusive`.
- **Validation:** `canSave` = وجود مورّد + عدم الحفظ + عدم التحميل (+ شروط البنود).
- **الإجراءات:** رأس الصفحة — استيراد من مستند (إنشاء فقط)، إلغاء، حفظ مسودة، حفظ وترحيل.
- **Sticky:** بطاقة الإجماليات `lg:sticky lg:top-4`. **لا إجراءات ثابتة على الجوال.**
- **Dialogs:** `PartnerDialog` (مورّد جديد)، `ProductDialog` (منتج جديد يُختار في سطره فوراً).
- **قواعد عمل ظاهرة:** الترحيل خطوة منفصلة عن الحفظ؛ الضريبة شاملة/غير شاملة تغيّر الاشتقاق.

### `/expenses/new` (+ `?edit=`)
- **المكوّنات:** `Card`×3 + بطاقة ملخّص جانبية، `Select`، `Input`، `textarea`،
  رفع مرفقات، `PartnerDialog`، `Dialog` (تصنيف جديد).
- **الحفظ:** `submit()` — «حفظ مسودة» فقط (الترحيل من صفحة التفاصيل).
- **Endpoint:** `POST /expenses` · التعديل `POST /expenses/{id}` مع `_method=PUT`.
- **Payload:** `FormData` (لأن المرفقات multipart؛ PHP لا يحلّل multipart في PUT).
- **Validation:** `amountMinor > 0` وإلا `need_amount`؛ الزر معطّل بلا `accountId`.
  عند التعديل: إن لم تكن الحالة `draft` يُعرض `edit_draft_only` ويُمنع التحميل.
- **Sticky:** بطاقة الملخّص `lg:sticky lg:top-5` وتحوي زرّ الحفظ. **لا شيء ثابت على الجوال.**
- **قواعد عمل ظاهرة:** الترقيم مولَّد (`NumberPreviewField` معاينة فقط)؛ الضريبة تُشتقّ من
  المبلغ والنسبة؛ التعديل للمسودات حصراً.

### `/receipt-vouchers/new` (+ `?edit=`)
- **المكوّنات:** `Card` واحدة، `Select`، `Input`، `textarea`، `NumberPreviewField`.
- **الحفظ:** `<form onSubmit>` — «حفظ مسودة».
- **Endpoint:** `POST /payments` · `PUT /payments/{id}`.
- **Payload:** JSON، `direction: 'received'` ثابتة، `amount` بالهللات، `invoice_id` اختياري.
- **Validation:** `partnerId` مطلوب و`minor > 0`. عند التعديل: `direction === 'received'`
  و`status === 'draft'` وإلا `edit_draft_only`.
- **قاعدة عمل ظاهرة:** اختيار فاتورة يملأ المبلغ بمتبقّيها؛ الفواتير المعروضة مرحَّلة
  وغير مسدّدة بالكامل لهذا العميل فقط.

### `/manual-journals/new` (+ `?edit=`)
- **المكوّنات:** `Card`×3 (تفاصيل، بنود، إجماليات)، محرّر أسطر ديناميكي،
  رأس أعمدة يظهر من `xl` فقط وبطاقة لكل سطر دونه.
- **الحفظ:** `submit()` — «حفظ مسودة».
- **Endpoint:** `POST /manual-journals` · `PUT /manual-journals/{id}`.
- **Payload:** `{entry_date, description, lines[]}` والمبالغ بالهللات.
- **Validation:** كل سطر يحتاج `account_id` وإلا `accountRequired`. التعديل للمسودات حصراً.
- **قواعد عمل ظاهرة:** إدخال مدين يمسح الدائن في السطر نفسه والعكس؛ لا يقلّ عن سطرين؛
  مؤشّر التوازن `balanced = debit > 0 && debit === credit` بنصّ لا بلون وحده.

## ٣. صفحات التفاصيل

### `/expenses/[id]` — المرجع الأنضج
رأس (رجوع + رقم + شارة حالة + سطر سياق) · صفّ إجراءات (ديسكتوب مسطّح / جوال تمرير أفقي) ·
خطأ داخلي · **جوال: `Accordion` بثلاثة أقسام وقسم واحد مفتوح** · **ديسكتوب: شبكة
`[1fr_18rem]` بملخّص لاصق**. الإجراءات: طباعة، تعديل (مسودة)، نسخ، حذف (مسودة وغير مرتبط
بمستند)، ترحيل (مسودة). `POST /expenses/{id}/post|duplicate` · `DELETE /expenses/{id}`.

### `/receipt-vouchers/[id]` — **بنيةٌ متطابقة** مع أعلاه
نفس الرأس، نفس صفّ الإجراءات، نفس منطق `toggleMobileSection`/`mobileOpen` **حرفياً**،
نفس الشبكة والملخّص اللاصق. الأقسام: تفاصيل، تخصيصات، ملخّص.
`POST /payments/{id}/post|duplicate` · `DELETE /payments/{id}`.

> هذا التطابق هو التكرار الحقيقي الوحيد المؤهِّل لاستخراج `DetailPage`.

### `/manual-journals/[id]`
رأس + تلميح حالة + جدول بنود (مدين/دائن + تذييل إجماليات) + بطاقة القيد المُنشأ +
حوار العكس. الإجراءات: نسخ، تعديل/حذف/ترحيل (مسودة)، عكس (مرحَّل).
`POST /manual-journals/{id}/post|duplicate|reverse` · `DELETE`.
**ثغرتان:** `if (!journal) return null` → صفحة بيضاء صامتة عند الفشل؛ وجدول البنود
بلا أي عرض جوال (`overflow-x-auto` فقط).

### `/journal-entries/[id]`
رأس + بطاقة «الأثر المحاسبي» + جدول بنود + بطاقة القيد المعكوس. للقراءة فقط —
الإجراء الوحيد رابط إلى المستند المصدر. **الثغرتان نفسهما**: `if (!entry) return null`،
وجدول بلا عرض جوال. التحميل `h-72 animate-pulse` خام لا `LoadingState`.

## ٤. `/purchases/[id]` — خارج نمط التفاصيل عمداً

ليست صفحة تفاصيل بالمعنى المقصود، بل **مساحة عمل مستندية**: معاينة قالب طباعة مجمَّد
(`print_template_revision`) داخل `DocumentScaler`، وتصدير PDF/Excel، ومشاركة، وطباعة
حرارية بقالب منفصل، وتبويبات علاقات (مدفوعات/حركة مخزون/قيود) تتحوّل `Accordion` على
الجوال، وسجلّ مراجعات، وحوار إنشاء مرتجع.

إخضاعها لقالب `DetailPage` الموحّد يعني إمّا تشويه القالب ليستوعب المعاينة المستندية،
أو إفقاد الصفحة قدراتها. وهي فوق ذلك تلامس تجميد قوالب الطباعة — منطقٌ حسّاس خارج نطاق
مرحلةٍ عنوانها «تكوين واجهة». **لذلك: لا تُرحَّل، وتبقى نمطاً ثالثاً معلَناً**
(مساحة عمل مستندية) بجانب نمطَي النموذج والتفاصيل.

هي أصلاً تملك ما تحتاجه: `loadError` بزرّ إعادة محاولة، وقائمة إجراءات فائض على الجوال،
وأقسام قابلة للطيّ. الثغرة الوحيدة فيها `if (!purchase) return <div className="text-muted">…`
— نصٌّ عارٍ بلا طريق رجوع.
