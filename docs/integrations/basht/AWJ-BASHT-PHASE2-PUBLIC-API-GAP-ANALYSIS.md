**لا تنفيذ هنا.** فحص قراءة لـ `routes/api_public.php` و`routes/api.php` و`PublicApiScope` على `main`/فرع #2027. لا تغيير في المحاسبة أو الصلاحيات.

## ما تغطيه Public API v1 اليوم
شركاء (عميل/مورد/كلاهما): قراءة + إنشاء · منتجات: قراءة + إنشاء · فواتير مبيعات: قراءة + **مسودة** · كشف حساب طرف (`role=customer|supplier`) · Webhooks. Scopes الموجودة: `partners|products|invoices:read/write` · `statements:read` · `webhooks:read/write`.

## الجدول
| العملية | في الـ Internal API (جلسة مستخدم + RBAC) | في Public API الآن | ما يلزم للإضافة | تقدير |
|---|---|---|---|---|
| **الموردون** | شركاء `type=supplier` | **موجود فعلاً**: `GET partners?type=supplier`، `POST partners {type:"supplier"}`، كشف `role=supplier` بنفس scopes الشركاء | لا كود. تحديث المهارة/التوثيق فقط (المهارة الحالية تذكر العملاء فقط) | صغير جداً |
| **عروض الأسعار** | `quotes` (قائمة/تفاصيل/إنشاء/تعديل/حذف/issue/revise/convert) عبر `QuoteService`، صلاحيات `invoices.*` | غير موجود | scope جديد `quotes:read/write` + متحكم Public يغلّف `QuoteService` (قراءة + إنشاء **مسودة** فقط) + OpenAPI + اختبارات. بلا هجرة. **لا** `convert/issue`. تحقّقتُ أن `QuoteService::create` يقبل `status` من المدخل (الافتراضي `draft`) — الغلاف العام يجب أن يثبّته `draft` ولا يمرّره | صغير–متوسط |
| **فواتير المشتريات** | `purchases` CRUD + `post` عبر `PurchaseService`، خلف `purchases.cycle` | غير موجود | scopes `purchases:read/write` (مسودة فقط) + متحكم + `EnsureApplicationActive` للقدرة + حد الخطة إن وُجد. بلا `post` | متوسط |
| **المصروفات** | `expenses` CRUD + `post` + مرفقات وضريبة ومركز تكلفة، خلف `finance.operations` | غير موجود | scopes `expenses:read/write` (مسودة)؛ تعقيد: المرفقات، تصنيفات، ضريبة المدخلات، مركز التكلفة، سياسة الخزينة | متوسط |
| **التقارير** | `reports/*` (ميزان، دخل، ميزانية، تدفق نقدي، مركز الذمم، ضريبة، مبيعات، مشتريات، عملاء، مخزون) بـ `reports.view` | كشف حساب الطرف فقط | scope `reports:read` + غلاف **بقائمة بيضاء** فوق `ReportService` (مثل نموذج الكشف). قيود: حجم الاستجابة، نطاق الفروع، وسقف الصفوف | صغير لكل تقرير |
| **سندات القبض والصرف** | `payments` (إنشاء مسودة/تخصيص/`post`/`reverse`) عبر `PaymentService` | غير موجود | scope `payments:*` + اختيار الخزينة (TreasurySelection) + تخصيص الفواتير. **أثر محاسبي عند الترحيل** | كبير — قرار مالك |
| **السداد والتحصيل** | الترحيل والتخصيص والبوابات الإلكترونية (روابط دفع الفواتير) | غير موجود عمداً | لا يُضاف قبل سياسة صريحة: من يرحّل، حدود المبلغ، موافقة بشرية، تدقيق. مستبعد من أي توسعة عملية قريبة | مستبعد |
