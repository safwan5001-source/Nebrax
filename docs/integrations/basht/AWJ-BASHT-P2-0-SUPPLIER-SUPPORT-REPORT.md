## 1) ما أُضيف (بلا API ولا Scope جديد)
كل شيء فوق مسارات Public API الحالية وscopes الحالية؛ الموردون هم شركاء بنوع `supplier` (أو `both`).

| # | العملية | الاستدعاء | Scope |
|---|---|---|---|
| 1–7 | **العمليات السبع الأصلية — لم تتغيّر حرفياً** | (انظر المهارة) | كما كانت |
| 8 | بحث الموردين | `GET partners?type=supplier&search=…` | `partners:read` |
| 9 | تفاصيل شريك/مورد | `GET partners/<uuid>` | `partners:read` |
| 10 | إنشاء مورد | `POST partners` بـ `"type":"supplier"` | `partners:write` |
| 11 | كشف حساب مورد | `GET partners/<uuid>/statement?role=supplier&from&to` | `statements:read` |

**قواعد الإنشاء داخل المهارة:**
- **بحث قبل الإنشاء** عبر كل الأنواع (بلا فلتر `type`) بالاسم، وبرقم الضريبة إن توفر؛ المطابقة بعد القص وتجاهل حالة الأحرف. وجود مورد مطابق ⇒ إعادة استعماله، لا إنشاء.
- إن كان المطابق عميلاً فقط ⇒ لا إنشاء صامت، ويُرفع القرار للمالك (لا يوجد تعديل في Public API).
- **Idempotency-Key ثابت وقابل لإعادة الاشتقاق:** `basht-supplier-v1-<أول 12 خانة سداسية من SHA-256 لرقم الضريبة، أو للاسم المقصوص بحروف صغيرة عند غيابه>`. نفس النية = نفس المفتاح؛ لا مفاتيح عشوائية؛ التعارض/الخطأ ⇒ توقف وتقرير، لا تغيير للمفتاح.
- لا اختلاق لرقم ضريبي أو سجل تجاري أو هاتف أو بريد؛ الحقول الاختيارية فقط حين يقدمها المالك.
- كشف المورد بسقف 2000 حركة (422 ⇒ تضييق `from/to`)، ويُعرض كما يعود من الـ API بالهللات.
- لا تعديل ولا حذف (غير موجودين في Public API)؛ التصحيح من تطبيق أَوْج.

المصادقة كما نجحت في الاختبار الحي: `Authorization: Bearer $AWJ_API_KEY` مع `AWJ_API_BASE`، بلا تغيير في metadata المهارة (`requires.env`).

**فحص حي بلا مصادقة (قراءة فقط):** `GET /partners?type=supplier` و`GET /partners/<uuid>/statement?role=supplier` ⇒ **401** (المساران منشوران ويطلبان مفتاحاً). لم تُستعمل أي مفاتيح.

**تغطية آلية في الخادم:** لا يوجد اختبار PHP قائم يمارس `type=supplier` أو `role=supplier` في Public API (بحثتُ في `tests/Feature/PublicApi*`). الدعم مبني على قراءة الكود: `PublicPartnerController` (فلتر `type` ثم `supplier|both`، `POST` يقبل `supplier`) و`PublicPartnerStatementController` (يمرّر `partner_role`). لم أضف اختبارات لأن القيد يمنع تعديل الباكند.

**لا كتابة حيّة:** لم يُنشأ أي مورد.

## 5) تحديث المهارة في OpenClaw — يدوي، ليس تلقائياً
دفع الفرع إلى GitHub **لا يغيّر** شيئاً في OpenClaw. إن ثُبّتت المهارة بالاستيراد/النسخ، فنسختها محلية على قرص باشت. للتحديث (من `/setup` ← Console):
```bash
D="$OPENCLAW_WORKSPACE_DIR"; mkdir -p "$D/skills/awj-erp"
curl -fsSL -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github.raw" \
  "https://api.github.com/repos/safwan5001-source/Nebrax/contents/docs/integrations/basht/skills/awj-erp/SKILL.md?ref=claude/awj-basht-p2-0-supplier-support" \
  -o "$D/skills/awj-erp/SKILL.md"
```
(أو الصق المحتوى يدوياً، أو أعد الاستيراد من واجهة OpenClaw مع الاستبدال.) **تحذيران:** (أ) إن كانت النسخة الحالية مستوردة إلى «مكتبة المهارات» فقد تبقى لها نسخة مستقلة؛ ملف مجلد `workspace/skills` له أولوية التحميل الأعلى حسب وثائق OpenClaw، لكن لم أتحقق من مكان نسختك الفعلية. (ب) ما إذا كانت الجلسات الجارية تُعيد قراءة المهارة فوراً أم تحتاج جلسة جديدة/إعادة تشغيل — غير مؤكد.

**اختبار قبول للتحديث (قراءة فقط، من الآيفون):** اسأل باشت: «ابحث عن الموردين في أَوْج وأعطني أول خمسة» — النتيجة المتوقعة HTTP 200 وأسماء حقيقية، أو قائمة فارغة إن لم يكن لديك موردون؛ وليس خطأ 401/403. ثم: «كشف حساب المورد X للفترة …» (يحتاج `statements:read`، ممنوح في المفتاح الحالي). **لا تطلب منه إنشاء مورد** حتى تقرّر.
