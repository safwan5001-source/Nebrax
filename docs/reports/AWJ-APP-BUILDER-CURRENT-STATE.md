# AWJ App Builder — جرد الوضع الحالي (مسودة، قراءة فقط)

> **الحالة:** مسودة بحث. لا تعديل لأي كود. لا تشغيل للاختبارات (الجرد من قراءة الكود).
> **درجات الدليل:**
> - **[م]** تحققتُ منه بنفسي في الكود في هذه الجلسة.
> - **[و]** ورد من وكيل قراءة فقط مع مرجع ملف/سطر **لم أعد فحصه**. أرقام الأسطر المسبوقة بـ `~` تقريبية؛ وقد ثبت أن أرقاماً من تقرير أحد الوكلاء خاطئة (`runtime_action_handler.dart` فيه 95 سطراً)، فتُعاد قراءتها قبل اعتماد أي منها نهائياً.
> - **[د]** ورد في وثيقة فقط دون تحقق من الكود.

## 1) الخلاصة

المحرك الحالي **متين وآمن** (عزل مستأجر، صلاحيات، نسخ منشورة غير قابلة للتعديل، تحقق مخطط ومطابقة قدرات). الفجوة الكبرى **بين ما يستطيع التاجر أن يصمّمه وما يستطيع تطبيق Flutter أن يعرضه**. وفي الواجهة فجوات حقيقية يجب إغلاقها قبل أي وضع سهل.

## 2) أهم الاكتشافات (مرتبة بالأثر على التصميم)

## 3) جرد المكوّنات (15) — السجل والكانفاس وFlutter

السجل ومظهر Flutter **متطابقان تماماً في الأنواع الخمسة عشر** [و] (`registry_identifiers.dart:17-33`، `component_registry.dart:30-46`). النوع المجهول يُعرض فراغاً في Flutter ونصاً في الكانفاس.

| المكوّن | Flutter | الكانفاس (ويب) | ملاحظة |
|---|---|---|---|
| Page / Section / Text / Button / NavigationTarget / CartList / ProductList | ✔ | ✔ | `ProductList` أفقي فقط (لا شبكة) |
| Image | جزئي (https، 16:9) | جزئي (لا `<img>`) | لا بديل نصي ولا fit |
| ProductCard | ✔ (عرض 160 ثابت) | جزئي (يتجاهل الصورة) | |
| ProductDetail | ✔ | جزئي (يتجاهل الصورة) | شاشة المنتج الفعلية Native لا مخططية |
| Price | ✔ (رمز `ر.س` ثابت افتراضياً) | جزئي (يتجاهل الرمز) | |
| CartSummary | ✔ | جزئي (يتجاهل التسمية) | |
| Quantity / AddToCart / VariantSelector | ✔ | ✔ (Quantity يتجاهل الحدود) | VariantSelector محلي فقط |

**الإضافة غير مقيّدة في الواجهة:** قائمة «إضافة» تعرض كل الأنواع حتى `Page`، فيمكن وضع `Page` متداخل أو `Quantity` خارج `ProductDetail` [و] (`inspector.tsx:~595,680`). مهم للوضع السهل: يحتاج قواعد وضع آمنة.

## 5) أثر تفضيل الوضع «لكل تطبيق»

| الخيار | يتطلب | أثره |
|---|---|---|
| عمود جديد على `builder_apps` (مثل `editing_mode`) | **هجرة** إضافية nullable، وعقد API جديد (`PATCH apps/{id}` يقبل الاسمين فقط اليوم) | مشترك بين كل مستخدمي التطبيق؛ بلا تعارض مع المخطط |
| داخل `schema` | غير ممكن | المخطط يرفض أي مفتاح غير معروف، وDart حرفي [و] |
| `localStorage` لكل مستخدم/تطبيق | لا شيء | لا يحقق «محفوظ لكل تطبيق» عبر الأجهزة والمستخدمين |

**الصلاحيات [و]:** `apps_builder.view/manage/publish` تُمنح لـ owner/admin عبر `*` فقط، ويُمكن منحها لأدوار مخصصة. أي تفضيل مشترك على التطبيق يغيّره كل من يملك `manage`. وتحويل الوضع **لا يُنشر** ولا يؤثر على التطبيق المنشور، لذلك يكفي `manage` ولا حاجة لصلاحية جديدة. مع الاعتراض الجوهري: لا يوجد قفل تفاؤلي (§2-5)، فتبديل الأوضاع بين مستخدمين مختلفين على مسودة واحدة معرّض للكتابة فوق بعضها.

## 6) سلامة الذهاب والعودة بين الوضعين (نتائج الجرد)

- **المحلل صارم ولا يُسقط شيئاً بصمت** [و]: يرفض المفتاح غير المعروف بدل حذفه، ومعرّفات المكوّنات تبقى كما هي. وهذا **ميزة** لسلامة التبديل: ما يكتبه الوضع السهل يعود كما هو في المتقدم.
- **لكن لا مكان لبيانات خاصة بالوضع السهل** في المخطط. أي «تلميحات واجهة» يجب أن تُشتق من البنية نفسها (أنماط تعرّف Presets من شكل الشجرة) أو تُخزَّن خارج المخطط (عمود/جدول جديد).
- **شبكة الأمان الاختبارية الموجودة** [و]: `BuilderAppTest`، `AppSchemaParserTest`، `CompatibilityResolverTest`، `ComponentRegistryTest`، `ActionRegistryTest`، `AppBuilderRegistryTest`، `AppBuilderIntegratedProofTest`، `AppBuilderPreviewToRuntimeIntegratedProofTest`، واختبارات الويب للمحرر والكانفاس وملفات العقد في `contracts/app-builder/`.
- **غير مغطى باختبار:** تعارض `revision`، وعدم تطابق `primaryColor`/`colorPrimary` [و].

## 8) ما يمكن إعادة استخدامه بأمان

- نموذج `BuilderApp`/المسودة/النسخ المنشورة، الصلاحيات، العزل، التحقق والمطابقة، مسار Preview Session. [و]
- المحرر الحالي كاملاً (وضع متقدم).
- أنماط التركيب: الوضع السهل يستطيع إنشاء «أقسام» من المكوّنات الـ15 **الآن** (نص، صورة بالرابط، قائمة منتجات، أزرار تنقل) دون تغيير عقد.

## 9) ما يحتاج تكييفاً أو عملاً جديداً (للتصور فقط، غير معتمد للتنفيذ)

| العمل | الطبقة | يحتاج Decision Gate؟ |
|---|---|---|
| إصلاح عقد الثيم (`colorPrimary` ومصدر التجربة المنشورة) | الويب + Flutter | نعم (تغيير سلوك Runtime) |
| قفل تفاؤلي على المسودة | API + الواجهة | نعم (تغيير عقد API) |
| تفضيل الوضع لكل تطبيق | هجرة + API | نعم (هجرة + عقد) |
| مكوّنات جديدة (بنر، كاروسيل، تبويبات، شريط علوي) | سجل + محلل + Flutter + كانفاس | نعم (عقد مخطط/Runtime) |
| موجِّه صفحات عام ودعم الفئات/الحساب/الطلبات | Flutter + Commerce client | نعم |
| شاشة دخول العميل | Flutter | نعم |
| رفع الوسائط | الويب + الباك إند الموجود | يُدرس |
