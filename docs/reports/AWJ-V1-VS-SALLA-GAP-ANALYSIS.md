## 3) تقييم نموذج V1 مقابل الأدلة

| ما أصاب فيه V1 | ما يجب أن يصححه V2 |
|---|---|
| وسم الحالات الثلاث (جاهز/بقيود/مقترح) | الإبقاء عليه وتوسيعه ليشمل الأشرطة والهوية |
| الكتالوج المرئي والبحث والتصفية | يُنظَّم بتصنيفات (محتوى/منتجات/تنقل/سلة/حساب) ويُدرج موضع الإدراج |
| تبديل الوضعين على مسودة واحدة | **كان العرض المتقدم قراءة فقط**؛ لم يُثبت أن بيانات المتقدم تبقى عند العودة. V2 يضيف تحريراً متقدماً يُختبر ذهاباً وعودة |
| JSON ناتج من مكوّنات السجل الحقيقية | يُحافَظ عليه، مع `optional` و`binding.query` |
| فحص جاهزية النشر | يضاف سلوك `optional` الحقيقي (V3) |
| | **المعاينة كانت ثانوية**؛ المطلوب نقطة دخول أساسية وتحرير بالضغط على العناصر |
| | **الصفحات والأقسام كانتا ممزوجتين** في تبويب واحد؛ تُفصل |
| | **نصّ V1 قال «التصفية والترتيب من الوضع المتقدم» كأنهما يعملان**؛ الصحيح أنهما **لا يُطبَّقان في التطبيق** (V1 أعلاه) |
| | **الإخفاء والتسمية قُدّما كأنهما مجانيان**؛ لا مكان لهما في المخطط (V4) |
| | لا حالة فشل حفظ، ولا اتجاه/جهاز، ولا تفاعل مع بقية الصفحات الأصلية (شاشة المنتج الأصلية) |
| | **عيب في V1 اكتُشف أثناء اختبار V2:** مفاتيح التبديل (toggle) لا تستجيب للنقر الحقيقي، لأن عنصر `<i>` الزخرفي يغطي الـ`input` ويلتقط النقر (الاختبار: قبل النقر `checked=true` وبعده `true`، والعنصر عند المركز `I`). صُحّح في V2 بـ`pointer-events:none`. **لم يُعدَّل V1** التزاماً بقيد الحفاظ على ملفاته |

## 4) خلاصة بحسب المطلوب

| الفئة | العناصر |
|---|---|
| **موجود ويمكن إعادة استعماله** | محرك المسودات/النسخ/الاستعادة، التحقق والمطابقة (بما فيها `optional`)، الصلاحيات، معاينة المتصفح الفورية و«معاينة على الجوال»، التجربة الافتراضية، قوائم المنتجات الحيّة، أفعال السلة الحيّة، الوضع المتقدم |
| **UX/UI فقط** | معاينة بنقطة دخول أساسية، التحرير بالضغط على العناصر، قائمة أقسام مستقلة، كتالوج بصري، نماذج بنصوص مساعدة وقيود، فصل الصفحات عن الأقسام، حالات الحفظ والتحذير |
| **مكوّنات Flutter + سجل جديدة** | سلايدر، شبكة منتجات، عداد، فيديو، آراء، مميزات، شريط علوي مدفوع بالمخطط، تبويبات سفلية، شريط إعلاني، شاشتا بداية وترحيب |
| **Runtime/API** | تمرير `binding.query` للجلب (يفتح ترتيب المنتجات/العدد)، موجّه صفحات عام، ربط التصنيفات وشاشتها، دخول العميل والطلبات، استهلاك رموز الثيم (لون/خط/داكن/خلفية)، حلّ `$item` في المعاينة، تخصيص صفحة المنتج وبطاقته |
| **قرارات معمارية** | مخزن جانبي لبيانات المحرر (إخفاء/اسم/نوع Preset)، قفل تفاؤلي، تفضيل الوضع لكل تطبيق، محتوى متعدد اللغات، استهداف أسواق، قفل بالباقات |
| **تبقى في المتقدم** | الشجرة والخصائص الخام، `binding`/`collect`/`query`، شرط الظهور، معاملات الإجراءات، التراجع/الإعادة، الإصدارات |
| **لا نقلّده** | دمج «الحفظ» مع «التطبيق لدى العملاء» (مسودة ونسخ أَوْج أقوى)، معاينة بالحفظ ثم التحديث اليدوي، شاشات تحميل بثّ الجهاز |
