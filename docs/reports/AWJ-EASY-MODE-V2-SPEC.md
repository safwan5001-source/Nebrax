# مواصفة الوضع السهل V2 — صانع تطبيقات أَوْج (تصوّر للمراجعة)

> **الحالة:** مواصفة UX/UI لنموذج تفاعلي. **لا تنفيذ فعلي، ولا تغيير** في صانع التطبيقات ولا AppSchema ولا Flutter Runtime ولا API ولا قاعدة البيانات.
> **الأساس:** `SALLA-OFFICIAL-DOCS-AUDIT.md` + `AWJ-V1-VS-SALLA-GAP-ANALYSIS.md` + `AWJ-SALLA-MOBILE-VIDEO-ANALYSIS.md`.
> **الملفات:** النموذج في `docs/reports/prototype/awj-easy-mode-v2/` (V1 محفوظ كما هو في `awj-easy-mode/`).

## 1) المبادئ

1. **المعاينة هي نقطة الدخول.** يفتح المحرر على تطبيق جاهز ظاهر في معاينة، لا على قائمة إعدادات.
2. **الضغط على العنصر داخل المعاينة يحرّره.** لا بحث في قوائم متشعبة.
3. **الأقسام قائمة مستقلة** (ترتيب/إخفاء/إضافة)، و**الصفحات مستقلة عن الأقسام**.
4. **المسودة نفسها في الوضعين.** الوضع السهل يولّد عقد AppSchema من مكوّنات السجل الحالي، والمتقدم يعرضها ويحرّرها؛ لا مخطط ثانٍ ولا محرك موازٍ.
5. **الصدق قبل الاكتمال.** كل عنصر موسوم: **جاهز** / **جاهز بقيود** / **مقترح** (يتطلب Flutter Runtime أو API). لا يُعرض شيء غير مدعوم كأنه يعمل.
6. **أَوْج تحتفظ بتفوقها:** مسودة ← نسخة منشورة غير قابلة للتعديل ← استعادة، ومعاينة فورية. **لا نقلّد** دمج «الحفظ» مع «التطبيق لدى العملاء» عند سلة.
7. **Mobile-first**، ثم السطح. RTL أصلي مع معاينة LTR.
8. **نظام تصميم أَوْج** (رموز `globals.css`): لون هوية واحد، خطّان، بلا زخرفة، لون + أيقونة + نص للحالات.

## 2) نموذج البيانات المشترك

```
Draft (واحدة) ── Easy Mode ──┐
                              ├─► AppSchema { pages: { home, cart, … } }
Advanced Mode ───────────────┘
```

| المفهوم في الوضع السهل | الناتج في AppSchema | الدليل |
|---|---|---|
| قسم «نص» | `Section{title} → Text{text,style}` | `ComponentRegistry` [م] |
| قسم «قائمة منتجات» | `Section{title} → ProductList{binding:{resource:'commerce.products'}} → ProductCard (optional, $item.*, openProduct)` | مطابق لـ`default-experience.ts` [م] |
| قسم «بنر ترويجي» | `Section → Image{url} + Text + Button{navigate}` | `Image` غير قابل للأفعال فالزر منفصل [م] |
| قسم «زر» | `Button{label,style} + action navigate{pageId}` | [م] |
| محتويات/ملخص السلة | `CartList{binding commerce.cart, collect items}` / `CartSummary` | [م] |
| قسم «مقترح» | عقدة `x-proposed.*`: **تفشل المطابقة عند النشر ما لم تكن `optional`** | `CompatibilityResolver.php:113-135` [م] |
| لون التطبيق | `theme.tokens.colorPrimary` | مفتاح Flutter [م] (وليس `primaryColor` الذي تكتبه واجهة الويب اليوم) |

**بيانات الوضع المتقدم لا تُفقد عند التبديل:** أي قيمة لا يمثلها الوضع السهل (مثل `binding.query.sort` أو `optional`) تبقى في المسودة نفسها، ويعرضها الوضع السهل كـ«مضبوط من المتقدم» ولا يمسحها. يُختبر ذلك ذهاباً وعودة (§9).

### 2.1 فجوة معمارية موسومة (لا تُحسم هنا)
**الإخفاء** و**اسم القسم** و**نوع الـPreset** لا مكان لها في AppSchema (المحلل يرفض أي مفتاح غير معروف). النموذج يعرضها لأنها جوهر التجربة، لكنه يوسمها **«يحتاج قراراً»**: مخزن جانبي لبيانات المحرر (عمود/جدول جديد) أو اشتقاقها من البنية، أو تفعيل `visibility` في Runtime. حتى يُقرَّر ذلك لا يُبنى في التنفيذ الفعلي.

## 3) هيكل الشاشة (ثلاثة تخطيطات)

| العرض | التخطيط |
|---|---|
| **سطح مكتب واسع (≥1200px)** | ثلاثة أعمدة: **المستكشف** (أقسام/صفحات/هوية) · **المعاينة** · **المفتش** (خصائص العنصر المحدد) |
| **متوسط (1000–1199px)** | عمودان: المستكشف والمفتش يتناوبان في العمود نفسه (التحديد يفتح المفتش، والرجوع يعيد المستكشف) |
| **جوال (<1000px)** | المعاينة بملء الشاشة بلا إطار هاتف، وشريط سفلي (الأقسام · إضافة · الصفحات · الهوية). المستكشف والمفتش **أوراق سفلية**؛ المفتش يترك المعاينة ظاهرة فوقه فيرى التاجر أثر تعديله مباشرة |

**الشريط العلوي:** اسم التطبيق وشارة «مسودة»، مفتاح **سهل/متقدم**، حالة الحفظ، تراجع/إعادة، **حفظ**، قائمة «المزيد».

## 4) التفاعلات

### 4.1 المعاينة والتحرير بالضغط
- كل قسم في المعاينة قابل للتحديد (ضغط/لمس/لوحة مفاتيح). التحديد يرسم إطاراً بلون الهوية ووسماً باسم القسم، ويفتح المفتش، ويُبرز الصف في القائمة.
- **شريط عائم** على القسم المحدد: أعلى، أسفل، إخفاء، تكرار، حذف.
- الضغط على فراغ الصفحة يلغي التحديد. زر «+ إضافة قسم» في آخر الصفحة.
- المعاينة **فورية** مع كل ضغطة مفتاح (لا حفظ ولا تحديث يدوي، على عكس سلة).

### 4.2 قائمة الأقسام (مستقلة)
سحب بالمقبض (مؤشر/لمس) أو أسهم لوحة المفاتيح؛ إخفاء/إظهار؛ قائمة: تحرير، تكرار، إعادة تسمية، نقل، حذف (مع «تراجع»). عدّاد «ظاهر/الكل». حالة فارغة صريحة.

### 4.3 كتالوج المكوّنات
ورقة بحث وتصنيفات (الكل، محتوى، منتجات، تنقّل، سلة، حساب) وتصفية بالحالة. لكل نوع معاينة مصغّرة، وشارة حالة، ووصف. اختيار نوع جاهز يضيفه **بعد القسم المحدد (أو في النهاية)** ويحدده ويمرر المعاينة إليه. اختيار نوع مقترح يعرض متطلبه ويتيح «إضافة كتصوّر».

### 4.4 الصفحات (منفصلة عن الأقسام)
| الصفحة | الحالة | الدليل |
|---|---|---|
| الرئيسية، السلة | **جاهز** (قابلة للتحرير بالأقسام) | Flutter يقرأ `home`/`cart` [م] |
| تفاصيل المنتج | **جاهز بقيود: عرض فقط** (شاشة أصلية في Runtime) | `product_screen.dart` [م] |
| التصنيفات، الحساب، الطلبات | **مقترح** (تصوّر) | لا موجّه صفحات ولا شاشات [م] |

**الأشرطة والتنقل:** شريط علوي (عرض فقط: عنوان ثابت في Runtime)، **تبويبات سفلية** (تصوّر: أسماء، ربط بصفحة، إظهار، ترتيب، **حدّ 5 ظاهرة** مستلهم من حد موثق عند سلة وليس قاعدة أَوْج)، **شريط إعلاني** (تصوّر موسوم).

### 4.5 الهوية
اسم التطبيق، لون التطبيق (جاهز بقيود + تنبيه P0-1)، وعناصر **مقترحة معطّلة** بسببها: الشعار، الخط، الوضع الداكن، شاشتا البداية والترحيب.

### 4.6 الجهاز والاتجاه
جوال 390، جوال صغير 360، تابلت 768 (تقريب فقط: لم تُوثَّق تخطيطات الأجهزة اللوحية في Runtime). تبديل RTL/LTR للمعاينة. على الجوال لا يُرسم إطار هاتف داخل الهاتف.

### 4.7 حالات الحفظ
| الحالة | العرض | الإجراء |
|---|---|---|
| لا تغييرات | ✓ «محفوظ» + الوقت | زر حفظ معطّل |
| تغييرات غير محفوظة | ● ⚠ «تغييرات غير محفوظة» | حفظ، **حارس مغادرة** |
| جارٍ الحفظ | مؤشر دوّار | تعطيل الحفظ |
| **فشل الحفظ** | ⚠ «فشل الحفظ — تعديلاتك محفوظة هنا» | **إعادة المحاولة**، لا فقد |
تراجع/إعادة (50 خطوة) بأزرار واختصارات `Ctrl+Z`/`Ctrl+Shift+Z`، و`Ctrl+S`. كل حذف يعرض «تراجع».

### 4.8 الوضعان
مفتاح سهل/متقدم **لا يمسح شيئاً**. المتقدم: شجرة وخصائص قابلة للتحرير لحقول محددة + المخطط JSON. تحديد قسم يُحدد عقدته في المتقدم، والعكس.

### 4.9 النشر (محاكاة)
فحص جاهزية يعكس المحرك: قسم/شريط **مقترح** يمنع النشر، **إلا** إن جُعل «اختيارياً» فيُسقط عند النشر (سلوك `optional` الحقيقي) مع تنبيه. لا نشر فعلي.

## 6) الاختلافات المعروفة عن Flutter Runtime الحقيقي
المعاينة في النموذج **تقريب في المتصفح**، وتختلف عن التطبيق الحقيقي في:
1. **شريط التطبيق:** النموذج يعرض اسم التطبيق؛ Flutter يعرض عنواناً ثابتاً مضمَّناً.
2. **الصور:** تُعرض بنسبة 16:9 مع بديل نصي؛ المنتجات ببيانات تجريبية.
3. **ترتيب المنتجات:** يُقبل في الخادم ويتجاهله Runtime.
4. **اللون:** النموذج يطبّق لون التطبيق فوراً؛ Flutter يقرأه اليوم من المخطط المضمَّن.
5. **الصفحات الإضافية والأشرطة والتبويبات:** تصوّر فقط.
6. **المعاينة على الجوال الحقيقية** (QR/جلسة معاينة) محاكاة.
7. **الأجهزة اللوحية:** تقريب بلا توثيق في Runtime.

## 7) الوصولية وRTL
أزرار بأسماء وصول، تركيز مرئي بلون الهوية، لوحة مفاتيح لإعادة الترتيب والتحديد والحوارات (Esc)، أهداف لمس ≥ 36px (44px في الصفوف)، حالات بلون + أيقونة + نص، `prefers-reduced-motion`، عزل الكلمات اللاتينية داخل الجمل العربية (`bdi`)، رمز الريال `U+20C1` بخطه.

## 8) ما يبقى في الوضع المتقدم
الشجرة الكاملة، الخصائص الخام، `binding`/`collect`/`query`، شرط الظهور، معاملات الإجراءات، سجل الإصدارات والاستعادة. النموذج يحرّر منها جزءاً تجريبياً لإثبات سلامة التبديل.

## 9) معايير القبول وخطة الاختبار (مطابقة للنموذج)
| المعيار | الاختبار الآلي |
|---|---|
| المعاينة هي نقطة الدخول | بعد الإنشاء تُرى المعاينة والمفتش فارغ «اضغط عنصراً» |
| التحرير بالضغط على العناصر | ضغط قسم في المعاينة يحدده ويفتح المفتش ويعدّل المعاينة |
| قائمة أقسام مستقلة | ترتيب (مؤشر/لوحة مفاتيح)، إخفاء، إضافة، تكرار، حذف + تراجع |
| كتالوج بصري | بحث وتصنيفات وتصفية بالحالة وإضافة بعد المحدد |
| فصل الصفحات عن الأقسام | تبويب الصفحات، صفحة مقترحة موسومة، شاشة المنتج عرض فقط |
| الهوية | لون يغيّر المعاينة، عناصر مقترحة معطّلة |
| RTL/LTR والأجهزة | تبديل الاتجاه والعرض يغيّران المعاينة |
| تراجع/إعادة وحالات الحفظ | غير محفوظ → جارٍ → محفوظ → **فشل → إعادة** |
| عدم فقدان البيانات بين الوضعين | ضبط `sort` وتحرير عقدة في المتقدم ثم العودة وتعديل ثم عودة: القيم باقية والمخطط متسق |
| تمييز المدعوم/المقترح | شارة على كل نوع، ومنع النشر ما لم يكن اختيارياً |
| لا أخطاء Console | مراقبة `pageerror`/`console.error` |
| جوال وسطح مكتب | 390 · 1100 · 1440 مع فحص عدم وجود تمرير أفقي |

## 10) قرارات مفتوحة (للمالك)
1. **مخزن بيانات المحرر** (الإخفاء/الاسم/Preset): عمود جديد أم اشتقاق من البنية أم تفعيل `visibility`؟
2. **تمرير `binding.query` في Flutter** (يفتح ترتيب المنتجات/العدد)؛ و«الأكثر مبيعاً» يحتاج ترتيباً جديداً في API.
3. **القالب:** هل نعدّد القوالب (على غرار افتراضي/منيو) أم نكتفي بقالب واحد وتجارب جاهزة؟
4. **المحتوى متعدد اللغات** في المخطط.
5. **ترتيب الأولويات للمكوّنات الجديدة** (أرشّح: سلايدر/بنر، تبويبات سفلية، شريط علوي، تصنيفات).
6. **صلاحيات الوضعين** وتفضيل الوضع لكل تطبيق (هجرة وعقد API).

## 11) خارج النطاق
منشئ «App Details» (لا يوجد في التوثيق)، قوالب WebView، مراحل التدشين للمتاجر (App Factory مؤجَّل)، حسابات المطورين.
