# S02a — فرض عقد المكوّنات (AD-12) على الخادم

**Base:** مبنية فوق S01d (#1826) حتى دمجها. الموافقة: AD-12 بالنهج المرحلي الموثَّق.

## ما نُفِّذ
- `AppSchemaContractChecker` + `ContractIssue` + `SchemaContractViolationException`: فاحصة نقية فوق المحلل البنيوي.
- **حدود صارمة عند الحفظ:** فرادة `component.id` داخل الصفحة، وسقف بايتات (`config/app_builder.php`، 262144 افتراضياً) ⇒ 422 بلا كتابة.
- **`issues[]` عند الحفظ والقراءة:** تحذيرية لا تمنع الحفظ (المسودات القديمة المخالفة تُحفظ وتُصلَح). `error` منها يمنع النشر/الفحص بـ422 `contract_violations` منظَّم بلا إنشاء نسخة.
- **القواعد:** خصائص (نوع/enum/مجهولة/مطلوبة غائبة)، إجراءات (معاملات مطلوبة/نوع/حد أدنى/مجهولة/غير مدعومة)، `navigate.pageId` موجود، `Page` جذر فقط، لا أبناء للورقيات.
- **`allowed_children`/`allowed_parents`** في `GET registries` من مصدر واحد (`ComponentRegistry`).
- عقد مشترك `contracts/app-builder/contract-issues.v1.json` يحرسه اختبار تطابق الرموز.

## معايرة ضد البيانات الفعلية
شُغِّلت الفاحصة على قالبَي الويب (blank/catalog) وعلى `integrated-proof-schema.v1.json`: صفر مخالفات؛ وكل اختبارات الصانع/المعاينة القائمة (420) تمر بلا تعديل، فلا مسودة قائمة تنكسر. مفتاح `$item.*` مستثنى من فحص النوع.

## الاختبارات
- `AppSchemaContractCheckerTest` (14) و`BuilderContractEnforcementApiTest` (9): حدود الحفظ، التحذيرات غير الحاجبة، منع النشر والفحص، إصلاح مسودة قديمة ثم نشرها، السجلات، عزل المستأجر (404 بلا issues)، الصلاحيات.
- محلياً: 420 ناجحاً (SQLite) + PostgreSQL للحزمة.

## خارج النطاق (مسجَّل)
- **حدود الكمية لكل مستأجر (DRF-07):** سياسة عمل ⇒ تحتاج قرارك (تقترحها S02c: خيارات: PlanGate بحدود لكل خطة / إعداد لكل مستأجر / بلا حد). 
- واجهة الويب: عرض `issues[]` والبناء على السجل وتوحيد قوائم الأنواع (CPT-03) = S02b.
- لا هجرة.
