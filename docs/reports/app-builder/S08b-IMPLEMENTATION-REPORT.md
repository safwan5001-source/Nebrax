# S08b — `binding.query` يصل من المخطط إلى الطلب (AD-09، الجانب الجهازي والمحرر)

**القرار:** AD-09 معتمد. **لا تغيير في شكل المخطط ولا API ولا هجرة** — الجهاز يبدأ باحترام `binding.query` الذي كان يُحلَّل ويُتحقَّق منه ولا يُرسَل (CMP-12). يكمل S08a (ترتيب `popularity` على الخادم).

## ما نُفِّذ
**Flutter**
- `sanitizedBindingQuery`: مفاتيح العقد فقط — `search` (≤120 مقصوصة)، `sort` (`^-?[a-z_]{1,40}$`)، `category_id` (UUID حرفي فقط)، `per_page` (عدد صحيح مقيَّد 1..100). كل ما عداه **يُسقَط ولا يُرسَل** (مفتاح مجهول، `id`، `page`، مرجع `$route.*`، قيمة بشكل خاطئ).
- `bindingDataKey` (قانوني: بلا استعلام فعّال = معرّف المورد وحده كما قبل) و`collectBindingRequests` (طلبات مميَّزة بعمق الشجرة) و`resolveNodeBindings` يقرأ بيانات الاستعلام المحدّد ثم المورد العاري (توافق).
- `HomeScreen`: يجلب **طلباً واحداً لكل استعلام مميَّز** (التكرار مرة واحدة) فتحمل قائمتان بترتيبين مختلفين بياناتهما الخاصة. صفحة بلا ربط ⇒ الطلب العاري الوحيد كما كان.
**الويب (المفتش)**
- خيارات الترتيب تعرض أسماء بشرية مترجمة (الاسم/السعر/تاريخ الإضافة/**الأكثر مبيعاً**)، والمجهول يبقى بمفتاحه.

## التوافق
- الأجهزة الأقدم (بلا S08b) تتجاهل `binding.query` كما كانت — لا كسر؛ المفتاح موجود في المخطط أصلاً فلا جيل Runtime جديد.
- `category_id` عبر `$route.categoryId` **مؤجَّل** (لا مصدر سياق قبل موجّه الصفحات S06) ويُسقَط بأمان.

## الاختبارات
- Dart (+10): تنقية الاستعلام وحدودها، المفتاح القانوني، جمع الطلبات المميَّزة، دقة التوزيع بين ربطين، التوافق مع المستدعي الأقدم؛ **widget**: `HomeScreen` يرسل 3 طلبات مميَّزة (التكرار مرة) بـ`sort`/`per_page` الصحيحين وكل قائمة تعرض بياناتها. `flutter analyze` نظيف، `flutter test` كامل 494/494.
- Vitest (+2): تسميات الترتيب بالعربية والإنجليزية وبقاء المجهول؛ حزمة app-builder 319/319.

## الحدود
- لم تُجرَّب على جهاز/محاكي فعلي (اختبارات widget فقط).
- اتجاه الترتيب في المحرر «تصاعدي/تنازلي»؛ لـ`popularity` «تنازلي» = الأكثر مبيعاً أولاً.

## مراجعة Codex (P1 + P2) — أُصلحتا
- **P1:** `HomeScreen` لم يكن يعيد الجلب حين تصل التجربة الحيّة بعد التركيب (فتبقى بيانات الصفحة المضمَّنة وتُتجاهل الاستعلامات عبر التوافق مع المورد العاري). الآن يعيد الجلب عند تغيّر التجربة، مع **رقم تسلسلي** يمنع تحميلاً أقدم متأخراً من استبدال الأحدث (اختباران، والطفرة بإزالة الحارس تُفشل اختبار «القديم المتأخر»).
- **P2:** مفتاح البيانات كان يلصق القيم دون ترميز فيتصادم `search='shoes&sort=name'` مع `{search:'shoes',sort:'name'}`. القيم صارت مرمَّزة (`Uri.encodeQueryComponent`) فلا تصادم (اختبار).
