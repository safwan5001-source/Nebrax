# S21b — إدارة الصفحات في الوضع السهل (مواصفة V2 §4.4)

**الأساس:** S21a/S20b/S03b. **لا API ولا هجرة ولا مفتاح مخطط.** الجهاز واللغة (جوال/تابلت/سطح مكتب، AR/EN) موجودان أصلاً في الرأس منذ S21a/S23a ولم يتغيّرا.

## ما نُفِّذ
- **تعيين الصفحة رئيسية** من الوضع السهل (كانت في المتقدم فقط)؛ الرئيسية الحالية لا تُحذف ولا يُعاد تعيينها (تظهر ملاحظة «هذه هي الرئيسية»).
- **حذف الصفحة بعد تأكيد** يسمّي الأثر: عدد إجراءات `navigate` التي تستهدفها في كل المخطط (`countNavigationTo`) — تبقى مخالفة حاجبة `navigate_target_missing` حتى تُصلَح. الإلغاء لا يمسّ شيئاً، والتأكيد يعيد التحديد إلى الرئيسية. تراجع/إعادة تعمل كما لباقي التعديلات.
- **صفحات مقترحة** (التصنيفات، الحساب، طلباتي) مدرجة **معطّلة بسببها** («لا شاشة لها في تطبيق الجوال الحالي») ولا تُضاف أبداً — صدق V2.
- **عدّاد الأقسام** يصير «ظاهر/الكل» حين يُخفى قسم.
- كل الأدوات معطّلة بلا صلاحية `manage`.

## الاختبارات
- vitest (5 سلوك فعلي): تعيين رئيسية **ويُحفظ فعلاً** (`navigation.initialPageId` في PUT)، الرئيسية بلا زرّي حذف/تعيين، الحذف: تأكيد ثم إلغاء بلا أثر ثم تأكيد يزيل الصفحة في PUT ويعيد التحديد، **الأثر معلَن (1 إجراء)**، المقترحة معطّلة بلا أزرار، الصلاحية، العدّاد. + `countNavigationTo` (أي عمق/أي صفحة، `openProduct` لا يُحسب). 345/345 + 37.
- حارس i18n كشف مفاتيح ناقصة أثناء العمل (أُضيفت) — ar/en حقيقيان.
- Playwright (متصفح حقيقي): حذف يسأل ويسمّي إجراءً واحداً، الإلغاء بلا تعديل، تعيين الرئيسية يُحفظ.

## الحدود
- لا إضافة صفحات «جاهزة» جديدة (لا شاشة Runtime لها). الأوراق السفلية والشريط العائم وسحب الترتيب = S21c.
