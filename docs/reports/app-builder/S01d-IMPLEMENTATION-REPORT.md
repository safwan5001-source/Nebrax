# S01d — حماية نشر المسودة (إغلاق G1)

**Base:** `main @ e88d0b0` (بعد S01c). الموافقة: قرار المالك (إغلاق G1 بعقد إضافي متوافق).

## ما نُفِّذ
- `POST app-builder/apps/{id}/versions` يقبل `expected_draft_revision` اختيارياً. عدم تطابقه داخل القفل ⇒ 409 `draft_changed_since_review` بلا نسخة.
- `publish()` يقفل صف التطبيق ثم صف المسودة ويلتقط المخطط ويتحقق منه من الصف المقفول نفسه (كان يقرؤه بلا قفل). ترتيب الأقفال: التطبيق ← المسودة؛ الحفظ يقفل المسودة وحدها فلا جمود.
- هجرة إضافية `nullable`: `source_draft_revision` على النسخة المنشورة (تُكتب عند الإنشاء فقط؛ النسخة تبقى غير قابلة للتعديل). null للقديم، بلا Backfill.
- الواجهة: النشر يرسل `baseRevisionRef.current`؛ 409 يغلق الحوار برسالة «لم يُنشر شيء» (ar/en).
- عقد جديد `contracts/app-builder/draft-publish.v1.json`، وCLAUDE.md محدَّث.

## الاختبارات
- `BuilderPublishExpectedRevisionTest` (9 حالات + dataProvider): مطابق ينجح ويسجّل المصدر، قديم/متقدم ⇒ 409 بلا نسخة ولا لمس للمسودة، بلا الحقل ينجح (توافق)، قيمة غير صالحة 422، مستأجر آخر 404 بلا تسريب، دور بلا نشر 403 قبل أي مقارنة، النسخة تحتفظ بمصدرها بعد تحرك المسودة.
- PostgreSQL (`pcntl_fork`): حفظ ونشر متزامنان — كل نسخة منشورة يطابق مخططها `source_draft_revision`، أرقام النسخ متتالية.
- الويب: النشر يرسل الـrevision، و409 يعرض الرسالة بلا نجاح. vitest app-builder: 306 ناجحاً.
- محلياً: 255 (SQLite، كل حزمة الصانع/المعاينة) و59 (PostgreSQL).

## المخاطر والحدود
- الحقل اختياري (توافق)؛ تحويله لإلزامي (428) قرار لاحق إن رغبت — الويب يرسله دائماً.
- `POST validate` لم يتغير (G2 → S21).
- هجرة جديدة (إضافية قابلة للتراجع)، لا نشر.
