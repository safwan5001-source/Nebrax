# S01c — فرض `base_revision` (428) على حفظ المسودة

**الحالة:** PR للمراجعة والدمج المشروط. **Base:** `main @ 258d392`. الموافقة: قرار المالك (AD-01، S01c موافَق عليه بعد إثبات الحصر).

## ما نُفِّذ
- المتحكّم: غياب/`null` لـ`base_revision` ⇒ **428** `{message, reason: "base_revision_required", current_revision}` بلا كتابة. الترتيب: مصادقة ← صلاحية ← 404 (مستأجر آخر/تطبيق غير موجود) ← تحقق الشكل (`schema` مطلوب ⇒ 422) ← 428 ← القفل/409.
- الخدمة: `int $baseRevision` إلزامي نوعاً (حذف الافتراضي `null`)، حُذف مسار «آخر كتابة تفوز» ومقياس `app_builder.draft_save_without_base_revision`. لا يمكن لأي مستدعٍ تجاوز القفل.
- العقد المشترك `contracts/app-builder/draft-save-conflict.v1.json` يوثّق 428 ويجعل الحقل إلزامياً. `CLAUDE.md` محدَّث.

## إثبات الحصر قبل الفرض
الكاتب الوحيد في الإنتاج هو الويب (المحرر، استعادة الإصدارات، بذر القالب) وكلها ترسل `base_revision` منذ S01b (#1816). لا يوجد في `mobile/` أو `preview-host/` أو `storefront/` أو `scripts/` أو الأوامر/الـJobs/الـSeeders أي كاتب للمسودة (بحث نصي، S01-INV). ملاحظة: لا يمكن نفي سكربتات خارج المستودع؛ مرحلة Beta بحسابات اختبار.
اختبارات الخادم التي كانت تحفظ بلا أساس (7 ملفات، 21 موضعاً) حُدِّثت عبر `builderDraftBody()` (يقرأ revision الحالي).

## الاختبارات
- `BuilderDraftOptimisticLockTest` (SQLite + PG) أُعيدت كتابة قسم التوافق الرجعي: 428 (غياب/null) بلا كتابة، الخدمة ترفض الغياب نوعاً، 428 بعد الصلاحية والنطاق (مستأجر آخر ⇒ 404 بلا تسريب).
- `BuilderDraftOptimisticLockPostgresTest`: حُذف اختبارا «الكتّاب القدامى» (لم يعد مساراً)، وتحوّل اختبار المستأجرَين المتزامنَين إلى كتّاب بأساس صحيح وإعادة محاولة.
- نتيجة محلية: 82 ناجحاً (SQLite) و24 ناجحاً (PostgreSQL) لحزمة الصانع. الحزمة الكاملة تُفحص في CI (sqlite + pgsql).

## المخاطر
- كسر متعمَّد لأي عميل خارجي يحفظ بلا أساس (لا وجود له في المستودع؛ يُخطَر بـ428 واضح).
- لا هجرة، لا نشر.
