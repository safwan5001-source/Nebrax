# S04a — الثيم الحيّ في Flutter (AD-03، الجانب الجهازي)

**القرار:** AD-03 (معتمد): رموز مسطّحة قانونية داخل `theme.tokens` + مرادف قديم مقروء فقط + Flutter يطبّق ثيم **التجربة الحيّة**. **بلا تغيير في شكل المخطط، بلا هجرة، بلا API.** اختبارات Dart كُتبت أولاً (ثبتت حمراء) ثم التنفيذ.

## ما نُفِّذ
- `mobile/lib/app/theme_tokens.dart`: `seedColorFromTokens` (أول قيمة **صالحة** بترتيب `colorPrimary` ثم `primaryColor`، وإلا لون العلامة الافتراضي؛ لا يرمي أبداً)، و`themeDataFor`.
- **THM-01 — لون التاجر يصل إلى التطبيق الحقيقي:** الصدفة (`AwjRuntimeShell`) تُبلّغ `onThemeTokensChanged` فور حسم قرار الإقلاع بـ`theme.tokens` للتجربة **الحيّة** (منشورة أو آخر نسخة سليمة)، و`AwjMobileRuntimeApp` يعيد بناء `ThemeData` منها. التجربة الافتراضية/غير المتاحة/قيد الحل ⇒ الثيم المضمَّن كما كان؛ الثيم عرضي ولا يعتمد عليه الإقلاع.
- **THM-09 — المعاينة تتبع المسودة:** `PreviewRuntimeView` يعرض الـ`ExperienceView` تحت `Theme` مشتق من رموز اللقطة (كان لون المضيف جامداً).
- `themeSeedColorFromSchema` (قائم) يستعمل المحلّل نفسه فلا تغيّر دلالته للمخطط المضمَّن.

## سلوك «المفاتيح الجديدة» (مدخل AD-02/S05) — مثبَّت باختبار
- مفاتيح جديدة **داخل `theme.tokens`** (`colorSecondary`، `brightness`، `radius.card`…) **يقبلها** Runtime الحالي (الخريطة نصية حرّة) ⇒ إضافتها آمنة للأجهزة القديمة.
- مفتاح جديد **على مستوى `theme`** (`typography`…) **يرفضه** Runtime الحالي ⇒ لا يُضاف إلا بجيل Runtime جديد (S05) — لا يُرسَل مخطط غير متوافق.
- قيمة رمز غير نصية مرفوضة.
