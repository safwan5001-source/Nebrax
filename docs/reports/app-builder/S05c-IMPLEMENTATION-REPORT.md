# S05c — النسخة الحيّة `live_version_id` + التراجع + ETag (AD-06)

**الحالة:** منفَّذة، مغلقة افتراضياً خلف بوابة نشر. **لا تغيير في أي نسخة حيّة فعلية** (البوابة `APP_BUILDER_LIVE_POINTER_ENABLED=false`، ولا هجرة بيانات).
**يعالج:** DRF-05 (جزئياً: الخادم)، DRF-10 (ETag من جهة الخادم)، SEC-02 (موثَّق أدناه). **لا يعالج بعد:** الأرشفة (DRF-08 ← S05d)، استهلاك Flutter لـ`If-None-Match`، واجهة المحرر.

## ما بُني
| البند | التفصيل |
|---|---|
| المخطط (إضافي) | `builder_live_pointers` (فريد لكل مستأجر+قناة، مراجع `restrict` على النسخة والتطبيق) و`builder_live_pointer_events` (تدقيق ثابت: promote/rollback، من/إلى، الفاعل، السبب). لا تعديل لأي جدول قائم، `down()` يسقط الجدولين. |
| الخدمة | `BuilderLivePointerService` السلطة الوحيدة: `promote` و`rollback`، معاملة، ترتيب أقفال **التطبيق ← المؤشر**، إنشاء كسول للمؤشر بـ`insertOrIgnore` دون سباق، idempotent (ترقية الحيّة نفسها لا تنتج حدثاً)، تحقق أن النسخة تُرندَر على جيل Runtime معروف (وإلا 422). التراجع الافتراضي يقرأ هدفه (آخر حدث) ثم يتحقق بعد القفل أن المؤشر لم يتحرك (`pointer_changed` ⇒ 409). |
| القناة | قناة الجوال النشطة المعتمدة للمستأجر (`MobileSalesChannelResolver::canonicalForTenant`)؛ لا يُقبل معرّف قناة من العميل. بلا قناة ⇒ 422. |
| الإدارة | `GET app-builder/live` (`apps_builder.view`)، `POST app-builder/apps/{id}/versions/{n}/promote` و`POST app-builder/live/rollback` (`apps_builder.publish` — يغيّر ما يراه العملاء)، كلها مع بوابة قدرة `commerce.app_builder`. «نشر وتفعيل»: `promote:true` على `POST versions` ذرّياً (فشل التفعيل يتراجع معه النشر). |
| التقديم | مع البوابة مفتوحة ومؤشر للقناة: **المؤشر سقف** — أعلى نسخة تُرندَر على جيل الجهاز من تطبيق المؤشر برقم ≤ الحيّة (AD-02 باقٍ). فنشر لاحق أو تطبيق آخر لا يستبدل الحيّ، والتراجع يعني ألا يُخدَم ما بعد الحيّة. جهاز قديم لا يرندر الحيّة ولا أقدم منها ⇒ 404 (التجربة الافتراضية)، لا تجربة تطبيق آخر. |
| ETag | `"<معرّف النسخة المختارة>-<جيل Runtime>"` + `Cache-Control: private, no-cache` (إعادة تحقق دائمة فيصل النشر فوراً) و`If-None-Match` المطابق (قائمة، `*`، `W/`) ⇒ 304 بلا حمولة. الترويسة تُضاف دائماً (إضافية لا تكسر أحداً؛ عميل Flutter الحالي لا يرسل `If-None-Match` فلا يرى 304 أبداً). |

## التوافق والبوابة (قاعدة 6: سياسة تُضبط لا تُفرض)
- البوابة `config('app_builder.live_pointer_enabled')` مغلقة ⇒ نقاط الإدارة 404 و`GET experience` على السلوك المؤقت **حرفياً** (أحدث نشر عبر تطبيقات المستأجر). مفتوحةً وبلا مؤشر للقناة ⇒ السلوك القديم نفسه حتى تُرقّى نسخة صراحةً (لا انقطاع تجربة عند فتح البوابة قبل الهجرة). إعادة إغلاقها تعيد الانتقاء القديم ولو وُجد مؤشر.
- **مؤجَّل صراحةً:** سكربت هجرة المستأجرين «آخر نسخة ⇒ المؤشر» (أمر تشغيلي بقرار تفعيل منسَّق، افتراضه معاينة بلا كتابة)، لأن كتابة مؤشرات لمستأجرين حيّين تغيّر ما يُخدَم دون تفويض.
- **SEC-02:** `GET commerce/v1/experience` بلا بوابة تطبيق `commerce.app_builder` **مقصود**: يُقرأ بمفتاح عميل API للجوال وقناة جوال نشطة، ومنشورٌ قائم لا يجوز أن يختفي من جهاز بتعطيل أداة التأليف. (القرار موثَّق هنا؛ حراسته: المسار خلف `AuthenticateApiClient` + `ResolveCommerceChannel` فقط.)

## الاختبارات (`BuilderLivePointerTest`، 21)
بوابة مغلقة (404 + قديم)، تثبيت الحيّ رغم نشر أحدث، تطبيق ثانٍ لا يسرق الحيّ، السقف، بلا مؤشر = قديم، إعادة إغلاق البوابة، تراجع + تدقيق، 409 بلا هدف، idempotent، نسخة غير قابلة للرندر 422، بلا قناة 422، عزل المستأجر، RBAC، ETag/304 (قائمة/ضعيف/تغيّر عند نشر جديد/لكل جيل)، نشر+تفعيل ذرّي (ومرفوض مع بوابة مغلقة ولا يترك نسخة)، تعارض `pointer_changed`، ثبات الأحداث.
**فحوص طفرات:** إزالة السقف، إزالة مرشّح التطبيق، وإزالة فحص البوابة — كلها تُفشل اختباراً.

## مخاطر معلنة
- سباق تفعيل: مغطى بالأقفال وبـ`pointer_changed`؛ لا اختبار pgsql متعدد العمليات لهذه الشريحة (الأقفال من النمط المُختبَر نفسه في `BuilderDraftOptimisticLockPostgresTest`).
- لا شيء يغيّر قيوداً محاسبية أو ZATCA أو صلاحيات خارج `apps_builder.*`.
