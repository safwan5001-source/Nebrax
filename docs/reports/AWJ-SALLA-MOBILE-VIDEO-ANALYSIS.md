## 3) تحليل UX/UI لتجربة الجوال

### 3.1 ما ينجح (ملاحظ)

1. **نموذج ذهني واحد:** «قائمة عناصر» ثم «تعديل عنصر». لا لوحة رسم حر. التاجر لا يرى شجرة ولا أسماء تقنية.
2. **اختيار بصري من كتالوج مغلق:** اثنا عشر نوعاً بمعاينة واقعية لكل نوع [م]. التاجر يختار بالعين لا بالاسم.
3. **تسلسل واضح لثلاث طبقات:** الشريط (7 مجموعات) ثم قائمة المجموعة ثم صفحة الإعدادات. كل صفحة فرعية بترويسة ثابتة «أنت الآن تخصّص» + اسم القسم + سهم رجوع [م].
4. **إفصاح تدريجي حقيقي:** مفتاح التبديل «افتراضية/مخصصة» يبدّل المعاينة والحقول فوراً قبل أي حفظ [م]، ومفتاح «تخصيص رساله التقييم» يتحكم بالحقول.
5. **بطاقة «معاينة العنصر» في كل صفحة إعدادات** تقلل الحاجة إلى معاينة كاملة.
6. **نصوص مساعدة بالمقاس المطلوب** بجانب كل رافع صورة (1200×612 وغيرها) تمنع الخطأ قبل وقوعه.
7. **رافع صورة متكامل:** معاينة + اسم + حجم + تقدّم + حذف + قص + شارة «الأساسية».
8. **حالات تحميل مدروسة:** هياكل رمادية وأقسام تظهر تدريجياً.
9. **ورقة سفلية لإجراءات العنصر** (إخفاء/تكرار/إعادة تسمية/حذف) بدل أزرار كثيرة في الصف [م].
10. **شارة اللغة «AR»** في كل حقل نصي: بنية متعددة اللغات من أول يوم.
11. **اتجاه RTL كامل** (المقابض والأيقونات يميناً، الشيفرون يساراً، الرجوع يميناً).

### 3.3 المعاينة: نموذجان عند سلة

1. **معاينة العنصر:** صورة ثابتة داخل كل صفحة إعدادات (نموذج للنوع، لا تتغير بحسب الإدخال، ومع ذلك تتبدل فوراً عند تبديل نمط العرض).
2. **معاينة الجهاز الحي:** صفحة كاملة بإطار آيفون، ببث لتطبيق فعلي (يبدو مستضافاً خارجياً [ا])، وزر «تحديث المعاينة» بثلاث حالات: مفعّل، معطّل أثناء التحميل، مضغوط.

### 4.1 تجربة الاستخدام

| المحور | سلة (الفيديو) | أَوْج الحالي | الحكم |
|---|---|---|---|
| نموذج التحرير | قائمة عناصر + نماذج إعدادات | شجرة مكوّنات تقنية (Page/Section/Text) + Inspector مبني على السجل | **يحتاج تبسيطاً جوهرياً** |

| نماذج الإعدادات | حقول بنصوص مساعدة ومقاسات وأمثلة | حقول مبنية على السجل بلا نصوص مساعدة أو مقاسات | يحتاج UX (بلا تغيير عقد) |
| الصور | رافع كامل | حقل رابط نصي فقط؛ واجهات الوسائط في الخادم غير موصولة | **فجوة** (يحتاج ربط الوسائط) |
| الحفظ | زر لكل صفحة بلا تحذير | حفظ يدوي + `beforeunload` فقط + لا قفل تفاؤلي | **أَوْج أقوى** في النسخ والنشر؛ ويحتاج حفظاً أوضح (P0-2/P0-3) |
| النشر والتراجع | غير مشاهَد | تحقق + نشر بصلاحية مستقلة + نسخ غير قابلة للتعديل + استعادة | **أَوْج موجود ومتقدّم**، نحافظ عليه |
| الأدوات المتقدمة | غير مشاهَدة | تراجع/إعادة، طبقات، ربط بيانات، شرط ظهور | يبقى في الوضع المتقدم |

| القفل بالباقة | إشعار متأخر | `Plans`/`PlanGate` موجودان في ERP؛ ربطهما بالباني غير مؤكد | يُصمَّم أفضل (القفل قبل الدخول) |

### 4.2 مطابقة أنواع سلة مع ما يمكن لأَوْج اليوم

> **تنبيه:** هذا تقدير [ا] من الجرد؛ لم أتحقق من خيارات `query.sort` ولا من سلوك كل مكوّن في Flutter.

| نوع سلة | ما يلزم | ما يتوفر في أَوْج | الفئة |
|---|---|---|---|
| منتجات متحركة | قائمة منتجات أفقية | `ProductList` أفقية + ربط `commerce.products` + `ProductCard` | **يمكن إعادة استخدامه** |
| منتجات ثابتة | شبكة منتجات | لا شبكة (القائمة أفقية فقط) | يحتاج مكوّناً/نمطاً جديداً |
| خلفية المتجر / بانر عريض | صورة + نص + رابط | `Image` (https، 16:9 ثابت) + `Button`/`NavigationTarget` + `navigate` (home/cart فقط) | **جزئي** |
| صور متحركة (سلايدر) | كاروسيل | غير موجود في أي طبقة | **مكوّن Runtime جديد** |
| قائمة عناصر (تصنيفات بالصور) | شبكة + ربط تصنيفات | لا شبكة، والتصنيفات غير مدعومة في Flutter | **Runtime + API** |
| عداد العروض | مؤقت تنازلي | غير موجود | **مكوّن جديد** |
| المدونة / آراء العملاء / فيديو يوتيوب | محتوى وفيديو | غير موجود | **مكوّنات جديدة** |
| مميزات المتجر | أيقونة + عنوان + وصف | يمكن تركيبها نصاً بلا أيقونات | جزئي (مكوّن أيقونات) |
| طلبات سابقة | دخول عميل + طلبات | لا شاشة دخول ولا طلبات | **Runtime + API** |

### 4.3 المجموعات الجامعة (الشريط الجانبي) مقابل أَوْج

| مجموعة سلة | حالة أَوْج | ما يلزم |
|---|---|---|
| الصفحة الرئيسية (قائمة عناصر) | غير موجود كتجربة | طبقة الوضع السهل فوق الصفحات الحالية |
| التصنيفات | غير مدعومة في Flutter (`commerce.categories` غير معلن) | Runtime: ربط ودعم شاشة تصنيفات |
| صفحة المنتج | شاشة المنتج Native لا مخططية | Runtime: خيارات صفحة المنتج |
| الشريط العلوي والتبويبات السفلية | **غير موجودة في السجل ولا المخطط ولا Flutter** | عقد مخطط + Runtime + سجل جديد |
| الشريط الإعلاني | غير موجود في أي طبقة | مكوّن/عقد جديد |
| شاشات البداية والترحيب | غير موجودة (الـ splash أصلي ثابت) | عقد + Runtime |
| الإعدادات العامة (الألوان، الخط، الداكن) | الواجهة تكتب رموزاً ولا يستهلكها التطبيق | **P0-1** ثم Runtime |

## 6) توصيات أولية للوضع السهل (اقتراحات، غير معتمدة)

> كل ما يلي [ا] اقتراح مني. لا شيء منه ملزم أو مبني.

1. **بنية معلومات من أربعة مكوّنات فقط:** (أ) قائمة «أقسام الصفحة الرئيسية» بسحب وورقة إجراءات، (ب) كتالوج أقسام بمعاينات، (ج) صفحة إعدادات لكل قسم بنماذج قصيرة ونصوص مساعدة، (د) شريط مجموعات للإعدادات العامة (الهوية، التنقل، الصفحات، الإعدادات).
2. **ابدأ من التجربة الافتراضية الحيّة** (Home + Cart مرتبطتان بالبيانات) لا من قالب فارغ؛ فالتاجر يجد تطبيقاً جاهزاً عند الإنشاء.
3. **كتالوج بثلاث حالات صريحة:** «جاهز» (قابل للبناء اليوم)، «مقيّد» (يحتاج تطوير Runtime)، «مقترح» (غير مبني). لا يظهر نوع غير مدعوم كأنه جاهز.
4. **المعاينة المتجاورة لأَوْج هي الميزة التنافسية:** حافظ على الإطار الفوري، وأضف في الجوال معاينة بملء الشاشة بزر واضح، و«معاينة على الجوال» كمسار منفصل.
5. **نمط حفظ واحد:** شريط سفلي ثابت بحالات (لا تغييرات / غير محفوظ / يحفظ / محفوظ)، وتحذير عند الخروج، مع إبقاء النشر زراً مستقلاً بصلاحية `apps_builder.publish`.
6. **القفل بالباقة قبل الدخول** (شارة على بطاقة الكتالوج)، لا إشعاراً متأخراً.
7. **نصوص مساعدة بالمقاسات** من السجل نفسه، وحقول مقاس الصور مرتبطة بقيود Runtime الفعلية.
8. **ترتيب بناء مقترح للمراحل (للنقاش):** المرحلة 0 (متطلبات أساسية)، ثم شريحة الوضع السهل فوق المكوّنات الحالية (أقسام منتجات، صورة/بنر بسيط، نصوص، أزرار)، ثم مكوّنات Runtime بحسب القيمة (بنر/سلايدر، تبويبات سفلية، شريط علوي، تصنيفات)، وأخيراً الحساب والطلبات.
9. **لا تنسخ بنية سلة حرفياً:** استعِر المبادئ (قائمة، كتالوج مرئي، إفصاح تدريجي)، وحافظ على هوية أَوْج وسياساتها (قاعدة 6: السياسة تُضبط ولا تُفرض).

## 7) المتطلبات التقنية والمخاطر

### 7.1 متطلبات تقنية (تتقاطع مع Phase 0)

| المتطلب | سببه |
|---|---|
| **عقد رموز الثيم** (`colorPrimary` والمصدر المنشور) قبل «الهوية والألوان» | وإلا يغيّر التاجر اللون ولا يتغيّر التطبيق (P0-1) |
| **قفل تفاؤلي للمسودة** | وضعان وربما مستخدمان على مسودة واحدة (P0-2) |
| **كل Preset ينتج مخططاً صالحاً** لدى المحلل والمطابقة | المحلل يرفض أي مفتاح غير معروف؛ لا مكان لبيانات خاصة بالمحرر في المخطط |
| **اشتقاق أنواع الأقسام من بنية الشجرة** (تعريف الـ Preset من شكله) أو تخزينها خارج المخطط | حفاظاً على سلامة الذهاب والعودة بين الوضعين |
| **كتلة «متقدمة» مقفلة** لأي عقدة لا يمثلها الوضع السهل | لا فقد بيانات عند التبديل |
| **تفضيل الوضع لكل تطبيق:** عمود جديد nullable + توسيع `PATCH apps/{id}` | لا مكان في المخطط (Decision Gate) |
| **ربط الوسائط** (واجهات `CommerceMedia*` غير موصولة) | رافع الصور في الوضع السهل |
| **نموذج محتوى متعدد اللغات** | شارة AR في كل حقل نصي عند سلة |
| **اختبارات الذهاب والعودة** بين الوضعين | شبكة الأمان الحالية لا تغطيها |

### 7.2 مخاطر

| الخطر | الأثر | التخفيف المقترح |
|---|---|---|
| **وعد واجهة لا يفيه Runtime** (ألوان، صفحات، تبويبات) | تاجر يضبط ولا يرى أثراً | وسم «جاهز/مقيّد/مقترح»، وحسم P0-1 أولاً |
| **تمدّد النطاق نحو Runtime كامل** (تبويبات، تصنيفات، حساب، طلبات) | عمل كبير متعدد الطبقات | شرائح، وكل مكوّن جديد بقرار Decision Gate |
| **فقد بيانات عند التبديل بين الوضعين** | تلف تصميم | قاعدة «لا يُسقط شيء»، كتل متقدمة محفوظة، اختبارات round-trip |
| **كتابة متزامنة** | آخر كاتب يفوز | P0-2 |
| **معاينة غير أمينة** (الكانفاس يتجاهل صوراً ورموزاً) | ثقة منخفضة بالمعاينة | P0-6، ووسم مستويات الحقيقة |
| **استعارة أكثر من اللازم من سلة** | مخاطرة تتعلق بالهوية/الأصول | نسخ المبادئ لا الأصول؛ تصميم أَوْج مستقل |
| **اعتماد على بيانات لا تُشاهَد** (سلوك الحفظ والنشر عند سلة) | قرارات UX مبنية على تخمين | تصوير البنود 2–6 في §5 قبل تثبيت التصميم |
| **تحميل بطيء للمعاينة الحية** (نموذج سلة) | إحباط | لا نقلّده: نحافظ على المعاينة الفورية |
| **مسار الصوت غير محلَّل** | فقدان شرح منطوق | إرسال نص الشرح إن وُجد |
