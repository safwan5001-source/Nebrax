# AWJ App Builder — Phase 0: متطلبات أساسية قبل الوضع السهل

> **الحالة:** توثيق فقط. **لا شيء هنا مُنفَّذ أو معتمد للتنفيذ.** كل بند يتطلب موافقة المالك الصريحة وDecision Gate مناسباً قبل أي عمل.
> **المصدر:** `AWJ-APP-BUILDER-CURRENT-STATE.md` (§2 و§7 و§9). درجات الدليل [م] تحقق مباشر، [و] تقرير وكيل قراءة فقط يُعاد فحصه قبل البدء.
> **القرار المعتمد من المالك:** تُوثَّق المشكلات المؤكدة كمتطلبات أساسية **دون إصلاحها الآن**.

## لماذا Phase 0

الوضع السهل يعد التاجر بنتيجة مرئية (ألوان، صفحات، أقسام). إن لم تُحسم هذه البنود، يعد المحرر بما لا يصل إلى التطبيق الحقيقي، أو يفقد تعديلات، أو يفشل النشر دون تفسير.

## متطلبات تخص الوضع السهل نفسه (قرارات مرتبطة، غير مبنية)

| المتطلب | ملاحظة |
|---|---|
| تفضيل وضع التحرير لكل تطبيق | لا عمود إعدادات في `builder_apps` ولا مكان في `schema` (يرفض المفاتيح غير المعروفة). الخيار على الخادم: هجرة بعمود nullable + توسيع `PATCH apps/{id}`. يُدرس أثره مع P0-2. التبديل لا يؤثر على المنشور، فتكفي `apps_builder.manage` |
| بيانات خاصة بالمحرر | لا مكان لها في `schema`؛ تُشتق من بنية الشجرة أو تُخزَّن خارجه |
| فئات/حساب/طلبات/دخول | لا موجِّه صفحات عاماً في Flutter (`navigate` يقبل `home`/`cart` فقط [م])؛ لا شاشات ولا واجهة دخول. تُوسَم «مقترح/غير مدعوم» في التصور حتى قرار Runtime |
| بنر، كاروسيل، تبويبات سفلية، شريط علوي، شبكة منتجات | غير موجودة في السجل ولا المخطط ولا Flutter [م]. دراسة مكوّنات Runtime جديدة جزء من التصور، وتنفيذها يحتاج Decision Gate |

## ترتيب مقترح (للنقاش فقط)

1. **ما لا يغيّر عقداً:** P0-3، P0-5، P0-6، P0-7، P0-9. يمكن تقييمها كشريحة واجهة صغيرة لاحقاً.
2. **ما يحتاج Decision Gate:** P0-1، P0-2، P0-4، P0-8، وتفضيل الوضع. تُعرض كل واحدة على المالك قبل التنفيذ مع خيارات وتوصية.
3. **بوابة الدخول إلى الوضع السهل:** لا يبدأ تطوير الوضع السهل قبل حسم P0-1 وP0-2 على الأقل.

## ما لن يُنفَّذ بدون موافقة صريحة

تطوير الوضع السهل، أي تغيير في `AppSchema`، أي تغيير في Flutter Runtime، أي هجرة أو تغيير في قاعدة البيانات، أي تغيير في عقود API.
