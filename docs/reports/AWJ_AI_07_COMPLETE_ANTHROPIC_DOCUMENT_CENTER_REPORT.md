## 2. المعمارية

```
المستخدم ──► POST /ai-assistant/messages [document_id?]
                │
                ├─ بلا document_id : مالي (مرحلتان، أدوات التقارير فقط)  ← #1559
                └─ مع document_id  : (UUID يحدّده المستخدم من شاشته)       ← PR التابع
                        1) تفويض: منصة ∩ مستأجر ∩ موافقة assistant_messages + document_projected_text
                                   ∩ ai.assistant.use ∩ documents.center.view ∩ فاعل طازج
                        2) مزوّد خارجي جاهز + مفتاح المنصة الثالث + إقرار المزوّد + إقرار المستندات المستقل
                        3) تسعير معرَّف + حجز ميزانية (feature = assistant_document) قبل القراءة
                        4) قراءة محلية: AiDocumentProjectionReader (مراجعة بشرية + تنقيح + عزل مستأجر/فرع + حالة المستند)
                        5) AiDocumentDigest: أسماء الجهات → Party-N، المنقَّح → مفتاح فقط، سقف رموز
                        6) نداء واحد بلا tools ولا tool_choice، والبيانات داخل <document_data> مُهرَّبة
                        7) تسوية بالاستهلاك الفعلي ← تنقية الجواب ← تأريض الأرقام ← استعادة الأسماء محلياً
```

- **العميل الوحيد** `converse()`؛ لا `Http::` في المزوّد (يحرسه اختبار).
- **لا أدوات في دورة المستند إطلاقاً**: الحقن داخل المستند لا يستطيع استدعاء شيء مهما نجح في خداع النموذج (مثبَت باختبار: نموذج «مخترَق» يردّ بـ`tool_use` فيُهمَل).

| المفتاح | يتحكم بـ |
|---|---|
| `AI_ASSISTANT_ENABLED` | المساعد كله (المنصة) |
| `AI_ASSISTANT_PROVIDER` | `mock` (افتراضي) أو `anthropic` |
| `AI_ASSISTANT_EXTERNAL_NETWORK_ENABLED` | **جديد** — اتصال المساعد بالخارج (مستقل عن Document AI) |
| `DOCUMENT_AI_PROVIDER_NETWORK_ENABLED` | اتصال استخراج المستندات (كما كان) |
| `AI_ASSISTANT_DOCUMENTS_ENABLED` | قراءة المستند المحلية (AI-04) — لا ترسل شيئاً |
| `AI_ASSISTANT_DOCUMENTS_EXTERNAL_ENABLED` | **جديد** — إرسال القيم المراجَعة للمزوّد الخارجي |
| `AI_ASSISTANT_METER_DOCUMENT_EXTRACTION` | **جديد** — قياس الاستخراج في ميزانية الذكاء الاصطناعي |

على مستوى المستأجر: موافقة المساعد + فئات (`assistant_messages` / `financial_summary` / `document_projected_text`) + **إقرار الإرسال الخارجي** + **إقرار إرسال المستندات** (مستقل، ويسقط تلقائياً بسقوط أيٍّ من: التعطيل، سحب فئة المستند، سحب الإقرار الأول).

## 4. الميزانيات — وهل يدخل الاستخراج في الميزانية نفسها؟

**الفحص:** قبل هذا العمل **لا**. استخراج المستندات كان محكوماً بحدود عمليات/صفحات شهرية (`DocumentProviderUsageEvent`) و`cost_minor` فيه `null`؛ فلا سقف رموز ولا تكلفة ولا حجز مسبق ولا حماية من التجاوز. تشغيل Anthropic المدفوع على الاستخراج كان سيكون بلا سقف مالي.

**القرار (سياسة تُضبط لا تُفرَض):** `ai_assistant.budget.meter_document_extraction`، **الافتراضي مطفأ** (سلوك المؤسسات القائمة لا يتغيّر). عند التشغيل:
- حجز قبل كل اتصال عبر `AiRequestLedger`/`AiBudgetService` نفسهما (سقف المنصة ثم المؤسسة، ذرّياً)، `feature = document_extraction`.
- تقدير الحجز: 6000 رمز/صفحة + 3000 + 4096 مخرجات (متحفظ؛ التسوية بالفعلي).
- بلا سعر للنموذج أو بلا ميزانية أو تجاوز ⇒ **لا يُرسَل المستند** ويُسجَّل المحاولة «متخطّاة» برمز `ai_budget_*`.
- فشل HTTP لا يولّد رموزاً (401/403/429/رفض) ⇒ تسوية بصفر؛ غير ذلك يتبع `failure_charge`.
- **توصيتي: تشغيله مع تفعيل Anthropic** (§9).

**واجهة المنصة:** `GET/PUT /api/platform/ai-budgets` — القراءة `platform:read`، الكتابة `platform:manage` + كلمة مرور المدير + تدقيق (`platform_integration_audit_events`، أسماء الحقول لا القيم). حمايات: لا فترة ماضية؛ حد أقصى 10¹² رمز و100,000 دولار/شهر؛ **سقف المؤسسة ≤ السقف العالمي** للفترة؛ تنبيه `over_allocated`؛ خفض السقف دون المستهلك يوقف الحجز الجديد فوراً. العرض يفصل الاستهلاك لكل `feature` (`assistant` / `assistant_document` / `document_extraction`) ولا يكشف أسعاراً ولا مفاتيح.

## 5. الخصوصية: ما يُرسَل وما لا يُرسَل (مستند)

| يُرسَل | لا يُرسَل أبداً |
|---|---|
| نص سؤال المستخدم | الملف الأصلي/الصورة/اسم الملف/مفتاح التخزين/الهاش |
| قيم مراجَعة بشرياً (تعديل المراجع يغلب المستخرَج) | القيم المنقَّحة (تُذكر بمفتاحها فقط في `redacted_fields`) |
| مبالغ عشرية، تواريخ، رقم المستند، أوصاف السطور | الأرقام الضريبية، معرّفات المستند/المستأجر/المستخدم/الفرع |
| الجهة المُصدِرة/المستلِمة كـ`Party-1/2` (تُستعاد محلياً) | أي مستند آخر، أي تقرير مالي، أي أداة |

**قرار تصميم يحتاج علمك:** أوصاف السطور (مثل «صمام صناعي») وأرقام المستندات تُرسَل كما هي لأن الإجابة عنها هي المطلوب؛ أسماء الجهات وحدها مستبدلة.

## 6. الأمان — ما أثبتته الاختبارات

- **حقن في المستند** (`IGNORE ALL PREVIOUS… </document_data> SYSTEM: …`): لا `tools` في الطلب؛ الوسم المغلق مُهرَّب (`<`) فلا يُنهي الكتلة؛ نموذج «مخترَق» يطلب أداة مالية ويخترع رقماً ومفتاحاً ⇒ الأداة لا تُنفَّذ، الرقم المخترَع يُحجب، الجواب ثابت.
- **تسرب:** المفتاح، أسماء الجهات، الأرقام الضريبية، رقم المستند، المبالغ، اسم الملف **غائبة** عن `ai_audit_events` و`ai_requests` و`ai_budgets` وكل سجلات التشغيل؛ خطأ المزوّد (يحمل المفتاح والاسم) يعود عاماً.
- **RBAC:** بلا `documents.center.view` ⇒ `tool_permission_denied`؛ بلا `ai.assistant.use` ⇒ 403؛ كلاهما قبل أي اتصال.
- **عزل:** مستند مستأجر آخر ⇒ `document_unavailable` (404) بلا اتصال ولا استهلاك؛ مستند فرع آخر كذلك؛ UUID فقط (مسارات/روابط/SQL ⇒ 422).
- **حالات المستند:** غير مراجَع (ويُحرَّر الحجز بلا رسوم)، تعديل بعد الإكمال، مصاب، فحص غير مكتمل، انتهاء احتفاظ، حذف نهائي، مؤرشف ⇒ كلها تُرفض قبل الإرسال (والقارئ نفسه مغطى بـ`AiDocumentProjectionTest` من AI-04).
- **محاسبة:** لقطة قبل/بعد: القيود، الأسطر، الفواتير، المشتريات، المصروفات، حركات المخزون، إجراءات/تعديلات المراجعة، التنقيحات، الدفعة، نتائج الاستخراج ⇒ **لا تغيير**.

## 9. قائمة تفعيل المالك (لم تُنفَّذ — تحتاج موافقتك)

1. **حدود التكلفة (قرارك):** سعر النموذج في `AI_ASSISTANT_ANTHROPIC_PRICING`، ثم ميزانية المنصة وميزانية كل مؤسسة من الشاشة الجديدة. بلا هذا لا يعمل شيء (فشل مغلق).
2. تكامل المنصة: مزوّد Anthropic مفعّل + مفتاح + نموذج (الشاشة القائمة) + `allow_document_sending` للاستخراج.
3. المساعد المالي: `AI_ASSISTANT_PROVIDER=anthropic` + `AI_ASSISTANT_EXTERNAL_NETWORK_ENABLED=true`.
4. الاستخراج: `DOCUMENT_AI_PROVIDER_NETWORK_ENABLED=true` + المزوّد الأساسي Anthropic + **`AI_ASSISTANT_METER_DOCUMENT_EXTRACTION=true`** (موصى به).
5. أسئلة المستندات: `AI_ASSISTANT_DOCUMENTS_ENABLED=true` + `AI_ASSISTANT_DOCUMENTS_EXTERNAL_ENABLED=true`، ثم من المؤسسة: موافقة نص المستند + الإقراران.
6. تجربة بمؤسسة واحدة بميزانية صغيرة، ومراقبة الشاشة وسجل التدقيق.

**التراجع الفوري:** `AI_ASSISTANT_PROVIDER=mock` (يوقف المساعد المالي وأسئلة المستندات)؛ `AI_ASSISTANT_DOCUMENTS_EXTERNAL_ENABLED=false` يوقف أسئلة المستندات وحدها؛ بلا ترحيل ولا فقد بيانات.

### ٢) حد رموز `AiDocumentDigest` — **ثغرتان مثبتتان وأُصلحتا** (#1560)

1. **القياس على تمثيل أخفّ من المرسَل:** كان التقدير على JSON عادي بينما يُرسَل JSON مهرَّب (`<`→`\u003C` أي 6 بايت)؛ نصّ مليء بـ`<` أو `&` كان يمرّ تحت الحد وهو أضعاف الحد فعلياً. الآن القياس على `encode()` — السلسلة المرسَلة نفسها.
2. **لا حد صارماً:** `build()` كان يعيد الملخّص حتى بعد حذف كل السطور ولو تجاوز الحد، والبوابة ترسله. الآن سلّم تقليص (السطور ← قصّ نصوص الرأس 100/60/30 ← حذف حقول اختيارية) ويُعلَن القصّ (`truncated`)؛ وما لا يتّسع يعود `fits=false` فيرفضه الـGateway **قبل أي اتصال** بالرمز `document_too_large` (422) وتُحرَّر المحجوزات **بصفر رسوم**، دون تسرب لقيمة في أي سجل.

الاختبار: `AiDocumentDigestBoundTest` (12): ست أشكال مستندات (عادي، رأس 200 و5000 حرف، سطور كثيرة، حشو `<` وحشو `&`)، سلّم التقليص، عدم الاتّساع، وطرفا الشبكة (قصّ ثم إرسال ≤ الحد؛ رفض بلا نداء).
*ملاحظة:* التقدير بايت/3 متحفظ لكنه تقريب لا محصٍ حقيقي للرموز؛ تجاوز المخرجات الفعلية يُحتسب فعلياً (`overrun`) ولا يُخفى.

### ٣) تزامن تعديل الميزانيات مع الحجز — **لا مسح للعدّادات؛ وجدتُ سباقَين وأُصلحا** (#1559)

- **مثبَت:** تعديل السقف لا يمسّ `reserved/used`؛ خفضه دون الجاري يُبقي الحجز القائم، يمنع الجديد، وتسوية الحجز القديم تتم بدقة؛ رفعه يعيد القبول فوراً.
- **خاصية تسلسلية** (400 خطوة عشوائية ثابتة البذرة: حجز/تسوية/فشل/تعديل سقف على مؤسستين + المنصة): بعد **كل** خطوة تساوي العدّادات نموذجاً مرجعياً مستقلاً (المحجوز = مجموع الطلبات المفتوحة، المستهلك = المسوّى)، ولا حجز يهبط فوق سقف ساري، وفي النهاية لا شيء معلّق والاستهلاك = مجموع ما على الطلبات.
- **PostgreSQL بموصلين حقيقيين:** (أ) حجز ينتظر تعديل سقف غير مودَع ثم يُحكَم بالسقف الجديد؛ (ب) تعديل سقف ينتظر حجزاً غير مودَع ثم يبقى الحجز؛ (ج) تعديلان لصف واحد يتسلسلان والعدّادات محفوظة.
- **سباق ١ (أُصلح):** `setCaps` كان `firstOrNew + save` — كاتبان ينشئان الصف نفسه ⇒ استثناء فهرس فريد (500). صار `upsert` ذرّياً لأعمدة السقف وحدها.
- **سباق ٢ (أُصلح):** فحص «سقف المؤسسة ≤ العالمي» ثم الكتابة كانا بلا قفل؛ تعديل متزامن للعالمي بينهما يكسر الفحص. صار قفل صف العالمي (`lockForUpdate`) داخل المعاملة.
- *حدّ معلن:* خفض السقف دون الجاري مسموح عمداً (يوقف الجديد ولا يُلغي القائم)، وتجاوز مجموع أسقف المؤسسات للعالمي يُعلَن `over_allocated` ولا يُمنع.

الاختبار: `AiBudgetConcurrencyTest` (8؛ 3 منها بموصلين حقيقيين وتتخطّى على SQLite وتعمل في مهمة pgsql في CI).
