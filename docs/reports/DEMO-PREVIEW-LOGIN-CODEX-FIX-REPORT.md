## 2. التعليق

> **P2 — Clear existing credentials before entering demo mode** (`demo-login-button.tsx:23`)
> مستخدم مصادَق يفتح `/login` ويضغط الزر: `enableDemo()` يكتب المستخدم وعلم المعاينة لكن **لا يزيل `token`**، فيبقى اعتماد مستأجر حيّ في `localStorage`، ويعود فعّالاً إذا مُسح علم المعاينة دون خروج كامل. المطلوب: مسح الجلسة الحقيقية قبل التفعيل واختبار يبدأ بتوكن موجود.

**التقييم: صحيح.** اختباري السابق «لا توكن» كان يبدأ من `localStorage` فارغ فلم يكشفه، وتقريري الأول كان يعلن «لا توكن» دون تغطية هذه الحالة. تصحيح الصياغة في التقرير الأول مرفق (§6).

مسار الضرر الفعلي: توكن حقيقي + علم `demo=true`. `api()` يفحص `isDemo()` أولاً فلا يُرسل التوكن ما دام العلم قائماً، لكن `isAuthenticated()` و`getToken()` يريانه، ومسح العلم وحده (`disableDemo()` أو أي مسار يمسحه دون `clearToken`) يعيد التوكن الحيّ فعّالاً مع مستخدم المعاينة المخزَّن.

## 3. الإصلاح

بالدوال القائمة، بلا آلية موازية:

```ts
clearToken();               // api.ts — token + user + demo
clearSessionPreferences();  // auth.ts — nibras_active_branch + demo (صار exported)
enableDemo();               // الموجود بلا تعديل
notifyAuthSessionChanged(); // يُعلم المستمعين (هوية الشركة، الصلاحيات)
router.replace('/dashboard');
```

| المطلب | التنفيذ |
|---|---|
| استخدام دوال التنظيف القائمة | `clearToken` و`clearSessionPreferences` — الأخيرة كانت خاصة فأُضيف `export` وحده (لا تغيير سلوك) |
| مسح token وuser والفرع النشط قبل التفعيل | بالترتيب أعلاه؛ اختبار يثبت أن التوكن مفقود لحظة كتابة علم `demo` |
| بلا Logout API | لا `logout()`؛ التنظيف محلي. (التوكن يبقى صالحاً في الخادم حتى انتهائه — مقصود، لا اتصال) |
| شرط `NEXT_PUBLIC_DEMO_PREVIEW=true` | بلا تغيير (`isDemoPreviewEnabled`) |

**الملفات:** `web/src/components/auth/demo-login-button.tsx` · `web/src/lib/auth.ts` (سطر `export` + تعليق) · `web/src/components/auth/demo-login-button.test.tsx` · `web/e2e/demo-preview-login.spec.ts`. لا Laravel ولا API ولا منطق `login()`/`logout()`.
