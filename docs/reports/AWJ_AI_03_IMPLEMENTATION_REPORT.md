## 2. What was delivered

### 2.1 Hybrid experience (one design, three surfaces)

| Surface | What it is | Where |
|---|---|---|
| **Contextual Assistant** | Side Sheet on the logical end (full-screen with a Back control on mobile). Opens from a topbar button (sm+) or the account menu (mobile). Shows the *current screen* (approved page metadata only), suggestions ordered for that screen, a composer (≤2000 chars, Enter/Shift+Enter), compact result summaries with **Open in Canvas** and **Open original report**. | `components/intelligence/assistant-panel.tsx`, `assistant-trigger.tsx`, `result-summary.tsx` |
| **Financial Intelligence Canvas** | Dedicated workspace `/intelligence`: explicit run of the three closed read-only tools (income statement, receivables aging, payables aging), dense SAR tables (cards on mobile for aging), evidence block (scope, basis, currency, time zone, read time, sources), warnings (incl. `as_of_not_historical`), run history of the session. | `intelligence-canvas.tsx`, `financial-result.tsx`, `income-statement-view.tsx`, `aging-view.tsx`, `evidence-panel.tsx` |
| **Consent & settings** | `/intelligence/settings` for owner/admin: master switch, per-category consent (messages / financial summaries; document text locked "AI-04"), privacy notice + explicit acknowledgement to grant, immediate revocation, optional metadata-only audit list for `ai.audit.view`. | `consent-settings.tsx`, `audit-activity.tsx` |

Navigation between surfaces: panel → Canvas (`Open in Canvas`, run stays active) → original report (`Open original report`) → browser Back returns to the Canvas with the run still in memory; the topbar button reopens the panel with the conversation intact. Sidebar entries `Financial Intelligence` (`ai.assistant.use`) and `Assistant settings` (`ai.consent.manage`).

### 2.2 Honest states (all derived from real server codes)

The UI never guesses. It reads `GET /ai-assistant/status` (fresh on every panel open / Canvas entry) and renders the server-computed `chat` / `financial` state; request errors are classified from the real `error.code` (`state.ts`). Covered: platform disabled · tenant disabled · consent required/revoked · permission denied · financial-tool permission denied · provider unavailable · currency unsupported · budget not configured / exceeded / platform budget exceeded / pricing unknown · invalid dates/scope · branch/warehouse scope forbidden · rate limited · duplicate request · network / server error · empty · loading · success. Mock is labelled **Demo** wherever the *mock provider* produced text; figures from the report tools are labelled as read from AWJ reports (not generated by the assistant). The Canvas carries a **Read-only** label, not Demo, because its figures are real.

### 2.3 Minimal backend (already on the branch, `ffdf5a5`)

| Endpoint | Purpose | Guard |
|---|---|---|
| `GET /api/ai-assistant/status` | Server-computed status for the current user (platform/tenant/consent/abilities/chat/financial/clock). No kill-switch secrets, keys, prices or budgets. | `ai.assistant.use` **or** `ai.consent.manage` **or** `ai.audit.view` (403 otherwise) |
| `PUT /api/ai-assistant/settings` | Tenant consent update. | new permission `ai.consent.manage` (owner/admin only) |
| `POST /api/ai-assistant/tools/run` | Explicit run of one closed finance tool (reuses the gateway's per-invocation gates: platform ∩ tenant ∩ consent ∩ fresh actor ∩ `reports.view`). No provider call, no budget spend. | `ai.assistant.use` |

Consent update (`AiAssistantConsentService`): single transaction with `lockForUpdate` on the tenant, closed schema (unknown field/category → 422, `document_projected_text` unavailable), granting needs platform enabled + `acknowledge_privacy`, revoking is always allowed and needs no acknowledgement, disabling clears every category, no-op writes skipped, a **required** `consent.updated` audit event (metadata: `consent_enabled`, `categories_granted`, `categories_revoked`) is written inside the same transaction (audit failure rolls the change back), effective on the next request (policy re-reads the tenant). Document Center's `allow_document_sending` is unrelated and untouched.

## 3. UI/UX decisions

| Decision | Reason |
|---|---|
| Panel for quick Q&A, Canvas for numbers | Tables and exact figures are the focus (DESIGN_SYSTEM.md); a 28rem sheet is the wrong place for a 6-column aging table. |
| Page context = screen kind (+ short id suffix) only, never sent | The server schema is closed and accepts no context field; nothing is read from the DOM. The chip says so in its tooltip. |
| Nothing financial is requested until the user clicks, and only when the freshly read status is `ready` | "Zero unauthorized financial requests" is enforced in the store (not just the view) and unit-tested for every blocked state. |
| In-memory state only, with a tenant‖user epoch | Tenant/user switch or logout wipes conversation and runs, and late responses from the previous identity are dropped; nothing is written to storage/analytics/logs (asserted by test). |
| Server `clock.today` drives default dates | Avoids browser/timezone guesses; client validation mirrors the server's rules (cosmetic, server stays authoritative). |
| Aging: table (sm+) / cards (mobile) | No horizontal scroll for financial figures on phones. |
| Warehouse never presented as a financial filter | Evidence block states "Warehouses: not applicable to financial totals" and labels `scope_kind: authorization` as "authorization scope, not a data filter". |
| Server-provided `ui_path` linked only if it is a same-origin app path | Defensive; unit-tested (`javascript:`, `//host`, query strings rejected). |
| Reused AWJ components only (Sheet, Dialog, Table, Badge, Switch, PageHeader, EmptyState/LoadingState, Money) | No new libraries or abstractions; tokens only, Default/Ink/Core × Light/Dark inherited. |

## 4. UX review of the 8 mandated journeys

Verified with Playwright against an intercepted API on desktop (1440×960) and a mobile viewport (390×844, touch emulation), by Vitest where stated, and by reviewing the screenshots.

| # | Journey | Result |
|---|---|---|
| 1 | Open assistant from a supported financial screen | OK. Desktop: topbar button, 1 click, composer focused. Mobile: account menu → item, 2 taps. Context chip shows "Income statement report". |
| 2 | Ask via existing gateway, see real/mock result with source/state | OK. Suggestion = 1 click; reply is labelled **Demo** with the "not a real AI analysis" note; the summary card shows the server's net income, warnings count, and source links. |
| 3 | Go to original report and return | OK. `Open original report` → report page; browser Back → Canvas with run intact; panel reopens with the conversation. |
| 4 | Missing consent / permission | OK. Admin sees the state + link to settings; member sees the state + "ask the owner/admin" (no link to a 403); user without `ai.assistant.use` gets no trigger and a direct URL shows a denial with **zero** `/ai-assistant/*` requests (asserted). |
| 5 | Panel ↔ Canvas | OK. `Open in Canvas` closes the panel and activates the run; Canvas has `Ask the assistant`; run history switches between runs. |
| 6 | Mobile | OK. Full width (≥388px), safe-area bottom padding, Back control and Send are ≥44×44 (asserted), no horizontal overflow on panel/canvas/settings (asserted), no bottom nav / stacked drawers. |
| 7 | Language / theme | OK. AR/EN (RTL/LTR) × Light/Dark + Ink/Core all rendered; theme toggle keeps the Canvas result; language switch reloads (state is memory-only by design). |
| 8 | Failure states | OK. Budget refusal and invalid/future dates (e2e); server error with retry and revoked consent mid-flight — state flips and the next click is blocked locally (Vitest). |

Defects found by this review and fixed before delivery:

1. **Focus was not returned to the opener** after closing the panel (Radix Sheet used without a Trigger) → opener captured on open and restored on close (e2e + unit test).
2. **First open left focus on a header button** because the composer is disabled while the status loads → focus deferred until `ready`; direct focus on re-open.
3. **Canvas showed a "Demo" badge over real figures** (misleading in the opposite direction) → replaced by a "Read-only" label; Demo remains only where the mock provider speaks.
4. **Tool names with dots used as message keys** (`finance.income_statement`) are invalid for next-intl → key-safe mapping + a guard test that fails on any dotted key in the namespace.
5. Topbar hook loop outside the provider (existing topbar test) → trigger split so nothing reads the user without the provider.
6. Duplicate accessible name "Report" (form + field) → form renamed "Report controls".
7. Awkward consent copy for enable-only → dedicated message.
8. Audit table overflowed on phones → time/reason folded under the event on <sm.
9. Message text direction for mixed AR/EN → `dir="auto"`; counter separated from the hint.
