## 1) الخلاصة التنفيذية (الحل الأفضل أولاً)

**لا نبني نظاماً رابعاً.** عندنا اليوم ثلاث قنوات؛ الخطة توحّدها تحت **عقد عمليات وكيل واحد** بدل إضافة قناة:

| القناة | ما هي | حالتها | دورها في الخطة |
|---|---|---|---|
| **A — Public API v1** (`/api/v1`) | M2M: مفتاح `ApiClient` + scopes مطابقة تامّة + Idempotency + Audit + حدود معدّل | قراءة/إنشاء: شركاء، منتجات، فواتير **مسودة**؛ كشف حساب طرف؛ Webhooks | **القناة الوحيدة للوكلاء الخارجيين** (باشت وغيره). تتوسّع بالقراءة والمسودات والتصدير |
| **B — AI Actions** (`AiActionGateway`) | سير عمل داخل التطبيق: رفع ← تحقق ← معاينة ثابتة بهاش ← اعتماد بشري ← تنفيذ ← إصلاح | منتج واحد فقط `product_import.v1`، مطفأ افتراضياً (`AI_ACTIONS_ENABLED=false`) | **محرّك الموافقات** لكل ما له أثر محاسبي (ترحيل/دفع): تُسجَّل فيه أنواع إجراءات جديدة، بلا آلة موافقات موازية |
| **C — مساعد أَوْج (قراءة فقط)** | `AiAssistantToolRegistry`: قائمة دخل، أعمار، إسقاط مستند | يعمل بضوابط موافقة/ميزانية | يستهلك **نفس كتالوج القدرات** والغلاف المتحقَّق منه للتقارير |

**الركائز الأربع للخطة:**
1. **الثقة المالية أولاً (H0):** غلاف تقرير متحقَّق حتمي من الخادم (إجماليات، عدد حركات، اتجاه الرصيد، نصوص عرض جاهزة، فحوص سلامة) — قبل توسيع أي قدرة. السبب: خطأ باشت في إجماليات كشف المورد.
2. **قراءة ثم مسودات ثم ترحيل محكوم:** مستويات مخاطر T0–T5؛ الوكيل لا يرحّل ولا يدفع ولا يعكس مباشرةً في هذا الأفق. الترحيل عبر **طلب موافقة** يعتمده إنسان في أَوْج.
3. **التصدير من الغلاف المتحقَّق نفسه:** CSV/XLSX عبر `SpreadsheetWriter` القائم؛ PDF الرسمي **لا يُنفَّذ قبل قرار مالك** (لا محرك PDF خادمي اليوم، وثلاثة مولّدات PDF في المتصفح).
4. **أقل صلاحية وتتبّع كامل:** scopes لكل مورد/عملية، سقف الصلاحيات عند الإصدار، وسجل عمليات الوكيل (من/ماذا/متى/لماذا).

**أهم ما كشفه الفحص (مُتحقَّق منه بالقراءة):**
- `PublicApiScope::permission()` (إسقاط scope ← RBAC) **غير مستدعى في أي مكان**؛ `EnsureApiScope` يتحقق من عضوية الـscope فقط. وإصدار المفتاح لا يفحص أن المُصدِر نفسه يملك الصلاحية المقابلة. (فجوة أمنية ← بوابة G-S2.)
- المسودات المنشأة عبر API تُكتب `created_by = null` ولا يوجد ختم مصدر؛ التتبّع الوحيد هو `PublicApiRequestLog` (ملف طلب، لا ربط بالمستند). (فجوة تدقيق ← G-S6.)
- كشف الحساب في Public يعيد `debit − credit` الخام **لكل الأدوار**، بينما واجهة أَوْج تعرض رصيد المورد **قيمة مطلقة** (`displayBalance(..., creditBalance)` في `partner-statement-document.tsx`). ولا يعيد الـAPI إجماليات ولا عدد حركات ولا اتجاهاً. أي وكيل يجمع بنفسه أو يعرض الإشارة الخام سيخالف شاشة أَوْج. (فرضية السبب الجذري لخطأ باشت — **غير مؤكدة**، لم أرَ ناتج باشت.)
- التحويل الصحيح هللات←ريال موجود أصلاً: `App\Support\Money::toRiyal()` (حسابي صحيح بلا float) لكن لا يُكشف للوكلاء.
- `SpreadsheetWriter::csvLine` يسبق القيم التي تبدأ بـ`-` بعلامة `'` (حماية حقن الصيغ) فيُفسد الأرصدة **السالبة** في CSV (`-65000` ← `'-65000`)؛ XLSX سليم. أي تصدير مالي CSV يحتاج وضع أعمدة عددية (G-S10).
- التصدير الخادمي = CSV/XLSX للمنتجات/المخزون/مركز المستندات فقط. التقارير: JSON فقط. PDF: ثلاثة مسارات في الواجهة (`invoice-pdf.ts` رسم مباشر jsPDF، `statement-pdf.ts`، و`lib/pdf.ts` لقطة html2canvas) خلف واجهة `DocumentExporter` تذكر صراحةً أنها قابلة للاستبدال بـSSR/Puppeteer.

## 2) المبادئ غير القابلة للكسر

مستمدّة من `CLAUDE.md` وتُطبَّق على كل شريحة:

1. أي أثر محاسبي عبر `LedgerService::post` حصراً؛ الوكيل لا يكتب في `journal_*` أبداً.
2. الإجماليات مشتقّة من السطور في الخادم؛ الوكيل لا يُدخل مجموعاً.
3. المبالغ `bigint` بالهللات؛ ممنوع float في أي مسار (خادم، أداة وكيل، ملف تصدير).
4. عزل المستأجر عبر `BaseModel`/`TenantScope` + `PublicApiTenantGuard` (fail-closed)؛ قرار "السياسة تُضبط ولا تُفرض" (قاعدة 6) لكل قرار عمل.
5. لا كسر لـInternal/Public API: كل تغيير **إضافي**؛ السلوك الحالي يبقى كما هو افتراضياً (مفاتيح/مجالات جديدة مغلقة افتراضياً).
6. Idempotency إلزامي لكل كتابة؛ مسودة فقط للوكيل حتى يُعتمد غير ذلك.
7. كل قدرة جديدة = scope جديد + عملية OpenAPI + اختبار عزل مستأجرين + اختبار 401/403 + تدقيق.
8. لا ملف مستأجر على رابط عام بلا حماية.

## 3) المعمارية المستهدفة

```text
 وكيل خارجي (باشت…)            مساعد أَوْج (داخلي)
        │ Bearer ApiClient              │ جلسة مستخدم
        ▼                               ▼
 ┌────────────────────────── Capability Catalog (كود، مصدر واحد) ───────────────────────────┐
 │ operation → scope → RBAC permission → risk tier → application key → domain service     │
 └───────────────┬───────────────────────────────┬──────────────────────────────┬──────────┘
   T0 قراءة      │      T1/T2 كتابة مباشرة       │   T3/T4 أثر محاسبي/نقدي       │  تصدير
                 ▼                               ▼                              ▼
   Report wrappers (قائمة بيضاء)     Public controllers → Domain services   Approval Request
   + Verified Envelope              (Idempotency، مسودة فقط)                (سجل AiAction + بهاش ثابت)
                 │                               │                              │ اعتماد إنسان في أَوْج
                 ▼                               ▼                              ▼
          ReportService (قائم)         InvoiceService/QuoteService…       Service::post(actor=المعتمِد)
                 │                                                              │
                 └───────────── Export Engine: الغلاف المتحقَّق ← SpreadsheetWriter/(PDF بقرار) ──┘
                                          │
                       Agent Operation Log (من/ماذا/متى/مصدر/نتيجة) + PublicApiRequestLog
```

**مستويات المخاطر**

| المستوى | الوصف | أمثلة | الوكيل مباشرة؟ |
|---|---|---|---|
| T0 | قراءة | تقارير، قوائم، كشوف | نعم (scope + غلاف متحقَّق) |
| T1 | كتابة بيانات مرجعية بلا أثر محاسبي | عميل/مورد/منتج | نعم (Idempotency) |
| T2 | مسودة مستند بلا قيد | عرض سعر، أمر شراء، فاتورة شراء/مبيعات، مصروف، مسودة قيد | نعم (مسودة فقط، الخادم يحسب الإجماليات) |
| T3 | ترحيل (قيد محاسبي) | ترحيل فاتورة/شراء/مصروف/قيد يدوي | **لا** — طلب موافقة بشري |
| T4 | حركة نقد/تحصيل | سند قبض/صرف، سداد، رابط دفع | **لا** — خارج هذا الأفق؛ قرار مالك منفصل |
| T5 | عكس/إلغاء/حذف | عكس قيد، حذف | **مستبعد** |

سياسة T3 قابلة للضبط لكل مستأجر (قاعدة 6): `disabled` (الافتراضي) | `human_approval`. **لا يوجد خيار "direct" في هذه الخطة.**
