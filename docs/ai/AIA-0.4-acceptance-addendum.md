## شروط قبول إلزامية (قرار المالك)

> **مرجعا البداية:** `PublicApiScopeCeilingProofTest` و`SpreadsheetWriterNegativeAmountReproTest` (PR #2030). يُستعملان **مرجعاً** لا بديلاً، ثم **يُحوَّلان إلى اختبارات رفض صارمة** في PR الإصلاح.

### أ) اختبارات الأمان النهائية (D-08)
1. **تفشل عند قبول إصدار scope غير مصرَّح به.** أي استجابة `2xx` أو إعادة `secret` أو إنشاء مفتاح/عميل لمُصدِر يفتقد الصلاحية المقابلة = فشل الاختبار (لا `incomplete`).
2. **ممنوع في اختبارات القبول:** `markTestIncomplete`، `markTestSkipped`، `#[RequiresPhp*]`/`@requires` المُتخطية، `Test::skip`، وأي تفرُّع شرطي على نتيجة الإصدار (`if (status === 201)` …). يُحوَّل فرع «الحالة المعيبة» في الاختبار الحالي إلى تأكيد رفض صريح ويُحذف فرع `incomplete`.
3. **حارس آلي لا يعتمد على الانضباط:** (i) اختبار بنيوي يفحص ملفات اختبارات القبول ويفشل إن وجد الأنماط أعلاه؛ (ii) تشغيل مجموعة `aia-0-4-security` في CI بـ`--fail-on-incomplete --fail-on-skipped --fail-on-risky` (النمط قائم في `cops-h1-1-perf`). *تعديل `ci.yml` يدخل نطاق PR الإصلاح ويُذكر صراحة في وصفه.*
4. **المصفوفة المطلوبة (SQLite وPostgreSQL كلتيهما؛ تعتمد على قاعدة البيانات في CI لا على التشغيل المحلي وحده):**

| المحور | الحالات الإلزامية (كلها تُثبَّت برفض أو بقبول صريح) |
|---|---|
| قراءة | `partners:read` · `products:read` · `invoices:read` · `statements:read` — مُصدِر بلا الصلاحية المقابلة ⇒ 403/422 بلا سرّ |
| كتابة | `partners:write` · `products:write` · `invoices:write` — مُصدِر يملك `*.view` دون `*.manage` ⇒ رفض؛ و`webhooks:read/write` (⇒ `apps.view/manage`) |
| تركيب | قائمة مختلطة (بعضها مسموح وبعضها لا) ⇒ **رفض كامل بلا إصدار جزئي** ولا عميل يتيم |
| مسارات الإصدار | إنشاء عميل مع مفتاح (`store`) **و**مفتاح إضافي لعميل قائم (`issueKey`) **و**CLI |
| الأدوار | دور محدود (`developer.manage` فقط) · دور بالصلاحية المقابلة ⇒ يُصدر · `accountant`/`staff` المدمجان ⇒ 403 (لا يملكان `developer.manage`) · `owner`/`admin` ⇒ يصدران كل scope معروف |
| CLI | **A:** `--issuer` ناقص ⇒ فشل بلا إصدار ورمز خروج غير صفري؛ مُصدِر غير موجود/معطَّل/من مستأجر آخر ⇒ فشل؛ مُصدِر بلا الصلاحية ⇒ رفض؛ مُصدِر مخوَّل ⇒ ينجح. **B (مؤجل بقرار المالك):** لا أمر ولا خيار تشغيلي في هذا الإصلاح (لا `--operator`؛ يُرفض كخيار مجهول) — لا يُفعَّل دون سجل تدقيق مناسب. **C:** لا مسار قديم بلا خيارات |
| العزل | `issuer` من مستأجر آخر ⇒ رفض/404 كما اليوم |

5. **التوافق الخلفي (اختبارات إلزامية):**
   - مفتاح صدر قبل الإصلاح بـscope يتجاوز سقف مُصدِره **يبقى صالحاً** (لا إبطال ولا تغيير تلقائي) — اختبار يُصدر مفتاحاً بالمسار القديم عبر `ApiClientKeyService` مباشرةً ثم يثبت أنه يقرأ بعد نشر الإصلاح؛ تقرير قراءة فقط يسرد المفاتيح المتجاوزة بلا كتابة.
   - `DeveloperApiClientManagementTest` و`PublicApiPartnerStatementTest` وبقية `PublicApi*Test` تبقى خضراء دون تعديل (إلا ما يُضاف).
   - `EnsureApiScope` وسلوك المصادقة وشكل استجابة الإصدار الناجحة (`secret`, `key`, `client`) بلا تغيير.
   - المالك وحامل الصلاحية يُصدران (اختبارا الثبات الحاليان يُحفظان كما هما).
