# A — SAP Fiori (Horizon era) and Ant Design: rules for AWJ ERP

Retrieved 2026-11-10 with curl. Fiori: guideline version **v1.154** (the latest version in the site's own query index). Ant Design: **ant.design now serves v6** (6.x); v5 lives at `5x.ant.design`. Where v5 and v6 differ, both are noted.
Column rule: "Documented" = faithful paraphrase of the official page (quotes ≤ 25 words). "Implication" = our inference only.

---

## 1. SAP Fiori for Web

**Overview.** Fiori is SAP's enterprise design language for apps that are "role-based, adaptive, simple, coherent, and delightful". It is built around a few floorplans (List Report, Worklist, Object Page, Overview Page, Analytical List Page, Wizard). These sit on the Dynamic Page and the Flexible Column Layout. Its table guidance is the most explicit I found for data-heavy ERP screens: which table type to use, how many rows it can hold, alignment, and totals.

| # | Rule / pattern | Documented detail | Source URL | Implication for AWJ (inference) |
|---|---|---|---|---|
| 1 | Choosing a floorplan | List Report: "find and act on relevant items within a large set" by searching, filtering, sorting and grouping. Worklist: a *comparably small* set of work items, processed one by one. Object Page: "see or edit one item with all its details". Initial Page: the user already knows the item's ID. ALP: insight or KPI impact, hybrid chart/table. | https://www.sap.com/design-system/fiori-design-web/v1-154/page-types/floorplans/list-report-floorplan-sap-fiori-element/usage | Give every AWJ module a small fixed set of page types. Invoices, purchases and products are List Report → Object Page. Approvals (fuel shift review, late tank readings) are Worklists. The dashboard is an Overview Page. "Open by number" (e.g. a POS return) is an Initial Page. |
| 2 | Anatomy of the List Report | A Dynamic Page holds: a title or **variant** (mandatory); a header toolbar with global non-finalizing actions; a collapsible header that contains the **filter bar** (mandatory); a content area with an optional tab/segmented switch, one toolbar per tab, and the table(s); and a footer that shows the message button. When the header is collapsed, the title shows "n filters active:" followed by up to 5 filter names and then "…". | same as #1 | Give every AWJ list page one template: title/saved view, a filter strip that can collapse, the table toolbar, then the table. When filters are hidden, show a one-line summary of the active filters so mobile users can see what they are looking at. |
| 3 | Dynamic Page header behavior | Three optional patterns that can be combined: **snap on scroll** (the header content scrolls away and the title stays fixed in collapsed mode), **snap on click** (on the title or the expand/collapse button), and **pin**. No pin on smartphones, or "whenever the dynamic page header would occupy more than 60% of the screen". Global actions stay available when the header is collapsed. The footer toolbar holds closing or finalizing actions. | https://www.sap.com/design-system/fiori-design-web/v1-154/page-types/page-layouts/dynamic-page-layout/usage | The document header (partner, totals, status) collapses to a slim sticky title bar while the user scrolls through invoice lines. Save, Post and Cancel go in a sticky footer, never only at the top of a long form. On phones, never pin the header. |
| 4 | Flexible Column Layout (list–detail–detail) | 1, 2 or 3 columns. Default splits are 33:66 or 66:33 for 2 columns, and 25:25:50, 25:50:25 or 50:25:25 for 3; the user can drag the splitter. L/XL screens have 5 default layouts. M (tablet) has no 3-column layout. S (phone) shows only the rightmost column, full screen. "For right-to-left languages… the last column is the leftmost column." Not meant for workbench layouts with a main column plus side panels. | https://www.sap.com/design-system/fiori-design-web/v1-154/page-types/page-layouts/flexible-column-layout/usage | This pattern suits AWJ's invoice list → invoice → line/payment drill-down on desktop. In RTL the drill-down grows to the **left**. On phones, use push navigation instead. |
| 5 | Content density: cozy vs compact | 1 rem = 16 px. Cozy touch area = **2.75 rem (44 px)**. In compact, "rows and toolbars can use sizes of 2 rem (32 px)" and the font size stays the same. Desktop defaults to compact; phones and tablets are always cozy. "Never combine 'cozy' and 'compact' modes within the same hierarchy or page." Grid table adds **condensed** (desktop only, never with cozy). Letterboxing caps content at **1280 px**. | https://www.sap.com/design-system/fiori-design-web/v1-154/foundations/visual/cozy-compact | AWJ needs two density tokens, not page-by-page tweaks: compact (32 px rows and controls) for desktop accounting, cozy (44 px) for touch (POS, fuel stations app). Keep the font size identical in both. Store the choice per user. |
| 6 | Which table to use | **Responsive table**: moderate data, "up to 200 items" of average complexity loaded at once; focus is on line items; works on all devices. **Grid table**: large, complex data where cells and comparison matter; desktop/tablet only. **Tree table**: hierarchical data. **Analytical table**: "multilevel grouping as well as grand totals and subtotals". Desktop-centric tables need a separate, reduced-complexity UI for phones. | https://www.sap.com/design-system/fiori-design-web/v1-154/foundations/best-practices/ui-elements/tables/table-overview | Map AWJ's single TanStack table to these modes. Line-item lists stay responsive (cards or pop-in on mobile). The GL ledger and stock movements use virtualized grid mode. The chart of accounts uses tree mode. Aged balances and P&L use grouped subtotals. Ledger-type screens need a separate phone design, not a squeezed version. |
| 7 | Responsive table pop-in | Columns that no longer fit move into a "pop-in area" under each row, as label/value pairs. Auto mode uses a minimum column width of **8 rem** and moves the right-most, lowest-priority column first. The GridSmall pop-in adds a column for every **13 rem (208 px)**. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/responsive-table/usage | Give each column a priority (high/medium/low) in our column definitions. On narrow screens, low-priority columns collapse into a label/value block inside the row instead of forcing horizontal scrolling. In RTL, "right-most" becomes the *end* (left) side. |
| 8 | Growing vs totals | Use "growing" mode (load on scroll is preferred over a More button) to show more than 100 items. "Don't show aggregations in 'growing' mode", because it is unclear what is being totalled. Don't show a toolbar item count while growing; show the count on More instead. Title bar, column headers and info bar can be sticky. | same as #7 | A footer total under a partially loaded list misleads the user. AWJ totals must come from the server for the whole filtered set and be labelled as such, or be hidden while infinite-loading. Keep column headers sticky. |
| 9 | Cell alignment | Left-align text, IDs, phone numbers and status. **Right-align numbers** (except IDs). Right-align amounts with currencies, "align them in terms of their respective decimal points". Right-align dates. Center icons. Text cells in the grid table are single-line and truncate; they never wrap. Be locale-aware. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/grid-table/usage | In RTL, "right-align numbers" must become a deliberate logical rule. Recommendation to validate: numeric columns align to `end` with tabular figures and a fixed number of decimals, so halalas line up. IDs and invoice numbers stay text-aligned. |
| 10 | Selection and freezing | Responsive table multi-select uses checkboxes, Shift for a range, and Select All or Ctrl+A. Select All covers only the items the user can reach. The grid table's multi-selection plug-in has a default range limit of **200**, shows a notice when the limit is hit, and offers a Deselect All button. Freeze columns from the column header menu (`fixedColumnCount`). For row height in auto mode, show at least 3–5 rows. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/grid-table/usage | Bulk actions (post, print, export) must say exactly what "all" covers. Cap and announce large selections. Allow freezing the document-number column on wide tables. |
| 11 | Filter bar and update mode | Basic search comes first, then filters with labels **above** them; an asterisk marks mandatory filters. "Adapt Filters (n)" shows the active count, including filters that are hidden. "Whenever possible, use the live update mode." Use a manual Go button only when the unfiltered data volume is very high or several filter values are needed. Selections reset when the results update. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/filter-bar/usage | Live filtering is the default for AWJ lists. Use manual "Apply" for heavy reports (ledger over a long date range). Always show the active-filter count, even for filters hidden in a "more filters" panel. Clear row selection when filters change. |
| 12 | Variant (view) management | Use one view control per page that saves filters, tabs, tables and charts. An asterisk marks unsaved changes. There is exactly one default view, plus pre-shipped standard views that cannot be edited and public views. A search appears when there are more than 10 favorites. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/variant-management/usage | "Saved views" per user (and shared per tenant) for heavy list pages such as overdue invoices this month. Show a dirty marker. Ship a non-deletable "Standard" view. |
| 13 | Form layout by size | Breakpoints: **S ≤ 600 px, M 601–1024, L 1025–1440, XL ≥ 1441** (form width, not page width). Column layout: S 1 column, M 2, L 3, XL 6 max. Label:field:empty ratios on a 12-column grid: S 12:12:0 (labels above), M 2:10:0 by default (3:5:4 recommended for full screen), L/XL 4:8:0, or 3:5:4 for a single group. Labels sit beside fields "if there is enough space, otherwise above". | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/form/usage | Document headers on desktop use 2–3 groups side by side with labels at the start; on phones, labels go above. Adding empty columns (3:5:4) keeps inputs from stretching across wide screens. |
| 14 | Validation timing | Focus-out validation suits drafts with few fields. Avoid it for many fields, for fast keyboard entry, or for partial entry. S/4HANA uses **On Enter** plus **On Save/Create** validation. Field errors show as value states, and a message button with a counter opens the message popover. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/form-field-validation/usage | For high-speed invoice line entry, validate the whole document on Enter or Save rather than nagging on each blur. Collect errors in a "n issues" button that jumps to each field or line. |
| 15 | Which message pattern | **Toast**: short success only; never for errors or warnings, or when the user needs to copy text (use a success dialog). **Message strip**: inline, near the content; persistent if no close button; not for field errors (use the value state). **Message popover**: non-interrupting list of validation messages, filterable by type, with a subtitle naming the field or row. **Message box**: interrupting, for technical errors and confirmations; must "provide steps for resolution". | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/message-toast/usage ; …/message-strip/usage ; …/message-popover/usage ; …/message-box/usage | Posting an invoice should not show its number only in a toast; it needs a copyable success state. ZATCA or ledger rejections (422 with `reason`) belong in a message box or strip with a fix path, never a vanishing toast. |
| 16 | Draft handling | The draft auto-saves **every 20 seconds**. Save is still needed to make it the active version. The lock is exclusive, and an idle lock expires after **30 minutes**. Editing statuses can be filtered: Own Draft, Locked by Another User, Unsaved Changes by Another User. There is a draft/saved version switch next to the title. | https://www.sap.com/design-system/fiori-design-web/v1-154/foundations/best-practices/global-patterns/object-handling/draft-handling | AWJ separates *draft* (editable) from *posted* (immutable), and that maps well here. Add an autosave indicator, an "edited by X" lock notice on shared documents, and list filters for "my drafts". The ledger stays immutable after posting (reverse only). |
| 17 | Semantic colors | Five value states: Neutral, Positive, Critical (warning), Negative (error), Information. Never use them for decoration. Separate *industry-specific* indication colors (two sets of 10) cover domain conventions. Every color needs an accompanying text, e.g. an object status. | https://www.sap.com/design-system/fiori-design-web/v1-154/foundations/best-practices/ui-elements/how-to-use-semantic-colors | Status chips (draft/posted/paid/overdue/cancelled) always pair color with a word. Keep the brand color out of status semantics. Fuel-tank thresholds could use a separate "indication" palette. |
| 18 | Numbers, currency, units | Number types: integer, float, currency, percentage, each with short, standard and long forms; use standard "in general". The currency formatter knows the currency's decimals (e.g. TND has 3). Units: prefer long text, translated; short text is fine for common units (currency, weight, length). Price per quantity uses "/". | https://www.sap.com/design-system/fiori-design-web/v1-154/foundations/best-practices/ui-elements/formatting/formatting-numbers ; …/formatting/units-of-measurement | Format from halalas using the currency's own exponent; never assume 2 decimals in the UI layer. Show short forms (e.g. 1.5M) only on dashboards, never in ledgers. Fuel: "SAR/L", liters spelled out where space allows. |
| 19 | Navigation chrome | Shell bar: branding (mandatory), search (expanded by default), notifications, help (mandatory), profile. Side navigation supports **up to 3 levels**, an optional search, and a fixed bottom area. Embedded collapse shows icons only. At **600 px (size S)**, or on phones, it becomes a full-screen overlay. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/shell-bar/usage ; …/side-navigation/usage | AWJ's 8-group sidebar fits the 3-level limit (group → module → sub-item). Add sidebar search and an icon-only collapsed mode. Switch to an overlay drawer at ≤ 600 px. |
| 20 | Wizard limits | Use for long or unfamiliar tasks: "a minimum of 3 and a maximum of 8 steps", followed by a summary screen before submitting. Not for 2-step or routine daily tasks. | https://www.sap.com/design-system/fiori-design-web/v1-154/ui-elements/wizard/usage | Use for onboarding, opening balances and imports (already step flows). Never use it for daily invoice entry. |

**Fiori RTL notes found:** the FCL drill-down mirrors (last column = leftmost). Message strip and toast declare LTR/RTL support. No page explains how to align numeric columns in RTL. That is a gap AWJ must decide for itself.

## 2. Ant Design (v6 on ant.design; v5 at 5x.ant.design)

**Overview.** Ant Design is Ant Group's design system for enterprise back-office ("middle-platform") products, with four design values: Natural, Certain, Meaningful, Growing. Its "Global Rules" pages (feedback, data entry, data display, navigation, buttons, data format) give short, opinionated guidance. Its React component docs give exact defaults (durations, paddings, breakpoints).

| # | Rule / pattern | Documented detail | Source URL | Implication for AWJ (inference) |
|---|---|---|---|---|
| 1 | Design value "Certain" | Interfaces should have "high certainty and low cooperative entropy". Keep restraint. Use modular design. Keep appearance and interaction consistent across products to cut learning cost. | https://ant.design/docs/spec/values | AWJ has many modules (ERP, POS, Commerce, Fuel). One shared component vocabulary matters more than any per-module flourish. |
| 2 | Grid and base unit | 24-column grid with a base unit of **8**. The design board is 1440 wide, with a 1168 content area in the example. Mainstream resolutions: 1920, 1440, 1366. Common layout: fixed left nav with a fluid work area. | https://ant.design/docs/spec/layout | Use an 8 px spacing scale and a fixed start-side sidebar (right side in RTL) with a fluid table area. |
| 3 | Breakpoints | xs < 576, sm ≥ 576, md ≥ 768, lg ≥ 992, xl ≥ 1200, xxl ≥ 1600; v6 adds **xxxl ≥ 1920**. | https://ant.design/components/grid | These are close to Tailwind's defaults. Use Tailwind's breakpoints, but test the 1366 and 1920 desktop widths explicitly. |
| 4 | Table size variants | `size`: large \| middle \| small in v5; renamed **large \| medium \| small** in v6. Cell vertical padding: **16 / 12 / 8**. Horizontal padding: **16 / 8 / 8**. Cell font size is **14** for all sizes. Selection column width is 32. Header background is #fafafa; selected row is #e6f4ff. | https://ant.design/components/table (v5: https://5x.ant.design/components/table) | Rough row heights from 14 px × 1.5714 line height (my calculation, not documented): about 55 / 47 / 39 px. AWJ's compact table (Fiori 32 px) is denser than Ant's "small". Pick row heights on purpose (e.g. 32/40/48) and keep the font size fixed across densities. |
| 5 | Table capabilities | Fixed header, fixed (stacked) columns, `sticky` header and scrollbar, ellipsis columns with tooltip, expandable rows, `summary` row (`(currentData) => ReactNode`), `virtual` list (5.9.0+), filters (`filterMode` menu/tree), sorters, and pagination placement (default bottom-end). | https://ant.design/components/table | Ant's `summary` takes `currentData`, meaning only the current page. That is the same trap as Fiori #8. AWJ's footer totals must state their scope (page vs filtered set). With virtual rows, sticky headers and pinned columns are required. |
| 6 | Empty cell | "When table cell is empty, use - to indicate that there is no data." | https://ant.design/docs/spec/data-display | In financial tables, distinguish "—" (no value / not applicable) from "0.00". This matches AWJ's fuel rule that a missing price must never show as zero. |
| 7 | Numbers and amounts | Use thousands separators. Units are lowercase, as in 123,220kg. In tables, numbers are "right-aligned" for vertical comparison. Amount format is "currency symbol + number" (CNY1,123.00) or a character symbol. Large amounts may use M/B. | https://ant.design/docs/spec/data-format | Fiori and Ant agree: align numbers to one edge, show decimals consistently, put the currency code next to the amount. For SAR, choose one form (the code or the new riyal symbol) and use it everywhere. |
| 8 | Dates and times | Default `YYYY-MM-DD`. Ranges use `~` with spaces. 24-hour `HH:MM:SS` by default. Relative time is for messages only ("just now", "N minutes ago", then absolute after 24 h). | https://ant.design/docs/spec/data-format | Use absolute dates in documents and ledgers, relative time only in notifications and activity. Hijri/Gregorian display is AWJ's own decision; Ant is silent on it. |
| 9 | Feedback choice | **Alert**: non-blocking, stays on the page (top preferred), does not auto-dismiss. **Message**: top-center, auto-dismisses, **3 s** default. "Lightweight prompts are not recommended for important failure messages"; use a dialog. **Notification**: complex or system-pushed content, top-right, **4.5 s** default. **Modal/dialog**: blocking, only for very important actionable information. **Popconfirm**: light confirmation anchored to the element. Loading feedback is needed once an operation takes "more than 2 seconds", with a cancel option if it is long. | https://ant.design/docs/spec/feedback ; https://ant.design/components/message ; https://ant.design/components/notification | AWJ feedback matrix: toast/message only for success; strip/alert for persistent page state (e.g. "period locked"); dialog for blocking failures (posting rejected). In RTL, "top-right" notifications become top-left (the logical end side). |
| 10 | Form layout | `layout`: horizontal (default) \| vertical \| inline. Horizontal stacks labels above controls at **≤ 575 px**. `labelAlign` start \| end (v6.7 renamed left/right to logical start/end). `labelWrap`, `requiredMark` (true \| optional \| custom), `colon`, `variant` (outlined/filled/borderless/underlined). | https://ant.design/components/form | Ant moved to logical alignment names. AWJ forms should use only logical (start/end) properties and switch labels above fields below about 576 px. |
| 11 | Label placement guidance | Label "to the left of input by default". It may sit on top "when the text is too long". Be consistent within one system. Use plain wording for novices and domain terms for experts. Short hints go under the field; long help goes behind an info icon. | https://ant.design/docs/spec/data-entry | Arabic labels are often long. Fiori and Ant together suggest labels above fields in dense document forms, and start-side labels only in wide settings forms. Pick one per form type and keep it. |
| 12 | Validation timing | `validateTrigger` default **onChange**. `validateDebounce` (ms), `validateFirst`, `scrollToFirstError` (with optional focus). Feedback text stays under the field and does not auto-disappear. | https://ant.design/components/form ; https://ant.design/docs/spec/feedback | Ant validates on change; Fiori prefers on Enter or Save for speed. For AWJ, validate on change only for format errors (e.g. the VAT number pattern). Run business rules on Save, then scroll to and focus the first error. |
| 13 | Dependent fields | `dependencies`: a field updates and re-validates when the fields it depends on change (example: confirm password). Do not combine it with `shouldUpdate`. | https://ant.design/components/form | Use declarative dependencies for things like payment method → treasury, or tax mode → price field, instead of ad-hoc effects. |
| 14 | Grouping long forms | Fewer than 7 fields: don't group. 7–15: group. More than 15: use tabs. A single top-to-bottom column is the most efficient layout. Use card grouping when the page is longer than about 2 screens. Step forms confirm before submitting. | https://ant.design/docs/spec/research-form (marked `skip: true`) | Gives clear thresholds for the product, employee and partner forms. |
| 15 | List behaviour | Pagination is the default, and the pager is hidden when there is less than one page. Keep the scroll position and mark visited items when the user comes back. Checking items reveals a **batch-operation toolbar**. New items appear first and are briefly highlighted. Delete either offers undo or requires a second confirmation, with security checks for destructive actions. Show an empty state for "no data" and for "no results". | https://ant.design/docs/spec/data-list (marked `skip: true`) | AWJ list conventions: the bulk bar replaces the toolbar while rows are selected; returning from an invoice restores the list position; drafts can be deleted with undo; posted documents cannot be deleted (reverse only). |
| 16 | Buttons | At most **one primary button** per group. Order by importance. "Cancel" may be primary when deletion is discouraged. Icon-only buttons need a tooltip. A back button sits on the "previous" side. | https://ant.design/docs/spec/buttons | One primary action per toolbar or footer (Post *or* Save, not both). In RTL, "back" points right and sits at the start. |
| 17 | Navigation | Top nav: 2–7 first-level items. Side nav suits "multi-level, operation intensive" apps. Breadcrumb depth should stay under 3 and never exceed 5; avoid breadcrumbs when other navigation already shows the location. | https://ant.design/docs/spec/navigation | Confirms sidebar navigation for the ERP. Use breadcrumbs only for deep drill-downs (report → account → entry). |
| 18 | RTL | `ConfigProvider direction="rtl"` switches the direction of supported components; there is a demo listing which components support RTL. | https://ant.design/components/config-provider | The pattern is direction set once at the root and consumed by every component. AWJ's shadcn/Radix stack should rely on `dir` plus logical CSS (`ms-/me-`, `start/end`), with no per-component flags. |

## 3. Do not copy

- **SAP identity**: the shell bar SAP logo, Joule button, launchpad tiles, "Horizon" theme colors and SAP icon font. AWJ has its own single brand color and two fonts (per DESIGN_SYSTEM.md).
- **SAPUI5 mechanics**: OData annotations, `sap.m`/`sap.ui.table` control names, the Fiori Elements auto-generation model, and SAP Jam share actions.
- **Fiori's exclusive-lock draft model as-is**: AWJ's accounting rule is that a posted entry is immutable and corrected by reversal. Borrow the draft *indicators*, not SAP's merging of saved and draft versions.
- **Separate desktop and mobile apps for heavy tables**: AWJ should keep one codebase and deliberately switch table modes per breakpoint.
- **Ant's Chinese-market defaults**: CNY/¥ examples, `YYYY-MM-DD` as the "China default", the 6.1 Children's Day term format, Alipay imagery and illustrations, and the blue #1677ff primary.
- **Ant's table paddings as density**: 16/12/8 px paddings are too loose for an accounting grid next to Fiori's 32 px compact rows.
- **Short number formats (1.57K / 1.57M) in ledgers or documents**: dashboards only.
- **Physical directions in either system** ("right-align", "top-right", "left-to-right" column order): translate each one into a logical start/end rule for RTL rather than mirroring the literal word.
