# B — IBM Carbon · Atlassian Design System · Microsoft Fluent 2

Fetched live on 2026-11-10 with curl, as extracted page text. The "Documented detail" column paraphrases the source; quotes are 25 words or fewer. The **Implication** column is my inference only. The AWJ baseline is `DESIGN_SYSTEM.md`: IBM Plex Sans Arabic plus Plex Mono, one brand blue, semantic green/red, 8px radius, tables as the hero, and cards on mobile.

## 1. IBM Carbon

**Overview.** IBM's open-source system for enterprise product UI. It is the most explicit of the three on dense tables: a 5-step row ramp, with the toolbar, batch bar and pagination paired to that ramp. It also has role-based themes and layering (White, g10, g90, g100), and productive vs expressive type and motion with numeric tokens. It uses the Plex family, which AWJ already ships.

| # | Rule / pattern | Documented detail | Source URL | Implication for AWJ (inference) |
|---|---|---|---|---|
| C1 | Row-height ramp | xs 24, sm 32, md 40 (default), lg 48, xl 64px (xl only for 2-line cells). | https://carbondesignsystem.com/components/data-table/usage/ | Use density tokens 32 (compact ledger), 40 (default) and 48 (touch). Skip 24px for Arabic text. |
| C2 | Chrome matches density | The header row "should always match the row size". Toolbar, batch bar and pagination heights also match it; a small toolbar goes only with xs/sm. | same | One density token must drive all table chrome together, not per-component props. |
| C3 | Table type and spacing | Title 20px; column header 14px SemiBold; rows 14px Regular. Cell padding 16px. Header margins 16/24. Tables need ≥3 columns. | https://carbondesignsystem.com/components/data-table/style/ | 14px is the table base. Compact mode may tighten inline padding to 12px. |
| C4 | Row state tokens | Rows use `$layer`, `$layer-hover`, `$layer-selected`, `$layer-selected-hover`, `$border-subtle` and `$focus`. Zebra uses `$layer-accent`. The batch bar uses `$background-brand`. | same | Add selected, selected-hover and zebra tokens to `globals.css` instead of ad-hoc classes. |
| C5 | Hover always; zebra optional | Row hover "should always be enabled", even on non-interactive rows. Zebra is an optional scanning modifier. | https://carbondesignsystem.com/components/data-table/usage/ | Hover on by default. Zebra as an option for wide statements, because it competes with the selection colour. |
| C6 | Toolbar and row actions | Show ≤5 toolbar actions, then overflow. Search sits under the title, collapsed or always open. A row with <3 actions shows inline icons. Overflow stays persistent on touch. | same | Cap toolbars at 5 actions. Never use hover-only row actions on phones. |
| C7 | Batch actions | Selection reveals a top batch bar, and row actions and menus are disabled while it shows. Exit with Cancel or deselect-all. The header checkbox has 3 states. | same | Use for bulk post, publish and print. Disable per-row menus during batch mode. |
| C8 | Sorting and accessibility | Only the sorted column shows its icon; unsorted icons appear on hover/focus. Headers are reachable by Tab and sort with Space/Enter. Use `aria-sort` and a table `aria-label`. | https://carbondesignsystem.com/components/data-table/accessibility/ | TanStack headers should set `aria-sort`. Touch users can't hover, so add a faint resting sort hint (a deliberate deviation). |
| C9 | Loading and expansion | "Use skeleton states instead of spinners" for expected load time. Expansion is for lazily queried detail; expand-all is off by default. Pagination sits at the bottom. | https://carbondesignsystem.com/components/data-table/usage/ | Use skeleton rows everywhere, and lazy expansion for invoice or journal lines. |
| C10 | Not a spreadsheet | Do not use the table "as a replacement for a spreadsheet application". Give it maximum width and do not nest it in cramped containers. | same | Line-item **entry** grids need their own editable-grid spec, separate from the read DataTable. |
| C11 | 2x Grid | 8px mini unit. Breakpoints: sm 320 (4 columns), md 672 (8), lg 1056 (16), xlg 1312, max 1584. Padding is always 16px. | https://carbondesignsystem.com/elements/2x-grid/overview/ | Candidate switch points for table↔card (672) and sidebar collapse (1056). Reconcile with Tailwind's 768/1024. |
| C12 | Spacing | `$spacing-01..13` = 2, 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96, 160px. | https://carbondesignsystem.com/elements/spacing/overview/ | Nearly identical to the Tailwind subset, so use it as the allowed-spacing lint list. |
| C13 | Productive type | Productive: 14px base with fixed headings ("fixed type styles are a must"). Expressive: 16px base with fluid headings. | https://carbondesignsystem.com/elements/typography/type-sets/ | App screens use productive type; fluid type only in the storefront and marketing. |
| C14 | Themes and layering | Tokens are "role-based" and only their values change per theme. Light layers alternate White ↔ Gray 10; dark layers get one step lighter per layer. "Do not apply components that are darker than the background." | https://carbondesignsystem.com/elements/color/overview/ | Add a `--layer-02` (table in dialog, card in sheet). Dark layers lighten upward. |
| C15 | Contrast and focus | Text 4.5:1; large text (24px, or 19px semibold) 3:1; UI boundaries 3:1. Focus "must pass 3:1", often with a `$focus-inset`. Disabled is exempt and unfocusable. | https://carbondesignsystem.com/guidelines/accessibility/color/ | Use a two-tone focus ring (primary plus inner surface inset) that passes on both selected and plain rows. |
| C16 | Motion | Productive motion is for tasks; expressive is for big moments. 70 / 110 / 150 / 240 (toast) / 400 / 700ms (dimming). Productive standard easing is `cubic-bezier(0.2,0,0.38,0.9)`. | https://carbondesignsystem.com/elements/motion/overview/ | Allow ≤240ms inside tables and forms, with productive easing only. |
| C17 | Notifications | Statuses are info, success, warning and error, each with a filled icon. Types are inline, toast, actionable, callout, banner and modal. A toast with an action persists. Toasts stack newest on top, ≤3 lines. Never time-dismiss critical messages. | https://carbondesignsystem.com/patterns/notification-pattern/ | Posting success goes to a toast. A 422 posting refusal goes inline next to the form. A locked period or ZATCA stop goes to a page banner. |
| C18 | Forms | Labels are top-aligned, 1–3 words, no colon. Mark only the minority with (optional) or (required). Validate on blur. Server errors appear as an inline notification. Disable the primary button on submit. Read-only is focusable and passes contrast. Inputs are 24/32/40/48px, default 40. | https://carbondesignsystem.com/patterns/forms-pattern/ · https://carbondesignsystem.com/components/text-input/usage/ | Use the **read-only** (not disabled) style for posted documents so they stay selectable and readable. Lock every post/approve button on submit. |

Carbon empty states come in three families: no-data, user-action (no results or done) and error-management (permission, system, configuration). The title should be positive, followed by a next-action body and an optional CTA (https://carbondesignsystem.com/patterns/empty-states-pattern/). *Inference:* a gated capability maps to "configuration required", and RBAC 403 maps to "permission".

**Do not copy:** IBM blue and 0px corners; the loud `$background-brand` batch bar (use `primary-soft`); sort icons that appear only on hover; top-right toasts without RTL mirroring (use the inline-end); fluid headings in the app.

## 2. Atlassian Design System

**Overview.** This system serves dense work apps (Jira, Confluence). Its strengths are a semantic token grammar, a clear elevation model, a status lozenge kept distinct from tags, and the most prescriptive content guidance for error, empty and warning copy.

| # | Rule / pattern | Documented detail | Source URL | Implication for AWJ (inference) |
|---|---|---|---|---|
| A1 | Token grammar | Names follow **foundation.property.modifier** (role, emphasis or state), e.g. `color.icon.success`. "Don't use a token just because the colors appear to match." | https://atlassian.design/foundations/tokens/design-tokens | Move to names like `--color-text-subtle` and `--color-bg-selected`, chosen by meaning. |
| A2 | Non-colour themes | Themes can also be "cozy/comfortable/compact views, reduced motion". | same | Implement density and reduced motion as theme attributes (`data-density`). |
| A3 | Roles and emphasis | Roles are neutral, brand, information, success, warning, danger, discovery, accent and input. Emphasis runs subtlest to boldest, with inverse tokens on bold surfaces. "Don't use an accent when the color has semantic meaning." | https://atlassian.design/foundations/color | Keep green and red strictly for financial meaning. User-chosen tag colours need a separate accent set. |
| A4 | Selected ≠ focused | "Keep selected and focused states distinct." `color.border.focused` is only for focus. Selected-plus-focused keeps the selection and adds focus. Pair selection with a non-colour cue. | same | AWJ currently uses `--primary` for both. Split them: selected row = soft background plus a start-edge bar or checkbox; focus = ring. |
| A5 | Spacing | Base 8px (`space.100`); the suffix is a percentage of the base. Values 0–80px (2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80). 0–8px for compact UI including "table cells"; 32–80px for layout. | https://atlassian.design/foundations/spacing | Compact ledger cells use 4–8px vertical padding. |
| A6 | Elevation | Levels are sunken (a backdrop well, only on default), default, raised (movable cards, with shadow) and overlay (modals, menus). An *overflow* shadow marks horizontally scrolled tables. Dark mode uses lighter surfaces. | https://atlassian.design/foundations/elevation | Add edge overflow shadows to wide tables. Don't raise static cards. |
| A7 | Dynamic table | Use a caption *or* a label. "Never rely on highlighted rows to convey important meaning." No controls in headers. Row edit labels are unique ("Edit component 3"). Prefer a modal or page for complex edits. After a delete, focus moves to the next item. | https://atlassian.design/components/dynamic-table/usage | Row-action `aria-label`s should include the document number. Manage focus after deleting a row. |
| A8 | Page header | Breadcrumbs, title, actions, then search/filters. One per page and not inside dialogs. "Avoid truncating the text as much as possible." | https://atlassian.design/components/page-header/usage | Build one standard `PageHeader`. Let long Arabic titles wrap. |
| A9 | Lozenge vs tag | A lozenge is a meaningful attribute (status, state, priority, permission); a tag is descriptive metadata. Lozenges have a 200px max width, truncate, and "can't be focused". Semantic colours where meaning is shared, accent otherwise. | https://atlassian.design/components/lozenge/usage | Use a Status lozenge for invoice, POS and shift states with short labels, because truncated text is unreachable. |
| A10 | Message tiers | **Flag**: event toast at bottom-left, ≤2 actions, never auto-dismiss critical messages. **Section message**: persistent and section-scoped. **Banner**: site-wide loss of data or function, one at a time, not dismissible, `role=alert` ("very noisy"). | https://atlassian.design/components/flag/usage · https://atlassian.design/components/section-message/usage · https://atlassian.design/components/banner/usage | Closed fiscal year or ZATCA stop → banner. "Cash refund not allowed" → section message. "Posted" → toast. |
| A11 | Inline edit | Read and edit views in place. Return saves, Esc cancels. Controls stay visible. Both views have identical styling. Used outside forms. | https://atlassian.design/components/inline-edit/usage | Only for draft fields such as notes or a reference. Never on posted, immutable documents. |
| A12 | Empty state | Optional spot illustration, header, description and CTA. Width 464px (wide) or 304px (narrow). Imagery should be "never negative" and checked for cultural translation. | https://atlassian.design/components/empty-state/usage | A 304–464px text measure suits Arabic. Drop illustrations unless they are culturally validated. |
| A13 | Error copy | Title of 3–4 words; state what happened and what to do. "If you don't know the reason… don't make one up." Use imperative CTAs, *we* not *you*, and avoid please/sorry. | https://atlassian.design/foundations/content/designing-messages/error-messages | Map each stable `reason` code to Arabic copy in the form *what happened → what to do*. Test the no-please rule with Arabic users. |
| A14 | Empty copy | 1–2 sentences, a CTA of 1–2 words that complements the title. Frequent messages are "more concise and less delightful". | https://atlassian.design/foundations/content/designing-messages/empty-state | Keep financial empty states neutral and terse. |

**Do not copy:** bottom-left flags (in RTL they mirror onto the phone bottom nav and the POS keypad); celebratory or "wink" empty states; "we not you" and no-please as universal Arabic rules; `role=alert` for non-critical banners; Atlassian fonts and sentence case.

## 3. Microsoft Fluent 2

**Overview.** Microsoft's cross-platform system. It is strong on global → alias token layering, state-suffix naming, elevation numbers, breakpoints, reflow and zoom, and button and toast copy. Numeric motion and size tokens appear only in the official fluentui code, and there is **no table/data-grid usage page** on the site.

| # | Rule / pattern | Documented detail | Source URL | Implication for AWJ (inference) |
|---|---|---|---|---|
| F1 | Two-layer tokens | **Global** tokens are raw values; **alias** tokens add meaning and support light, dark, high-contrast and brand theming "out of the box". | https://fluent2.microsoft.design/design-tokens | Primitive palette → aliases, so dark mode and tenant branding swap only the mappings. |
| F2 | State suffixes | `colorNeutralBackground1..6`, `Foreground1..4`, `Stroke1..3/Accessible`. States are suffixes such as `...Background1Hover/Pressed/Selected`, plus `colorStrokeFocus1/2`. | https://fluent2.microsoft.design/color-tokens · https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/alias/lightColor.ts | Every surface and brand token gets a full state set. Focus uses two strokes. |
| F3 | Focus vs colour | States get darker from rest to hover to selected. On focus, "the color of the control does not change, but the container gets a thicker stroke". | https://fluent2.microsoft.design/color | Focus is a stroke only, so a focused selected row keeps its selection (consistent with A4). |
| F4 | Breakpoints | 320–479, 480–639, 640–1023, 1024–1365, 1366–1919, 1920 and up. | https://fluent2.microsoft.design/layout | Test dense tables at 1366×768. Use 640 as a phone card↔table cut-off. |
| F5 | Spacing and targets | 4px base: 2, 4, 6, 8, 10, 12, 16, 20, 24, 28, 32, 36, 40, 48, 52, 56. Touch targets are 44×44 on iOS/Web and 48×48 on Android. | same | Use ≥44px hit areas in POS and fuel-ops phone UIs. |
| F6 | Fork/collapse | Responsive techniques: reposition, resize, reflow, show/hide, and fork list/detail (side by side when wide, focused when narrow). | same | List plus detail split on xl; full-page detail on phones. |
| F7 | Reflow and zoom | Reflow without horizontal scroll at 400% zoom ("designing down to a 320 pixel breakpoint"). Text zoom of 200% must not clip. Don't lose focus after closing temporary UI. | https://fluent2.microsoft.design/accessibility | Tables are a WCAG reflow exception; chrome and forms are not. Return focus to the trigger after a Sheet or Dialog closes. |
| F8 | Contrast and disabled | Text 4.5:1; large text (>18.5px bold or 24px) 3:1; icons 3:1. Button text 4.5:1 "in all interactive states". Disabled buttons are exempt but need a tooltip saying why. | same · https://fluent2.microsoft.design/components/web/react/core/button/usage/ | A disabled Post or Approve button explains the RBAC or gate reason in a tooltip. |
| F9 | Primary placement in RTL | One primary button per layout. Primary sits on the leading side; "In right-to-left languages, primary button placement will be on the right." | same | An explicit RTL rule for dialog and footer button order. |
| F10 | Button copy | Labels respond to the title ("Delete this file?", then Delete / Cancel). Use Next/Previous. Never OK for errors; use Close. Cancel = abandon unsaved; Close = no state effect. | same | Post, reverse and void dialogs use the verb from the title. |
| F11 | Field | Labels top-aligned. Required = red asterisk, or a single note if all fields are required. A disabled field keeps its label enabled. Placeholder is never essential; helper text explains formats. | https://fluent2.microsoft.design/components/web/react/core/field/usage/ | Agrees with C18. |
| F12 | Message bar | Warning and error **must** include a button or link. Content "never truncates". Stack by severity. A dismissed warning or error reappears next session until resolved. Place below the command bar. | https://fluent2.microsoft.design/components/web/react/core/messagebar/usage/ | Configuration blockers (VAT role, treasury) persist until they are fixed. |
| F13 | Toast | Confirmation, progress and communication. Without an action it times out after **7s**, and hover pauses it. Not for necessary actions. ≤4 per toaster, **16px** apart. No spinner and progress bar together. | https://fluent2.microsoft.design/components/web/react/core/toast/usage/ | 7s for success. Determinate progress toast for imports and exports. |
| F14 | Elevation | Shadow N = N px blur: 2, 4 (cards and list items), 8 (dropdowns, tooltips), 16 (callouts), 28 (side navigation, sheets), 64 (dialogs). | https://fluent2.microsoft.design/elevation | Only about 3 levels in AWJ (8 / 16 / 64). No shadow on table cards. |
| F15 | Shapes | 4px radius by default, 2px under 32px, 8 or 12px for large components. No rounding at screen edges or on joined split buttons. | https://fluent2.microsoft.design/shapes | Keep 8px cards and use 4px for inputs and in-table chips. |
| F16 | Icons | **Regular** icons for wayfinding and actions; **Filled** for "selected states". Small icons are "too small for interactions". Validate cultural meaning. | https://fluent2.microsoft.design/iconography | Lucide has no filled variants, so show selection with colour plus a start bar. Mirror directional icons in RTL only. |
| F17 | Motion | Duration scales with size and distance. Linear easing only for rotation. Page-level navigation uses a quick fade. Provide a "no motion" setting. Code tokens: 50–500ms (100/150/200/250/300/400). | https://fluent2.microsoft.design/motion · https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/global/durations.ts | Route changes fade (sliding invites RTL direction bugs). Honour `prefers-reduced-motion`. |
| F18 | Type and RTL | Caption 12/16, Body 1 14/20, Subtitle 2 16/22, Subtitle 1 20/26, Title 3 24/32. "Use right-alignment for right-to-left (RTL) languages, like Arabic." No all caps. | https://fluent2.microsoft.design/typography | All three systems agree on a 14/20 body. Test 14/22 for Arabic diacritics. |

**Do not copy:** Segoe UI and the per-product brand colours; the informal second-person voice as a rule (Arabic business register is more formal); "staggered animation is preferred" applied to table rows; Windows' reversed state logic; a 7s toast for anything that carries a document number the user must record.

## Cross-source consensus
All three document: a 14px productive body with ~20px line height; WCAG AA (4.5:1 text, 3:1 large text, non-text and focus; disabled exempt); top-aligned labels with placeholders never essential; critical messages never auto-dismissed; toasts only for non-critical messages; no meaning by colour alone; role-based tokens whose values change by theme.
